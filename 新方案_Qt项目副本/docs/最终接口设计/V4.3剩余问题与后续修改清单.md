## 3. 已完成: M9 并行执行框架

当前已实现 V4.3 的并行 slot 模型。后续只需在真实硬件上验证时序和 SDK 触发锁存行为。

### 3.1 V4.3 目标模型

```text
motion slot:
  Func106 / Func107 / Func108 / Func109 / Func11

program slot:
  Func110 / Func120

系统控制:
  Func104 可随时触发
```

规则:

```text
1. motion slot 内部互斥，Func109 作为 V4.3 1.1 标准函数纳入该 slot
2. program slot 内部 Func110 和 Func120 互斥
3. motion slot 可与 program slot 并行
4. Func104 不受 slot 限制
```

### 3.2 已实现内容

已实现的执行前置检查:

```text
标准函数 106/107/108/109/11 只检查 motion slot 是否空闲

Func104 跳过 slot 检查
```

已实现的 GUI 执行层:

```text
1. 按 func_num 轮询目标函数状态
2. 允许运动/标准函数执行时下发 110/120
3. 110/120 互斥
4. 流程执行器支持 motion/standard + Func110 + optional Func120 典型并行组
```

已实现的 mock:


### 4.2 GUI 编辑器已修正

后台模板编辑页中，Func104 不再仅靠旧 `stop_mode` 两态表达，而是改为“快捷动作 + 完整控制字”双层表达:

```text
快捷动作:
  自定义/无动作 / 急停按下 / 急停松开 / 暂停按下 / 暂停松开/继续 / 结束按下 / 结束松开 / 报警复位

完整控制字:
  estop_ctrl   = 0 / 1 / 2
  pause_ctrl   = 0 / 1 / 2
  cancel_ctrl  = 0 / 1 / 2
  reset_ctrl   = 0 / 1
```

```text
1. “继续” 模板重新保存后被错误降级为“暂停”
2. “报警复位” 模板重新保存后丢失 reset_ctrl=1

4. 无法表达“急停松开” / “结束松开” / 自定义控制字组合
```

同时已修正:

```text
1. Func104 下拉标签由“急停/慢停”改为“系统控制”
2. Func109 字段文案由“检测值”改为“校验值”
```

### 10.4 仿真阶段超时设置结论

现场联调已确认: 当前仿真阶段需要下位机人工点确认后才返回结果，因此超时参数不应按“纯机械动作时间”设置，而应按“人工确认窗口”设置。

当前调整:

```text
1. 默认 motion_timeout_sec: 30s -> 180s
2. GUI “运动超时(s)” 默认值: 30 -> 180
3. data/system_config.json 默认值同步为 180s
```

推荐口径:

```text
仿真/人工确认阶段: 180s
慢节奏现场联调:   300s
真实自动运行阶段: 15~30s
```

说明:

```text
当前代码使用同一个 motion_timeout_sec 同时控制标准函数和 Func104 等待超时。
这在仿真阶段可接受；后续如需精细化，可再拆分 motion/system/manual-confirm 三类超时。
```

### 10.5 真机回显等待改造

真机联调新增结论:

```text
1. 控制器回显区此前按 50ms 周期刷新，现已改为同步刷新
2. 上位机现有“逐点短重试”仍不足以稳定覆盖真机场景
3. 现场需要改成“写完参数后持续等待回显收敛，回显正常且前置检查通过后立刻触发”
4. 报警主模型应改为“重试间隔 + 最大重试次数”，总等待时间仅作为派生展示值
5. 达到指定连续错误次数后先预警并记为稳定异常，避免单次/短时读错误判
6. 失败类型必须拆分为“回显通讯失败”和“回显正常但执行条件不满足”
7. 失败时必须保留回显等待耗时、完整快照、不匹配点和前置检查结果，便于判断是否要改控制器程序
```
