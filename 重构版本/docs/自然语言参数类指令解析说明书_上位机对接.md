# 自然语言参数类指令解析说明书（上位机对接）

> 版本：V1.0 | 日期：2026-06-04
> 用途：上位机将自然语言指令解析为控制器函数调用，核心原则是**继承性+复述确认**

---

## 一、概述

### 1.1 目的

上位机接收操作者的自然语言指令（语音/文字），解析为控制器函数调用。大模型将补全后的完整参数**复述**给操作者确认，确认后才执行。

### 1.2 两个核心原则

**原则一：继承性**

操作者未指定的参数，**从控制器当前实际值继承**，不依赖HMI。正常使用时没有HMI，所有默认值都从控制器MODBUS读取。

**原则二：复述确认**

大模型必须将补全后的**完整参数列表复述**给操作者，操作者确认后才写入执行。绝不能只凭部分参数就直接执行。

### 1.3 函数选择约定

| 优先级 | 函数 | 用途 | 说明 |
|--------|------|------|------|
| **首选** | 108 | 直线插补运动 | 所有正常运动一律使用 |
| **次选** | 112 | 连续路径运动（规避） | 需要路径规划时使用 |
| 辅助 | 104 | 急停/暂停/取消/复位 | 运行控制 |
| 辅助 | 109 | T0延时（阻塞） | 运动间延时等待 |
| 辅助 | 110 | T1延时（并行） | 与运动并行的延时 |
| 辅助 | 120 | IO操作 | 夹爪/气缸等IO控制 |

**禁止使用106/107函数**（关节运动），容易导致模式转换中的姿态奇异点干涉。当前阶段全部使用108函数。

## 二、MODBUS通讯地址

### 2.1 指令下发地址

| 地址 | 内容 | 说明 |
|------|------|------|
| IEEE(0) | 功能号 | 108/112/104/109/110/120 |
| IEEE(2) | 参数0 | para(0) |
| IEEE(4) | 参数1 | para(1) |
| IEEE(6) | 参数2 | para(2) |
| ... | ... | 每个参数占2个IEEE地址 |
| IEEE(30) | 参数14 | para(14) |
| IEEE(32) | 执行触发 | 写1触发执行 |

### 2.2 控制器当前状态读取地址（继承源）

参数补全时从这些地址读取当前实际值：

| 地址 | 内容 | 用途 |
|------|------|------|
| IEEE(1500) | 当前X | 继承位置X |
| IEEE(1502) | 当前Y | 继承位置Y |
| IEEE(1504) | 当前Z | 继承位置Z |
| IEEE(1506) | 当前RX | 继承姿态RX |
| IEEE(1508) | 当前RY | 继承姿态RY |
| IEEE(1510) | 当前RZ | 继承姿态RZ |
| IEEE(1708) | 安全速度% | 继承速度 |
| IEEE(1710) | 安全加速度% | 继承加速度 |
| IEEE(1712) | 安全减速度% | 继承减速度 |

> 注意：正常使用时没有HMI，速度/加速度/减速度从安全参数地址IEEE(1708/1710/1712)继承，不是HMI地址。

## 四、参数继承与补全规则

### 4.1 三种参数完整度

| 类型 | 定义 | 处理方式 |
|------|------|---------|
| **全参数指令** | 自然语言中包含所有6个位置+3个速度参数 | 直接映射，复述确认后执行 |
| **半参数指令** | 只指定部分参数 | 缺省参数从控制器当前值继承，复述完整参数后确认执行 |
| **单参数指令** | 只指定1个参数变化 | 其余参数全部继承当前值，复述完整参数后确认执行 |

### 4.2 继承规则（核心）

操作者未指定的参数，按以下规则从控制器继承：

| 参数类别 | 继承源 | 说明 |
|----------|--------|------|
| 位置 X/Y/Z | IEEE(1500/1502/1504) | 当前笛卡尔坐标 |
| 姿态 RX/RY/RZ | IEEE(1506/1508/1510) | 当前姿态角 |
| 速度% | IEEE(1708) | 安全速度参数 |
| 加速度% | IEEE(1710) | 安全加速度参数 |
| 减速度% | IEEE(1712) | 安全减速度参数 |
| 位置增量 | 默认0 | 绝对定位 |
| 急停命令 | 默认0 | 正常运动 |

**关键：没有HMI时，速度/加速度/减速度从安全参数继承，不从HMI读取。**

### 4.3 解析流程

```
自然语言输入
    ↓
[1] 识别意图 → 确定函数号
    ↓
[2] 提取参数 → 从自然语言中提取明确参数
    ↓
[3] 继承补全 → 未指定参数从控制器当前值继承
    ↓
[4] 复述确认 → 大模型将完整参数复述给操作者
    ↓
[5] 操作者确认 → 是：写入MODBUS执行 / 否：取消或修改
    ↓
[6] 写入执行 → IEEE(0)=函数号, IEEE(2~30)=参数, IEEE(32)=1
```

## 七、复述确认协议

### 7.1 复述格式

大模型必须按以下格式复述完整参数：

```
【复述确认】FuncXXX 函数名
X=___  Y=___  Z=___  RX=___°  RY=___°  RZ=___°
速度=___%  加速度=___%  减速度=___%
模式：绝对/增量定位
确认执行？
```

**每项参数必须标注来源**：
- 明确指定值：直接显示
- 继承值：标注"←继承当前"或直接显示继承后的数值

### 7.2 安全预检

确认前应调用安全判定函数（见《机械手基础运行信息交互状态说明书》附录D）：

```python
result = checker.check_move_safe(x, y, z, rx, ry, rz)
if not result["valid"]:
    # 展示错误信息，禁止执行
    for err in result["errors"]:
        print(f"⚠ {err['detail_zh']}")
```

### 7.3 执行后状态监控

写入IEEE(32)=1触发后，轮询以下地址确认执行状态：

| 地址 | 含义 |
|------|------|
| LONG(34) 主状态 | M_EXEC=执行中 / M_DONE=完成 / M_ALARM=报警 |
| LONG(36) 运行状态 | $100=非法函数 / $200=参数错误 |
| LONG(38) 报警代码 | 各类报警位 |

## 八、复合指令解析

### 8.1 运动序列

**自然语言**："走到X1000等待2秒然后走到X1500"

**解析为3条指令**：

1. Func108：X=1000，其余继承当前
2. Func109：延时2秒
3. Func108：X=1500，其余继承当前

每条指令都需复述确认。

### 8.2 运动+IO

**自然语言**："走到X1000打开夹爪"

**解析为2条指令**：

1. Func108：X=1000
2. Func120：IO打开

> 注意：Func120是并行指令，如果需要运动完成后再开IO，应先等Func108完成后再发Func120。

## 九、函数选择决策树

```
收到自然语言指令
    ↓
是否为运动指令？
    ├─ 否 → 104(急停/暂停/复位) / 109(延时) / 120(IO)
    └─ 是 → 是否需要路径规避？
         ├─ 是 → Func112
         └─ 否 → Func108（默认选择）
```

**关键约定：当前阶段全部使用108函数，除非明确需要规避才用112。**
