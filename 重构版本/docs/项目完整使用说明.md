# 机械手自然语言交互系统完整使用说明

本文档基于当前项目代码整理，面向现场操作员、工程师和维护人员，说明如何启动、登录、连接控制器、维护模板/位置/流程、使用自然语言和语音会话、查看日志、修改配置、打包发布以及排查常见问题。

> 当前主程序入口是 `gui_main.py`，桌面 GUI 主窗口是 `robot_modbus_lite/qt_gui.py`，默认协议链路是 V5.0 六轴 Modbus TCP 协议。本文不以早期伪代码或旧 V4.3 流程为准。

---

## 1. 系统能做什么

当前系统是一个机械手控制与自然语言交互桌面应用，主要能力包括：

1. **工程师页面**
   - 连接模拟控制器或真实 ZMotion 控制器。
   - 维护指令模板 `query_table.json`。
   - 维护流程 `flows.json` / `flow_registry.json`。
   - 配置安全范围、速度上限、确认超时、TTS 播报、UI 缩放等系统参数。
   - 查看运行日志、导出日志、清空日志。

2. **用户页面**
   - 用自然语言输入或语音会话发起查询、流程草案、单步动作和系统动作。
   - 查看当前设备状态、安全状态、实时位置、最近操作、待确认草案。
   - 对高风险或生产动作执行安全确认。
   - 查询设备状态、报警、位置、流程、模板、执行结果。
   - 启用或关闭 AI 回答语音播报。

3. **自然语言能力**
   - 支持“小正/小郑/校正/小镇/小郭”等唤醒词及配置化扩展。
   - 支持位置移动、关节/虚拟轴点动、延时、IO、系统控制、流程草案。
   - 支持本地规则、标准词归一化、拼音归一化、同音/方言词表。
   - 支持 DeepSeek 用于普通问答、复杂流程草案、低置信语义兜底。
   - DeepSeek 只做理解、问答和草案生成，不直接控制机械手。

4. **安全链路**
   - L1 安全预检：急停、报警、暂停、软限位、球面半径、速度钳位等。
   - L2 运动预演：可达性、奇异区、中点建议等。
   - L3 流程预检：流程逐步预检、步间隔、累计误差、禁入包围盒等。
   - 所有实际执行必须走本地白名单、预检、确认和 V5.0 协议写入。

5. **语音能力**
   - 手动录音识别。
   - 连续语音会话：开启会话后通过静音分段判断一句话结束。
   - 识别过程中在用户对话区显示“正在识别语音...”状态。
   - AI 回答可播报，播报内容只保留最新 AI 回答，不播报普通日志和中间状态。

## 3. 运行方式

### 3.1 源码运行

在项目根目录执行：

```powershell
E:\VeighNa\python.exe gui_main.py
```

也可以使用当前环境中的 Python：

```powershell
python gui_main.py
```

如果第一次运行，先安装依赖：

```powershell
python -m pip install -r requirements.txt
```

当前 `requirements.txt` 包含：

```text
PySide6
requests
cryptography
fastapi
uvicorn[standard]
pydantic
pypinyin
sounddevice
numpy
pyinstaller
```

本地讯飞 SDK 不是强制依赖，如果使用本地讯飞识别，还需要安装或提供 `xfyunsdkspeech`。如果使用 pyttsx3 播报，还需要安装 `pyttsx3`；如果使用 Windows SAPI，则依赖 Windows COM 语音组件和 `win32com`。

### 3.2 EXE 运行

打包后的主程序：

```text
打包输出\dist\RobotModbusLite\RobotModbusLite.exe
```

运行时请注意：

- 必须保留整个目录 `打包输出\dist\RobotModbusLite\`。
- 不要只复制单个 `RobotModbusLite.exe`。
- `_internal/`、`data/`、DLL、`.env` 等资源缺失会导致启动、语音或配置读取异常。

### 3.3 其他入口模式

`gui_main.py` 还支持：

```powershell
python gui_main.py --iflytek-worker
python gui_main.py --web-server
python gui_main.py --ui web-browser
```

普通桌面使用只需要直接运行 `gui_main.py` 或 EXE。

## 4. 环境变量和密钥配置

项目根目录 `.env` 会被 DeepSeek 和讯飞客户端读取。

### 4.1 DeepSeek

常用字段：

```env
DEEPSEEK_API_KEY=你的key
DEEPSEEK_MODEL=deepseek-v4-flash
ALLOW_LOCAL_KEY=true
```

说明：

- 如果有授权服务，程序优先使用授权服务中的 DeepSeek。
- 如果授权不可用且 `ALLOW_LOCAL_KEY=true`，程序会尝试读取本地 `.env` 的 `DEEPSEEK_API_KEY`。
- DeepSeek 失败时，系统会回退本地规则或本地知识库。

### 4.2 讯飞语音识别

本地讯飞模式需要：

```env
IFLYTEK_APP_ID=...
IFLYTEK_API_KEY=...
IFLYTEK_API_SECRET=...
```

如果未配置或未安装 SDK，点击语音/会话时会提示启动失败或识别失败。

### 4.3 发布注意

`.env` 可能包含真实密钥。正式交付前要确认是否允许随包分发。打包配置会包含 `.env`，如果不能分发密钥，需要先移除或改为授权服务方式。

## 5. 登录和角色

启动后进入登录页。当前系统有两个主要角色：

| 角色 | 主要用途 |
|---|---|
| `operator` 操作员 | 用户页自然语言、位置/流程读取与创建、流程执行、看板查询、报警确认。 |
| `engineer` 工程师 | 工程师页模板维护、流程管理、删除、确认流程、系统配置、安全参数维护。 |

权限由 `robot_modbus_lite/permission_service.py` 控制。当前操作员也允许创建/更新位置和流程，但删除、系统配置修改等能力保留给工程师。

## 6. 主界面结构

## 7. 连接控制器

### 7.1 模拟控制器

推荐先使用模拟控制器验证界面和自然语言链路。

操作：

1. 登录工程师页。
2. 在运行页选择“模拟控制器”。
3. 填写或保留默认地址。
4. 点击“检测连接”。
5. 日志出现“Mock连接成功”即表示可以测试模板、流程和用户页自然语言。

### 7.2 真实控制器

真实控制器使用 `Windows Python（64位）` 下的 ZMotion SDK/DLL。

操作：

1. 确认真实控制器 IP 可达。
2. 选择真实控制器。
3. 输入控制器地址。
4. 点击“检测连接”。
5. 连接成功后会启动实时轮询。

注意：

- 如果真实控制器连接失败，日志可能出现 `connect(...) failed with code 20008`。
- 确认网线、IP、控制器上电、SDK DLL 路径和防火墙。
- 真实设备下发动作前必须确认现场安全。

## 8. 指令模板使用

指令模板存储在：

```text
data/query_table.json
```

每条模板包含：

| 字段 | 说明 |
|---|---|
| `query_key` | 模板名称，例如 `home`、`位置A`、`J1到10度`。 |
| `func_num` | 函数号，例如 104、106、107、108、109、110、120。 |
| `keywords` | 自然语言匹配关键词。 |
| `description` | 模板说明。 |
| `safety_level` | 安全级别。 |
| `params` | 具体函数参数。 |

常见函数：

| Func | 用途 |
|---|---|
| 104 | 系统控制：急停、暂停、继续、取消、报警复位等。 |
| 106 | 关节点动或关节定位。 |
| 107 | 虚拟轴点动，例如 X/Y/Z/RX/RY/RZ 方向动作。 |
| 108 | 直线插补 / PTP 移动到目标坐标。 |
| 109 | 定时检测/延时。 |
| 110 | 可并行延时。 |
| 120 | IO 控制。 |

工程师页可以新增、修改、删除模板。修改后保存会写入 `query_table.json`，自然语言解析和流程步骤会使用最新模板。

## 9. 位置库使用

位置库文件：

```text
data/position_registry.json
```

位置结构：

```json
{
  "name": "home",
  "pose": [1475, 0, 1545, 0, 0, 0],
  "spd": 50,
  "move_type": 0,
  "locked": false,
  "is_system": false
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `name` | 位置名称。 |
| `pose` | `[x, y, z, rx, ry, rz]` 六维坐标。 |
| `spd` | 默认速度百分比。 |
| `move_type` | 移动方式，通常 `0` 表示默认移动方式。 |
| `locked` | 锁定后不可普通修改。 |
| `is_system` | 系统位置，不允许删除。 |

自然语言示例：

```text
home位坐标是多少
位置A的参数是什么
小正，移动到home
小正，去位置A
```

注意：

- 位置查询不需要唤醒词也可以走问答/查询。
- 生产控制动作通常需要唤醒词。
- 当前默认 `home` 是 `1475, 0, 1545, 0, 0, 0`。

## 10. 流程库使用

流程有两份文件：

```text
data/flows.json
data/flow_registry.json
```

`flows.json` 是旧视图格式，用于列表和兼容；`flow_registry.json` 是结构化流程库，包含确认状态、版本、创建人、步骤结构等。

### 10.1 工程师页维护流程

操作：

1. 进入工程师后台。
2. 打开流程管理区域。
3. 从可用模板中选择步骤。
4. 添加到流程步骤列表。
5. 设置流程名和步间隔。
6. 保存流程。

流程执行前会检查：

- 步骤模板是否存在。
- 控制器是否连接。
- 控制器是否就绪。
- 是否正在执行其他流程。

### 10.2 用户页生成流程草案

复杂口语流程不会直接执行，而是先生成草案。

示例：

```text
小正，打个招呼的小流程，让机械手先回到home位再小臂上下点头15度，3次
```

系统会尝试生成多步草案，例如：

1. 移动到 home。
2. 小臂上点头。
3. 小臂下点头。
4. 重复三次。

生成草案后会提示：

```text
当前仅生成草案，不自动保存或执行。
可说“确认保存”或“保存并执行”。
```

用户可继续说：

```text
确认保存
保存并执行
取消草案
重新预检
第2步速度改成30%
删除第3步
撤销修改
```

注意：

- 单独说“执行”如果没有被草案命令处理，可能被识别为普通闲聊或未知动作。推荐说“保存并执行”或“按这个执行”。
- 草案保存后会同步写入 `flows.json` 和 `flow_registry.json`。

## 11. 自然语言输入规则

### 11.1 普通问答

普通问答不需要唤醒词。

示例：

```text
你是谁
你能做什么
有哪些默认命令
home位置参数是什么
现在下位机状态是什么
报警怎么办
```

处理顺序大致是：

1. 本地知识库。
2. 看板/状态查询规则。
3. 位置/流程/模板上下文查询。
4. DeepSeek 问答。
5. 本地兜底回答。

### 11.2 生产控制动作

生产动作通常需要唤醒词。唤醒词在 `data/voice_wake_words.json` 配置。

当前配置：

```json
{
  "primary": "小正",
  "aliases": ["小郑", "校正", "小镇", "小政", "小真", "小针", "小郭"],
  "session_grace_seconds": 10
}
```

支持示例：

```text
小正，移动到home
小郑，去位置A
校正，J1到10度
小镇，X前进50
小郭，休息
```

`session_grace_seconds` 表示短时间会话上下文内可对唤醒词更宽容，但不能依赖它绕过安全规则。

### 11.3 特殊休息姿态

当前支持无唤醒词休息命令：

```text
休息
休息了
去休息
回到默认休息姿态
回到0位
```

休息姿态按当前模板/位置解析，通常应映射到休息或 0 位动作。若现场定义为：

```text
900, 0, 1000, 0, 0, 0
```

应在位置库或模板中明确维护。

### 11.4 应急命令

急停类命令需要三段式授权码：

```text
急停 A1B2 急停
```

授权码来自 `data/system_config.json`：

```json
"emergency_codes": ["A1B2"]
```

单独说“急停”不会直接触发急停，系统会提示缺少授权码。

## 12. 自然语言配置文件

### 12.1 标准词、同音、方言

文件：

```text
data/nlp_standard_words.json
```

用途：

- 标准动作词。
- 同音字/近音词。
- 四川话或现场口语变体。
- 拼音归一化。

`pypinyin` 的作用是把中文转成拼音，用于把 ASR 识别错字、同音词、近音词尽量归一到标准词。例如“小正/小郑/校正”等在拼音或别名规则下能被合并理解。

修改后通常重启 GUI 生效。

### 12.2 唤醒词

文件：

```text
data/voice_wake_words.json
```

可增加 ASR 常见误识别：

```json
"aliases": ["小郑", "校正", "小镇", "小郭"]
```

注意：

- 唤醒词过宽会增加误触发风险。
- 生产动作仍需安全预检和确认。

### 12.3 本地知识库

文件：

```text
data/assistant_knowledge_base.json
```

用于普通问答，例如“你是谁”“能做什么”“报警怎么办”“流程草案怎么用”。

条目结构：

```json
{
  "id": "system_identity",
  "category": "identity",
  "keywords": ["你是谁", "你是什么"],
  "content": "我是机械手自然语言交互系统的问答助手...",
  "priority": "high",
  "source": "system",
  "answer_style": "plain"
}
```

维护原则：

- 写系统能力、安全边界、使用方法等静态说明。
- 不写动态数据，例如“当前有几个模板”，动态数据由代码实时注入。
- 关键词越具体，命中越稳定。

### 12.4 看板查询别名

文件：

```text
data/dashboard_query_aliases.json
```

用于把“现在状态怎么样”“下位机状态”“报警信息”等映射到具体看板查询。

### 12.5 流程短语别名

文件：

```text
data/flow_phrase_aliases.json
```

用于把“点头”“打招呼”“上下摆”等现场口语映射到具体动作组合。复杂流程草案会使用这个文件和 DeepSeek/本地规则共同生成步骤。

## 13. 语音使用

用户页底部按钮显示为“开启会话”或“开始录音”，取决于当前模式。

### 13.1 手动录音

流程：

1. 点击录音按钮。
2. 说话。
3. 再次点击停止。
4. 系统识别后把文本填入输入框或自动处理。

特点：

- 适合确认麦克风、SDK、讯飞凭证是否正常。
- 一次录音一次识别。

### 13.2 连续语音会话

流程：

1. 点击“开启会话”。
2. 系统持续监听麦克风。
3. 说完一句后，系统根据静音间隔切分一句话。
4. 识别过程中用户对话区显示“正在识别语音...”。
5. 识别完成后自动进入自然语言处理。
6. 继续说下一句即可。

实现细节：

- 音频采样率 16000。
- 能量阈值默认 350。
- 起始有声约 120ms。
- 结束静音约 500ms。
- 最短语音段约 300ms。
- 最长语音段约 5000ms。

注意：

- AI 正在生成文字时，会忽略麦克风输入，避免把系统自己的回答识别成用户命令。
- TTS 播报不再长期阻塞下一轮输入；检测到新的用户语音段后会尝试停止当前播报并处理新输入。
- 如果识别太慢，优先检查讯飞 SDK、网络和麦克风设备。

### 13.3 语音播报

用户页右侧有“语音播报”复选框。

配置字段：

```json
"operator_tts_enabled": true
```

播报规则：

- 只播报 AI 最终回答。
- 不播报日志、最近操作、中间状态。
- 新 AI 回答出来时，旧待播报内容会被替换。
- 如果用户开始下一轮输入，系统会废弃旧待播报队列，并尝试停止当前播报。

## 14. 安全确认和执行

自然语言解析到可执行动作后，系统不会无条件下发。

典型流程：

1. 用户输入：`小正，移动到位置A`。
2. NLP 解析为模板或原子动作。
3. L1/L2/L3 预检。
4. 用户页进入确认场景。
5. 用户点击“确认执行”或输入“确认执行”。
6. 系统按 V5.0 协议写入控制器。
7. 执行完成后刷新状态和日志。

可说：

```text
确认执行
取消
采纳建议
速度改成30%
步长改成10毫米
```

确认超时由 `operator_confirm_timeout_sec` 控制，默认 60 秒。超时后待确认计划会自动取消。

## 17. UI 缩放和不同分辨率

当前系统支持 UI 自动缩放。

配置：

```json
"ui_scale": "auto"
```

也可以手动设置：

```json
"ui_scale": 0.85
```

范围：

```text
0.6 ~ 1.2
```

说明：

- Qt 获取的是逻辑像素，不是物理像素。
- Windows 150% DPI 下，2560x1080 可能被 Qt 看成约 1706x720。
- 自动缩放会按屏幕可用宽高计算，避免页面撑出屏幕。
- 工程师页和用户页都使用滚动区域兜底。

## 21. 常见问题

### 21.1 GUI 打不开

检查：

1. 是否有旧进程占用。
2. 是否缺少 PySide6。
3. 是否在 EXE 目录中只复制了单个 exe。
4. 查看 `gui_stderr.log`、`gui_stdout.log` 或运行控制台输出。

### 21.2 连接真实控制器失败

常见日志：

```text
connect(192.168.1.11) failed with code 20008
```

处理：

1. 检查 IP。
2. 检查网线和控制器上电。
3. 检查控制器端口和防火墙。
4. 切换到模拟控制器验证上位机逻辑。

### 21.3 语音识别很慢

可能原因：

1. 讯飞 SDK 初始化慢。
2. 网络慢。
3. 语音段太长。
4. 麦克风持续噪声导致静音分段不结束。
5. `.env` 凭证不正确导致重试。

处理：

- 先用手动录音验证。
- 检查 `data/exported_logs` 中语音耗时日志。
- 调整麦克风输入音量和环境噪声。

### 21.4 AI 回答时页面闪烁

系统当前使用 QTextBrowser/HTML 渲染对话气泡和思考状态。若闪烁明显：

- 检查是否在频繁追加中间日志到对话区。
- 尽量只展示最终 AI 回答和必要状态。
- 使用较短流式间隔，避免每个字符都触发布局大幅变化。

### 21.5 为什么“执行”没有执行流程

如果当前存在流程草案，推荐使用：

```text
保存并执行
确认保存
按这个执行
就这样执行
```

单独“执行”可能被普通问答或未知动作路径处理，尤其是在没有明确待确认计划或草案状态已丢失时。

### 21.6 为什么小正/小郑识别不稳定

检查：

```text
data/voice_wake_words.json
data/nlp_standard_words.json
```

把 ASR 常见误识别加入 `aliases` 或标准词同音/方言字段。修改后重启 GUI。

### 21.7 为什么普通问答没有执行动作

这是设计要求。普通问答、咨询、身份询问、功能询问不触发机械手动作。生产动作需要唤醒词、本地解析、安全预检和确认。

### 21.8 为什么 TTS 播报只有第一条或旧回答排队

当前设计是只播报最新 AI 回答。新输入或新回答会清理旧待播报队列，并尝试停止当前播报。某些本地 TTS 引擎不一定能硬中断正在播放的一句话，但播放结束后不会继续播旧队列。

## 22. 推荐现场使用流程

### 22.1 首次部署

1. 安装依赖或使用打包 EXE。
2. 配置 `.env`。
3. 检查 `data/system_config.json`。
4. 配置 `data/voice_wake_words.json`。
5. 配置 `data/nlp_standard_words.json`。
6. 用模拟控制器启动。
7. 测试自然语言问答。
8. 测试模板命令。
9. 测试流程草案。
10. 测试真实控制器连接。
11. 现场低速验证动作。

### 22.2 日常操作员使用

1. 登录操作员。
2. 打开用户页。
3. 确认左侧状态栏无急停、暂停、报警。
4. 查询状态：`现在下位机状态是什么`。
5. 需要控制时使用唤醒词：`小正，移动到home`。
6. 查看预检和确认信息。
7. 点击“确认执行”或说“确认执行”。
8. 执行完成后查看对话区和右侧最近操作。

### 22.3 工程师维护

1. 登录工程师。
2. 修改模板、位置、流程或系统参数。
3. 保存后用模拟控制器验证。
4. 检查日志。
5. 必要时重新打包。
6. 将整个 `RobotModbusLite` 目录交付现场。

## 23. 重要安全提醒

1. 不要让 DeepSeek 或普通问答直接下发动作。
2. 不要把普通“急停”配置成直接执行，当前三段式急停是安全设计。
3. 修改唤醒词时不要过宽，否则可能误触发生产指令。
4. 修改 `query_table.json`、位置库、流程库后，必须先在模拟控制器验证。
5. 真实控制器下发前，必须确认机械手运动范围内无人、无障碍、夹具状态正确。
6. 若出现报警、急停、暂停、通讯异常，先处理现场安全，再复位或继续。
