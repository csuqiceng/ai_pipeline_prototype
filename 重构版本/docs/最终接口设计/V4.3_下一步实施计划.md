# V4.3 下一步实施计划

## 1. 目标

本计划只覆盖当前代码侧和仓库卫生可推进的后续工作，不直接修改业务逻辑。

优先目标:

```text
1. 补齐 M0.5 真实硬件地址映射验证脚本
2. 补齐 M9 并行执行 mock 自动化验收脚本
3. 清理 pycache / *.pyc 版本控制污染
```

暂不优先处理:

```text
1. 删除 BIT API 旧兼容接口
2. 删除 6001/6002 GUI/语音入口
3. 移除 IEEE(52/54/70/72) 可选反馈
```

原因:

```text
这些属于兼容残留或固件待确认项，建议真实硬件联调稳定后再做。
```

## 2. P0: 新增真实硬件地址映射验证脚本

### 2.1 新增文件

```text
tools/verify_v43_mapping.py
```

### 2.2 脚本定位

该脚本用于连接真实正运动控制器，验证 V4.3 上位机使用的 Modbus IEEE/LONG 地址映射是否与真实 SDK 行为一致。

默认必须只读，不改变控制器状态。

### 2.3 命令行接口

只读验证:

```bash
python tools/verify_v43_mapping.py --host <controller-ip>
```

可选写入测试:

```bash
python tools/verify_v43_mapping.py --host <controller-ip> --write-test
```

可选参数建议:

```text
--repo-root <path>      默认自动取脚本上级仓库根目录
--json <path>           输出验证结果 JSON
--timeout-sec <value>   SDK 连接或读取超时时间，仅用于脚本自身控制
--write-test            显式启用安全写入测试
```

### 2.4 默认只读验证项

必须读取并打印:

```text
LONG(34)  函数状态和全局状态位
LONG(36)  系统状态
LONG(38)  报警详情
IEEE(320) 系统状态镜像
IEEE(322) 当前函数号
IEEE(1600~1610) MPOS 关节反馈
IEEE(1612~1622) MPOS 位姿反馈
```

必须验证并报告:

```text
1. read_modbus_long(start=34,count=1) 是否可读取 LONG(34)
2. read_modbus_long(start=36,count=1) 是否可读取 LONG(36)
3. read_modbus_long(start=38,count=1) 是否可读取 LONG(38)
4. read_modbus_float(start=1600,count=6) 是否返回 IEEE(1600,1602,...,1610)
5. read_modbus_float(start=1612,count=6) 是否返回 IEEE(1612,1614,...,1622)
6. IEEE(320) 与 LONG(36) 是否大体一致
7. read_modbus_long(start=34,count=3) 是否返回 LONG(34,35,36)
```

注意:

```text
IEEE(322) 并行时只能代表一个当前函数号，不可作为并行状态判断依据。
脚本只记录该值，不把它作为 M9 是否正确的唯一判断。
```

### 2.5 写入测试约束

`--write-test` 必须默认关闭。

启用后也不得直接写:

```text
LONG(34)
LONG(36)
LONG(38)
IEEE(320)
IEEE(322)
IEEE(1600~1622)
```

如果实现写入测试，只允许使用下位机侧明确提供的安全测试地址白名单，且必须在脚本输出中提示用户确认固件侧未使用这些地址。

第一版建议先不实现写入动作，只保留参数和醒目提示:

```text
--write-test 当前预留，暂不执行任何写入。
```

### 2.6 输出格式

控制台输出建议分区:

```text
[connect]
[long-status]
[ieee-system]
[mpos]
[address-step]
[summary]
```

每项给出:

```text
PASS / WARN / FAIL
读取地址
原始值
解释说明
```

脚本退出码:

```text
0 = 只读项全部可读取，无硬失败
1 = 连接失败或关键地址读取失败
2 = 参数错误
```

### 2.7 验收标准

```text
1. 无控制器时，参数错误或连接失败信息清晰。
2. 默认运行不写任何控制器地址。
3. 能复用现有 ZMotionVrClient，不复制 SDK 加载逻辑。
4. 读取 LONG 地址使用 read_modbus_long。
5. 读取 IEEE 地址使用 read_modbus_float。
6. 连接失败时退出码为 1，并输出现场人员可读的错误信息，不直接甩 Python traceback。
7. 输出能直接用于现场联调记录。
8. 脚本输出明确提示: 通过/失败仅代表本次地址可读性和一致性检查结果，不等同于硬件固件行为完全验证通过。
```

## 3. P1: 新增 M9 mock 自动化验收脚本

### 3.1 新增文件

```text
tools/verify_v43_mock_m9.py
```

### 3.2 脚本定位

该脚本只跑本地 mock，不依赖真实控制器。

目标是把当前已经人工验证过的 M9 并行规则固化成可重复执行的验收脚本。

### 3.3 覆盖场景

必须覆盖:

```text
1. Func108 + Func110 可并行
2. Func110 + Func120 同 program slot 互斥
3. Func108 + Func106 同 motion slot 互斥
4. Func108 + Func109 同 motion slot 互斥
5. Func104 在 motion/program 执行中可触发
6. Func104 reset_ctrl=1 后 mock slot 不残留假忙
```

### 3.4 建议实现方式

直接使用:

```text
mock_controller.controller.MockController
mock_controller.client.MockZMotionVrClient
robot_modbus_lite.models.SixAxisCommand
```

不要启动 Qt GUI。

可以用小 helper:

```text
write_command(client, six_cmd)
read_status(client)
func_state(raw, func_num)
assert_alarm_bit(bit)
wait_until(predicate, timeout)
```

### 3.5 输出和退出码

控制台输出:

```text
PASS Func108 + Func110 parallel
PASS Func110 + Func120 mutex
...
```

退出码:

```text
0 = 全部通过
1 = 任一场景失败
```

### 3.6 验收标准

```text
1. python tools/verify_v43_mock_m9.py 可直接运行。
2. 不依赖 PySide6。
3. 不连接真实硬件。
4. 失败时明确打印失败场景、LONG(34)、LONG(38)。
5. 失败时退出码为 1。
```

## 4. P2: 仓库卫生清理

### 4.1 修改范围

新增或更新:

```text
.gitignore
```

至少加入:

```gitignore
__pycache__/
*.pyc
```

### 4.2 git 索引清理

计划命令:

```bash
git rm -r --cached -- '**/__pycache__'
git rm --cached -- '*.pyc'
```

Windows PowerShell 下需要改成安全枚举方式，不能用危险删除命令。

建议只从 git 索引移除，不删除本地文件:

```powershell
git ls-files | rg '(__pycache__|\.pyc$)' | ForEach-Object { git rm --cached -- $_ }
```

如果现场环境没有 ripgrep，可用 PowerShell 内置命令:

```powershell
git ls-files | Select-String '__pycache__|\.pyc$' | ForEach-Object { git rm --cached -- $_.Line }
```

### 4.3 验收标准

```text
1. git status 不再显示 pycache/pyc 运行后变更。
2. 本地源码不被删除。
3. 不处理与 V4.3 无关的 build/dist 大范围文件，除非单独确认。
```

## 5. 暂缓项

### 5.1 BIT API 删除

暂缓删除:

```text
ControllerClient Protocol read_modbus_bit / write_modbus_bit
ZMotionVrClient read_modbus_bit / write_modbus_bit
MockZMotionVrClient read_modbus_bit / write_modbus_bit
MockController BIT(151) 兼容复位逻辑
```

理由:

```text
当前 V4.3 新路径已不依赖 BIT。
彻底删除可能影响旧测试、旧调试入口或历史 UI 行为。
建议真实硬件联调稳定后再删。
```

### 5.2 6001/6002 入口删除

暂缓删除:

```text
qt_gui.py SYSTEM_COMMAND_CODES auto_start/auto_stop
voice_nlp_adapter.py auto_start/auto_stop 映射
qt_gui.py _apply_legacy_system_action 中 auto_start/auto_stop 的本地状态切换
```

理由:

```text
service.build_six_system_command(6001/6002) 已明确报错，当前不会下发真实控制器。
是否从 UI/语音入口隐藏，需要产品侧确认。
_apply_legacy_system_action 仍保留 auto_start/auto_stop 的本地 UI 状态切换，后续删除入口时需要一并确认这部分本地行为是否保留。
```

### 5.3 IEEE(52/54/70/72) 可选反馈

暂缓删除。

理由:

```text
当前只作为日志显示，不作为成功/失败依据。
需等固件确认这些地址是否仍维护。
```

## 6. 推荐实施顺序

```text
1. 新增 tools/verify_v43_mapping.py
2. 本地运行脚本参数/连接失败路径，确认默认不写控制器
3. 新增 tools/verify_v43_mock_m9.py
4. 运行 mock M9 验收脚本
5. 运行 python -m compileall robot_modbus_lite mock_controller tools
6. 处理 .gitignore 和 pycache 索引清理
```

真实控制器执行 M0.5 和根据硬件结果修正 SDK 策略，作为本计划完成后的现场联调阶段单独记录。

## 7. 风险控制

```text
1. 第一阶段不改 qt_gui.py / service.py / mock_controller/controller.py 的业务行为。
2. 真实硬件脚本默认只读。
3. 写入测试即使提供参数，也先保持预留，不做实际写入。
4. 仓库卫生只清 pycache/pyc，不批量处理 build/dist。
5. 任何真实控制器写入项必须另开计划并明确安全地址。
6. verify_v43_mapping.py 连接失败时退出码为 1，并输出明确错误信息，避免现场只看到 traceback。
```

## 8. 完成定义

本计划第一轮完成后，应满足:

```text
1. 代码仓库具备 M0.5 现场验证入口。
2. M9 并行行为有本地可重复验收脚本。
3. pycache/pyc 不再污染后续变更。
4. 真实硬件验证仍单独记录结果，不把本地脚本通过等同于硬件通过。
```
