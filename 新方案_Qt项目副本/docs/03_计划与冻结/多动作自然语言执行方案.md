# 多动作自然语言执行方案

## 目标

支持一条自然语言解析为多个顺序动作，例如：

- `先移动到位置A，然后移动到位置B`
- `先启动，再移动到位置A`
- `先执行流程222，再暂停`

执行原则：

1. 动作按顺序串行执行
2. 前一步成功，才执行下一步
3. 任一步失败，后续动作停止
4. 底层仍复用现有单步发送、流程执行、系统动作主链路

---

## 设计原则

### 1. 不重写底层发送主链路

以下逻辑保持不变：

- `_execute_query_key`
- `_handle_system_action`
- `_start_flow`
- 镜像确认
- 执行触发
- `_wait_for_execution_complete`
- `_after_send`
- 中间点规避

多动作执行只在这些现有入口外面包一层顺序调度器。

### 2. 解析层从单动作扩为动作序列

原来：

- `VoiceNlpAction`

现在：

- `VoiceNlpPlan`
  - `actions: list[VoiceNlpAction]`
  - `source`
  - `raw_text`
  - `reason`

### 3. DeepSeek 与本地规则都支持动作序列

- DeepSeek 支持返回：
  - 单动作 JSON
  - 多动作 `actions[]` JSON
- 本地规则支持识别：
  - `然后`
  - `接着`
  - `再`
  - `之后`
  - `并且`

---

## 执行策略

### 单动作

与当前版本保持一致：

- `template` -> `_execute_query_key`
- `system` -> `_handle_system_action`
- `flow` -> `_start_flow`

### 多动作

新增自然语言动作序列执行器：

1. 保存 `actions[]`
2. 从第 1 步开始
3. 当前步完成后，通过 `on_done(ok)` 决定是否继续
4. `ok=True` -> 下一步
5. `ok=False` -> 整体终止

---

## 日志策略

新增自然语言序列日志：

- `自然语言 / 执行解析`
- `自然语言 / 动作序列第N步开始`
- `自然语言 / 动作序列第N步成功`
- `自然语言 / 动作序列第N步失败`
- `自然语言 / 动作序列完成`
- `自然语言 / 动作序列终止`

---

## 当前范围

本次实现范围：

- 支持多模板顺序执行
- 支持系统动作与模板混合顺序执行
- 支持流程作为动作项参与顺序执行

不做：

- 条件分支
- 循环
- 并发动作
- 自动生成新流程文件

---

## 风险控制

1. DeepSeek 只允许从当前已有模板、流程、系统动作中选目标
2. DeepSeek 返回非法目标时，回退本地规则
3. 不允许并发执行多个自然语言动作序列
4. 失败后立即停止后续步骤，避免状态扩散
