# P0 用户页安全交互闭环实施计划

**日期**：2026-05-20  
**依据**：`docs/用户页面实现现状与缺口总结.md`  
**目标**：先补齐用户页面的安全交互底线，避免“急停”关键词误触发，并建立统一回应、主动播报队列和看板快照基础。

---

## 一、实施边界

本轮只做 P0 安全交互闭环：

1. 三段式应急编码。
2. 即时回执与统一回应对象。
3. 主动播报消息队列。
4. 用户页可复用看板快照缓存。
5. 用户页最小接入。

本轮暂不依赖真机完成：

1. L2 `FRAME_TRANS2` 正逆解。
2. FSTATUS 遍历评分。
3. 奇异点检测。
4. 完整动力学/碰撞级 L3 流程仿真。
5. 50ms 高频轮询改造。

### 2.3 用户页最小接入

已修改 `robot_modbus_lite/operator_ui_mixin.py`：

1. 初始化 `BroadcastQueue`、`ResponseBuilder`、`EmergencyChannel`、`DashboardCache`。
2. NLP 解析开始时改用 `ResponseBuilder.receipt()` 生成“收到，正在解析指令。”。
3. 用户页文本/语音等价命令先经过 `EmergencyChannel.evaluate()`。
4. 单独“急停”“紧急停止”不再直接触发 `sys_estop`，只提示“请按急停 授权码 急停格式确认”。
5. 三段式授权通过后才调用 `_handle_system_action("sys_estop")`。
6. NLP 计划里如果出现 `system/sys_estop`，也会再次走应急编码校验。
7. `_refresh_operator_view()` 每轮刷新同步更新 `DashboardCache`。
8. 用户页完整状态页的设备健康、位置、执行、报警安全字段优先读取 `DashboardCache.snapshot`。
9. `_operator_add_chat_from_log()` 已开始接收系统、应急和反馈状态变化日志，并通过 `ResponseBuilder.from_log_entry()` 转成主动播报消息。

## 四、后续 P0/P1 剩余任务

### 4.1 主动播报语音输出

下一步需要增加：

1. `pyttsx3` 是可选依赖，目标部署环境需要确认是否安装以及发声设备是否可用。
2. 自动暂停后目前需要手动重新开启；已补状态栏、对话区、日志和故障说明弹窗。
3. 工程师后台系统配置表单已新增 TTS 开关、播报去重窗口、TTS 重试间隔和最大连续失败次数；保存后台配置后会同步用户页语音播报开关状态。

### 4.2 L1 预检服务化

已完成第一步：

1. 新增 `robot_modbus_lite/safety_precheck.py`。
2. 复用现有 R/Z、急停、报警、暂停、连接、通道占用检查。
3. 增加目标位置软限位、速度、加速度、减速度检查。
4. `WebPrecheckService.run_l1()` 已改为委托共用服务。
5. 用户页解析到可执行计划后会运行 L1 预检，并把结果写入确认页和预检场景。

剩余：

1. L1 已有保守参数修正建议，但还没有面向复杂路径/工艺的建议策略。
2. L2 运动规划预演已接入用户页基础门禁，但真实控制器逆解和中间点绕行尚未真机验证/实现。
3. L3 流程级预演已接入第一版骨架，但还不是完整时序/误差/干涉级预演。

### 4.3 风险建议闭环

已完成第一步：

1. 新增 `SafetySuggestionService`，可把目标 X/Y/Z 夹到软限位内。
2. 可把速度、加速度、减速度百分比夹到安全上限内。
3. 用户页“采纳建议”会生成临时模板记录，不修改原始模板。
4. 采纳后会重跑 L1/L2/L3 预检预演，通过后再进入确认执行链路。
5. L2 失败且配置安全中间点时，用户页可生成“安全中间点 -> 原目标”的临时流程。
6. 确认页会展示 L1 可夹紧建议和 L2 中间点建议。
7. 安全确认已增加可配置超时，默认 60 秒；超时会自动取消旧计划并提示重新输入。
8. L2 可在多个 FSTATUS 候选中自动跳过奇异风险候选，确认页会显示已选 FSTATUS 和已规避候选。

剩余：

1. 中间点建议仍是保守临时流程，尚未做真机级路径验证。
2. FSTATUS 已可自动规避奇异候选，但尚未下发为独立控制器执行参数；当前作为 L2 预演决策和确认页提示。
3. 建议说明还没有做富文本/分级高亮，只是结构化文本展示。

### 4.4 L2 运动规划预演骨架

已完成接口骨架：

1. `kinematics_engine.py` 定义 `InverseKinematicsResult` 和 `KinematicsEngine` 协议。
2. `motion_plan.py` 定义 `MotionPlanService`。
3. 可遍历 FSTATUS 候选并按关节绝对值总和选择较优解。
4. 可检查 J4 是否接近奇异阈值。
5. 未配置运动学引擎时返回 `unavailable`，不会误报通过。
6. 用户页已具备 `_operator_l2_target_pose()`，可从模板计划提取六维目标位姿。
7. 已新增 `FrameTrans2KinematicsEngine`，通过 `TABLE(550~556)`、`FRAME_TRANS2(550,560,2)`、`TABLE(560~565)` 执行逆解适配。
8. `ZMotionVrClient` 已补齐 `set_table/get_table/execute` 三个窄接口。
9. 用户页已从当前 `robot_x/y/z/r` 生成起点位姿，并把起点/目标传给 L2 预演。
10. 路径奇异点检查已从单点 J4 阈值扩展为 5 点插值检查。
11. L2 失败结果已接入用户页确认执行门禁；`unavailable` 只提示，不阻断执行。
12. L2 失败时如存在安全中间点，确认页会提供中间点临时流程建议，采纳后改为执行临时流程。
13. L2 会按评分遍历 FSTATUS 候选，若低分候选接近奇异区，会自动改选下一个可通过候选。
14. L2 预演已接入细粒度进度回调：`start`、`fstatus_scan`、`candidate_scored`、`singularity_check`、`complete` 会同步到 Qt 用户页预检进度条和对话/播报队列。

剩余：

1. 真实控制器 `FRAME_TRANS2` 调用尚未真机验证。
2. 插值检查仍依赖逆解引擎质量，还不是完整动力学/碰撞级路径预演。
3. FSTATUS 目前用于预演决策和操作者确认提示，是否需要写入控制器执行参数需依据后续协议扩展确认。

### 4.5 L3 流程级预演骨架

已完成第一版：

1. 新增 `process_precheck.py`，提供 `ProcessPrecheckService.run_l3()`。
2. 可检查流程步骤模板完整性，缺模板时直接失败。
3. 可逐步调用 L1 预检和 L2 运动规划预演。
4. L2 `unavailable` 作为警告，不误阻断；L1/L2 `fail` 会导致 L3 失败。
5. 用户页解析到 `flow` 动作时会运行 L3 流程预演，并保存 `_operator_last_process_precheck_result`。
6. 确认执行时，L3 失败会阻断流程执行并写入对话区和日志。
7. 已增加流程步间隔状态机模拟：`l3_min_step_delay_ms` 可配置，步间隔不足会阻断。
8. 已增加累计误差预算：`l3_cumulative_error_limit_mm` 可配置，模板 `expected_error_mm` 累计超限会阻断。
9. 已增加简化禁入包围盒检查：`l3_forbidden_boxes` 可配置，目标点进入包围盒会阻断。
10. 工程师后台保存系统配置和读取控制器限位时会保留 L3 预演配置字段。
11. 工程师后台系统配置表单已新增 L3 最小步间隔和累计误差上限字段。
12. L3 预演进度已通过 progress callback 进入对话/播报，并同步到用户页预检进度条。
13. L3 预演已接入阶段级进度事件：`start`、`template_check`、`step_complete`、`timing_check`、`error_budget`、`interference_check`、`complete`。逐步 L1/L2 检查占 5%~70%，后续汇总检查推进到 100%，避免进度条回退。

剩余：

1. 当前 L3 仍是保守骨架，不是完整动力学/碰撞级仿真。
2. 流程级中间点绕行建议已有离线汇总和展示，但还没有经过控制器路径执行验证。
3. 流程预演进度已经可视化，并具备阶段级播报；但仍是同步预演过程中的阶段显示，不是真机执行进度。

### 4.6 标准 JSON 结构

已完成第一版：

1. 新增 `json_schema.py`。
2. 定义类型 A `CommandIntent`，覆盖 `command_intent` 14 个核心字段。
3. 定义类型 B `InteractionRecord`，覆盖输入、NLP、安全检查、执行、响应和设备快照嵌套字段。
4. 定义类型 C `DeviceSnapshot`，可从 `DashboardSnapshot` 转换。
5. 增加 `validate_command_intent()`、`validate_interaction_record()`、`validate_device_snapshot()` 基础校验函数。
6. 新增 `interaction_archiver.py`，用户页文本提交时会写入 `interaction_session_<session_id>.jsonl`。
7. 用户页 NLP 解析完成后，会按同一 `msg_id` 回填 `nlp_result`。
