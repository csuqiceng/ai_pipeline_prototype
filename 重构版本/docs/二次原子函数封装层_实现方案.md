# 二次原子函数封装层 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在当前 Qt 机械手控制系统中实现“自然语言 -> 二次原子函数 -> QueryRecord/SixAxisCommand -> MODBUS Func”的标准化指令层。

**Architecture:** 保留现有模板、流程、系统命令执行链，在 `VoiceNlpAdapter` 与底层 `RobotModbusService` 之间新增原子指令层。新层负责唤醒词隔离、要素提取、默认值/记忆值补全、风险评估、确认策略、位置库与最终执行适配。

**Tech Stack:** Python 3、PySide6、现有 `QueryRecord` / `SixAxisCommand` 模型、现有 Func104/106/107/108/109/110/120 控制链。

---

## 1. 当前理解

`docs/二次原子函数封装表_V2.0.md` 定义的是自然语言生产指令到控制器 Func 的二次封装层，不是单纯关键词表。它要解决三个问题：

1. 把操作者语音分成闲聊、生产指令、应急指令、查询、流程控制。
2. 把半参数/模糊指令补齐成确定参数，例如“上升”补成 Z 轴增量、默认步长、当前速度、当前加减速。
3. 在真正下发 Func 前完成确认、安全预检、日志与界面反馈。

当前工程已经有一条可用链路：

```text
operator_ui_mixin.py / gui_ui_mixin.py
  -> nlp_mixin.py
  -> voice_nlp_adapter.py
  -> QueryRecord
  -> RobotModbusService.build_six_command_from_record()
  -> SixAxisCommand.to_func_writes()
  -> six_axis_command_mixin.py
  -> MODBUS 写入、回显等待、反馈读取、日志
```

现有限制是 `VoiceNlpAdapter` 目前只输出三类动作：`template`、`flow`、`system`。这能执行固定模板和已有流程，但还没有实现封装表要求的“原子函数层”：唤醒词、小正指令隔离、全/半/模糊参数、记忆参数、风险确认、位置库、查询类动作都没有形成统一模型。

因此本实现不应推翻现有执行链，而是新增一个原子计划层，让自然语言先转换为 `AtomicPlan`，再适配为现有 `QueryRecord` 或直接适配为 `SixAxisCommand`。

## 2. 实现边界

本期实现：

- 生产指令必须匹配“小正”前缀，应急三段式“急停XXX急停”除外。
- 支持 Func104、Func106、Func107、Func108、Func109、Func110、Func120。
- 支持应急、关节、虚拟轴、笛卡尔、速度步长、IO、延时、查询、位置库。
- 支持多动作顺序执行，例如“小正，上升3毫米，然后右移5毫米”。
- 单条动作按确认模式决定是否先确认，流程动作继续沿用现有流程执行。
- 原子指令执行继续复用现有回显等待、反馈读取、日志系统。

本期不实现：

- Func11 连续插补，仅保留接口和模型扩展位。
- 真正的三维路径规划，只做 PC 侧 L1 范围/状态/参数预检。
- 用大模型直接生成底层寄存器。大模型输出必须仍经过本地白名单和参数校验。

## 4. 核心数据模型

建议模型如下：

```python
@dataclass(frozen=True)
class AtomicIntent:
    intent_id: str
    category: str
    func_num: int | None
    params: dict[str, float | int | str | bool]
    raw_text: str
    display_text: str
    requires_confirm: bool = False
    risk_level: str = "low"
    source: str = "rule"


@dataclass(frozen=True)
class AtomicPlan:
    actions: tuple[AtomicIntent, ...]
    raw_text: str
    source: str
    reason: str
    executable: bool
    confirm_text: str = ""
    warning_text: str = ""


@dataclass
class AtomicMemory:
    current_speed: float = 50.0
    current_step_mm: float = 10.0
    current_step_deg: float = 5.0
    current_acc: float = 100.0
    current_dec: float = 100.0
    confirm_mode: str = "beginner"
    last_direction: tuple[float, float, float] | None = None
    last_command: dict[str, object] | None = None
```

`VoiceNlpAction` 可保持兼容，在原子计划输出时：

```python
VoiceNlpAction(
    action_type="atomic",
    target="atomic_plan_id",
    source="rule",
    raw_text=text,
    reason=plan.reason,
)
```

实际 `AtomicPlan` 可挂在 `VoiceNlpPlan` 的扩展字段，或在 `VoiceNlpAction` 增加 `payload` 字段。更推荐增加 `payload`，避免再用 `target` 传 JSON 字符串。

## 5. 解析与执行流程

标准流程：

```text
输入文本
  -> normalize_text()
  -> classify_input()
     - emergency: 三段式急停
     - command: 小正前缀生产指令
     - chat_with_warning: 提到急停/暂停/复位但无小正
     - chat: 普通问答
  -> split_actions()
  -> parse_atomic_intent()
  -> resolve_params()
  -> evaluate_risk()
  -> build_confirm_or_executable_plan()
  -> adapt_to_QueryRecord/SixAxisCommand
  -> _execute_query_key 或新增 _execute_atomic_intent
```

前缀规则必须放在所有生产动作解析之前：

- `急停123急停`：应急通道，校验编码白名单后执行 Func104。
- `小正，上升3毫米`：进入生产指令解析。
- `上升3毫米`：不执行，只作为普通问答或提示“生产动作请以小正开头”。
- `急停`：不执行，提示“如需急停请使用标准格式”。

| 原子动作 | Func | QueryRecord params / SixAxisCommand 字段 |
|---|---:|---|
| `emergency_stop` | 104 | `estop_ctrl=1` |
| `emergency_release` | 104 | `estop_ctrl=2` |
| `pause` | 104 | `pause_ctrl=1` |
| `resume` | 104 | `pause_ctrl=2` |
| `cancel` | 104 | `cancel_ctrl=1` |
| `reset` | 104 | `reset_ctrl=1` |
| `joint_nudge` | 106 | `axis_no, pos_val, spd_pct, acc_pct, dec_pct, fuzzy_pos=1` |
| `joint_move_abs` | 106 | `axis_no, pos_val, spd_pct, acc_pct, dec_pct, fuzzy_pos=0` |
| `virt_nudge` | 107 | `axis_no=6..11, pos_val, spd_pct, acc_pct, dec_pct, fuzzy_pos=1` |
| `virt_move_abs` | 107 | `axis_no=6..11, pos_val, spd_pct, acc_pct, dec_pct, fuzzy_pos=0` |
| `cart_move_abs` | 108 | `target_x/y/z/rx/ry/rz, spd_pct, acc_pct, dec_pct, fuzzy_pos=0, move_type` |
| `cart_move_rel` | 108 | `target_x/y/z/rx/ry/rz, spd_pct, acc_pct, dec_pct, fuzzy_pos=1, move_type` |
| `delay_t0` | 109 | `delay_sec` |
| `delay_t1` | 110 | `delay_sec` |
| `io_set` | 120 | `io_no, io_action` |
| `query_*` | 无 | 读取当前看板/反馈，不下发 Func |
| `set_speed/set_step` | 无 | 更新 `AtomicMemory`，不下发 Func |

`atomic_adapter.py` 生成临时 `QueryRecord` 的方式：

```python
record = QueryRecord(
    query_key=f"atomic:{intent.intent_id}",
    func_num=func_num,
    params=params,
    keywords=intent.raw_text,
    description=intent.display_text,
    safety_level=safety_level,
)
```

这样可继续调用现有：

```python
self.service.build_six_command_from_record(record)
```

## 7. 参数补全规则

参数来源优先级必须固定：

```text
用户本次明确值 > AtomicMemory 上次/当前值 > 系统默认值
```

示例：

- `小正，上升3毫米`  
  `axis_no=8, direction=+1, pos_val=3, spd_pct=current_speed, acc_pct=current_acc, dec_pct=current_dec`

- `小正，上升`  
  `axis_no=8, direction=+1, pos_val=current_step_mm`

- `小正，J1正转`  
  `axis_no=0, direction=+1, pos_val=current_step_deg`

- `小正，20%速度上升3毫米加速度50%减速度30%`  
  所有显式值覆盖记忆值。

缺失方向或轴号时不能直接执行：

- `小正，移动一下`：缺方向，返回“请说明方向，例如上升、下降、左移、右移”。
- `小正，正转5度`：缺关节轴，返回“请说明关节轴，例如 J1 正转5度”。

## 8. 确认与风险策略

风险等级：

- `emergency`：急停、暂停、复位类，直接执行。
- `low`：默认步长内，速度不超过 50%，远离限位。
- `medium`：步长超过默认 2 倍，或速度超过 50%，或接近限位。
- `high`：参数超限、接近奇异点、速度超过 80%，或安全预检失败。

确认模式：

| 模式 | low | medium | high | emergency |
|---|---|---|---|---|
| `beginner` | 确认 | 确认 | 确认 | 直接 |
| `skilled` | 直接 | 确认 | 确认 | 直接 |
| `expert` | 直接 | 直接 | 确认 | 直接 |

确认文案示例：

```text
准备执行：上升3毫米。
速度 50%，加速度 100%，减速度 100%。
预计 Z: 860.0 -> 863.0。
安全预检通过。确认执行吗？
```

确认阶段支持：

- `小正，确认`：执行挂起的原子计划。
- `小正，取消`：取消挂起计划。
- `小正，速度改为20%`：修改挂起计划速度后重新计算风险和确认文案。
- `小正，慢一点`：速度降低 10%，最低 5%。

## 9. UI 交互设计

用户页应保持“对话负责意图，侧栏负责状态”的边界：

- 对话区只显示自然语言问答、解析结果、确认请求、执行结果。
- 左侧状态区继续显示空闲/运行/报警、急停/暂停/报警、实时位置、快捷操作。
- 右侧最近操作显示完整日志，但要结构化，不做过滤。
- “完整状态”页面显示原子计划详情、当前记忆参数、位置库、最近日志。

当解析出待确认动作时：

```text
用户：小正，上升3毫米
AI：准备执行：上升3毫米。速度 50%，预计 Z 860.0 -> 863.0。确认执行吗？
```

当直接执行低风险动作时：

```text
用户：小正，上升
AI：已执行：上升10毫米。
```

当是闲聊或危险词误提及时：

```text
用户：急停
AI：未执行。急停请使用“小正，急停”或“急停123急停”。
```

## 11. 验收标准

完成后应满足：

- 没有“小正”的生产动作不会下发到控制器。
- 三段式急停在编码白名单内时可快速执行。
- 封装表中的 E/J/V/C/SP/IO/D/Q 核心指令都有本地规则覆盖。
- 半参数、模糊参数能按“显式值 > 记忆值 > 默认值”补齐。
- 需要确认的动作不会直接执行。
- 所有原子动作最终仍走现有 `SixAxisCommand` 写入、回显、反馈和日志链路。
- 用户页对话只展示人能理解的动作结果，不展示底层 JSON。

## 12. 关键风险

- 不能让大模型绕过本地安全层。DeepSeek 只能辅助分类，最终必须经过 `atomic_parser/resolver/adapter` 校验。
- 不能让旧模板规则在无“小正”时误执行生产动作。原子层上线后，`VoiceNlpAdapter` 需要先做生产指令隔离。
- 不能把确认逻辑只做在 UI 上。确认状态必须保存在后端计划对象中，否则语音确认和按钮确认会不一致。
- 不能直接把位置库写死在代码中。`home/safe` 可内置，用户保存的位置必须落盘。

## 13. 推荐实施顺序

1. 先做 `atomic_models`、`atomic_parser`、`atomic_resolver`，不接 GUI。
2. 再做 `atomic_adapter`，确认能生成现有 `QueryRecord` 并复用 `RobotModbusService`。
3. 再接 `VoiceNlpAdapter` 和 `NlpMixin`。
4. 最后接用户页确认卡、查询结果、位置库显示。
5. 每完成一类 Func 映射就加测试，避免等全部写完再联调。
