## 3. 已完成: M9 并行执行框架

当前已实现 V4.3 的并行 slot 模型。后续只需在真实硬件上验证时序和 SDK 触发锁存行为。

### 3.1 V4.3 目标模型

```text
motion slot:
  Func106 / Func107 / Func108 / Func109 / Func11

program slot:
  Func110 / Func120

系统控制:
  Func104 可随时触发
```

规则:

```text
1. motion slot 内部互斥，Func109 作为 V4.3 1.1 标准函数纳入该 slot
2. program slot 内部 Func110 和 Func120 互斥
3. motion slot 可与 program slot 并行
4. Func104 不受 slot 限制
```

### 3.2 已实现内容

已实现的执行前置检查:

```text
标准函数 106/107/108/109/11 只检查 motion slot 是否空闲
Func110/120 只检查 program slot 是否空闲
Func104 跳过 slot 检查
```

已实现的 GUI 执行层:

```text
1. 按 func_num 轮询目标函数状态
2. 允许运动/标准函数执行时下发 110/120
3. 110/120 互斥
4. 流程执行器支持 motion/standard + Func110 + optional Func120 典型并行组
```

已实现的 mock:

```text
1. mock_controller 中拆分 motion/program 执行状态
2. 模拟 110/120 与 106/107/108/109/11 并行互斥关系
3. 重复触发同 slot 时写 LONG(38).02 指令忙
4. Func104 不等待 motion/program 线程，reset_ctrl=1 会清理 mock slot 引用
```

### 3.3 已通过验证

```text
1. Func108 + Func110 可并行
2. Func110 + Func120 互斥
3. Func108 + Func106/Func109 互斥
4. Func104 执行中可触发
5. reset_ctrl=1 后 mock 不残留假忙 slot
6. GUI offscreen 并行组识别通过
7. tools/verify_v43_mock_m9.py 自动化验收 6/6 PASS
```

### 3.4 仍需真实硬件确认

```text
1. IEEE(32) 单触发位连续触发时，下位机是否稳定锁存上一条命令
2. motion/program 并行时 LONG(34) 多函数状态是否同时刷新
3. IEEE(322) 并行时只显示一个当前函数号，实际 GUI 判断不得依赖它
4. 真实 SDK 单连接读写是否需要额外串行锁
```

## 4. 已完成: 默认模板与打包内置模板同步

当前默认模板数据已完成 V4.3 语义对齐，并已确认源码与打包产物一致。

### 4.1 已完成内容

`data/query_table.json` 已补齐以下函数模板:

```text
Func11 / Func104 / Func106 / Func107 / Func108 / Func109 / Func110 / Func120
```

已修正的关键模板:

```text
1. J2回正: 改为 Func106 关节点动
2. Z上升50: 改为 Func108 相对 Z+50，fuzzy_pos=1
3. 位置B: 保持 Func108，但改为绝对位姿模板，fuzzy_pos=0
4. Func104: 默认模板改为显式 estop_ctrl / pause_ctrl / cancel_ctrl / reset_ctrl
```

### 4.2 GUI 编辑器已修正

后台模板编辑页中，Func104 不再仅靠旧 `stop_mode` 两态表达，而是改为显式系统动作选择:

```text
急停 / 暂停 / 继续 / 取消/结束 / 报警复位
```

这样可避免以下问题:

```text
1. “继续” 模板重新保存后被错误降级为“暂停”
2. “报警复位” 模板重新保存后丢失 reset_ctrl=1
3. Func104 模板预览与实际写入控制字不一致
```

### 4.3 打包产物已同步

已重新打包并校验以下三份文件内容一致:

```text
data/query_table.json
打包输出/dist/RobotModbusLite/_internal/data/query_table.json
dist/RobotModbusLite/_internal/data/query_table.json
```

已额外修正:

```text
build_qt.ps1 输出目录编码问题，避免再次生成乱码打包目录
```

### 4.4 已验证

```text
1. load_query_table_json() 可正常装载新模板
2. python -m compileall robot_modbus_lite data tools 通过
3. 离屏 GUI round-trip 验证: 急停 / 暂停 / 继续 / 报警复位 载入后再保存参数不变
4. 源码与两份包内置 query_table.json 的 SHA256 一致
```

说明: 该项属于本地数据与打包一致性修正，不替代真实控制器联调验证。
