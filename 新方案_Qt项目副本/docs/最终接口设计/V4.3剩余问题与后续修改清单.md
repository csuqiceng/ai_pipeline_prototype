# V4.3 剩余问题与后续修改清单

## 1. 总体状态

当前 V4.3 迁移核心功能已经完成:

- 8 个核心函数: Func104 / 106 / 107 / 108 / 109 / 110 / 120 / 11
- `LONG(34)` 函数状态和全局状态位
- `LONG(36)` 系统状态
- `LONG(38)` 报警码
- `IEEE(322)` 当前函数号
- MPOS `IEEE(1600~1622)` 位姿/关节反馈
- Func104 四控制字
- `BIT(151)` 报警复位执行路径移除
- `spd_pct / acc_pct / dec_pct` 百分比字段完全替换
- 查询表字段迁移
- M9 motion/program slot 并行执行框架
- mock V4.3 行为验证

剩余内容主要分为真实硬件验证、协议外兼容残留、待固件确认反馈和仓库卫生。

## 3. 已完成: M9 并行执行框架

当前已实现 V4.3 的并行 slot 模型。后续只需在真实硬件上验证时序和 SDK 触发锁存行为。

### 3.1 V4.3 目标模型

```text
motion slot:
  Func106 / Func107 / Func108 / Func109 / Func11

program slot:
  Func110 / Func120

系统控制:
  Func104 可随时触发
```

规则:

```text
1. motion slot 内部互斥，Func109 作为 V4.3 1.1 标准函数纳入该 slot
2. program slot 内部 Func110 和 Func120 互斥
3. motion slot 可与 program slot 并行
4. Func104 不受 slot 限制
```

### 3.2 已实现内容

已实现的执行前置检查:

```text
标准函数 106/107/108/109/11 只检查 motion slot 是否空闲
Func110/120 只检查 program slot 是否空闲
Func104 跳过 slot 检查
```

已实现的 GUI 执行层:

```text
1. 按 func_num 轮询目标函数状态
2. 允许运动/标准函数执行时下发 110/120
3. 110/120 互斥
4. 流程执行器支持 motion/standard + Func110 + optional Func120 典型并行组
```

已实现的 mock:

```text
1. mock_controller 中拆分 motion/program 执行状态
2. 模拟 110/120 与 106/107/108/109/11 并行互斥关系
3. 重复触发同 slot 时写 LONG(38).02 指令忙
4. Func104 不等待 motion/program 线程，reset_ctrl=1 会清理 mock slot 引用
```

### 3.3 已通过验证

```text
1. Func108 + Func110 可并行
2. Func110 + Func120 互斥
3. Func108 + Func106/Func109 互斥
4. Func104 执行中可触发
5. reset_ctrl=1 后 mock 不残留假忙 slot
6. GUI offscreen 并行组识别通过
```

### 3.4 仍需真实硬件确认

```text
1. IEEE(32) 单触发位连续触发时，下位机是否稳定锁存上一条命令
2. motion/program 并行时 LONG(34) 多函数状态是否同时刷新
3. IEEE(322) 并行时只显示一个当前函数号，实际 GUI 判断不得依赖它
4. 真实 SDK 单连接读写是否需要额外串行锁
```

## 7. P3: pycache 被版本控制跟踪

当前仓库中 `__pycache__` / `.pyc` 文件被 git 跟踪。

### 7.1 影响

每次运行:

```text
python -m compileall ...
```

都会导致 `.pyc` 文件显示为修改。

### 7.2 建议处理

后续做一次仓库卫生清理:

```text
1. 从 git 索引中移除 __pycache__ 和 *.pyc
2. 在 .gitignore 中加入:
   __pycache__/
   *.pyc
3. 保留源码和必要资源，不提交编译缓存
```

注意:

```text
这不是 V4.3 协议问题，不影响运行逻辑。
```
