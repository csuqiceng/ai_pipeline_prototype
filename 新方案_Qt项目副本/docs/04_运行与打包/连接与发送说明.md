# 连接与发送说明

## 1. 文档目的

本文档用于说明当前 `RobotModbusLite` 方案中：

- 上位机如何连接运动控制器
- 上位机如何组织发送数据
- 上位机如何通过 ZMOTION SDK 把数据写到控制器
- 当前 GUI/CLI 分别如何调用这套逻辑

适用对象：

- 项目评审人员
- 下位机工程师
- 上位机维护人员

## 2. 当前方案总览

当前方案采用“上位机查表 + 控制器执行”的模式。

也就是：

1. 上位机接收文本命令或流程
2. 上位机从查询表中查出一条或多条记录
3. 每条记录转换成一组连续数值
4. 上位机通过以太网连接控制器
5. 上位机通过 Modbus TCP 写入这组数值
6. 控制器收到后由 ZBasic 程序自行解析并执行

## 3. 控制器连接方式

### 3.1 连接参数

- 控制器 IP：`192.168.1.11`
- 连接方式：以太网
- 通讯协议：`Modbus TCP`
- SDK：`ZMOTION SDK`

### 3.2 当前程序如何连接

当前程序不自己写 socket，而是直接调用 ZMOTION SDK 提供的接口连接控制器。

连接入口在：

- [zmotion_client.py](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/robot_modbus_lite/zmotion_client.py)

核心逻辑：

```python
ret = self._device.ZAux_OpenEth(self.host)
```

这里的 `self.host` 默认是：

```text
192.168.1.11
```

如果返回码为 `0`，表示 SDK 层连接成功。  
如果返回码非 `0`，表示连接失败，例如当前现场出现的 `20008`。

### 3.3 GUI 中的“测试连接”如何实现

GUI 加载后会自动调用后台线程执行连接检测。

对应文件：

- [gui.py](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/robot_modbus_lite/gui.py)

流程如下：

1. GUI 启动
2. 调用 `_run_connection_check()`
3. 后台线程执行 `_check_controller_connection()`
4. 创建 `ZMotionModbusClient`
5. 调用 `client.connect()`
6. 连接成功或失败后，把结果显示到页面
7. 最后断开连接

所以 GUI 的“连接状态”不是模拟值，而是真正调用 SDK 去连控制器。

## 4. 查询表与发送数据的关系

### 4.1 数据来源

当前方案使用的是“有效数据查询表”，原始来源是：

- [机械臂AI地址表.csv](c:/Users/a/Desktop/ai_pipeline_prototype/附件/机械臂AI地址表.csv)

GUI 首次启动时，会把 CSV 导入成自己的 JSON 数据源：

- [query_table.json](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/data/query_table.json)

之后 GUI 的新增、编辑、删除都只操作这个 JSON，不改原始 CSV。

### 4.2 单条记录的结构

当前每条记录都可以理解成一条“可执行节点”。

例如：

```text
位置A    3    1400    -1    1380    1    80    1    10
```

它表示：

- 查询键：`位置A`
- 函数序号：`3`
- 参数 1~7：`1400, -1, 1380, 1, 80, 1, 10`

### 4.3 当前发送结构

上位机发送时，会把一条记录转换成：

```text
[函数序号, 参数1, 参数2, 参数3, 参数4, 参数5, 参数6, 参数7]
```

例如：

```text
[3, 1400, -1, 1380, 1, 80, 1, 10]
```

### 4.4 业务理解

当前上位机不关心每个参数在控制器内部如何解释，只负责：

- 查到什么
- 就把什么发过去

控制器端再负责：

- 读取函数序号
- 读取后续参数
- 调对应的 ZBasic 函数

## 6. 流程如何变成逐步发送

### 6.1 流程定义

流程保存到：

- [flows.json](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/data/flows.json)

格式例如：

```json
{
  "flows": [
    {
      "name": "流程1",
      "steps": ["归零", "home", "位置A", "位置B", "抓取", "放下"]
    }
  ]
}
```

### 6.2 流程执行逻辑

执行流程时，上位机会：

1. 读取流程名
2. 按顺序遍历每个步骤
3. 每一步都去查询表中找到对应记录
4. 把每一步都转换成 8 个值
5. 逐步调用 SDK 发送

对应实现位置：

- [service.py](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/robot_modbus_lite/service.py)
- [gui.py](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/robot_modbus_lite/gui.py)

### 6.3 当前流程发送特点

当前版本是“顺序逐步发送”，即：

- 第一步发完
- 再发第二步
- 再发第三步

当前版本还没有做：

- 每一步执行完成状态回读
- 每一步完成确认后再发下一步
- 超时/中断恢复

所以当前流程能力适合早期联调，不适合直接定义为最终生产逻辑。

## 7. 实际发送调用

### 7.1 当前发送接口

当前实际发送调用的是：

```python
self._device.ZAux_Modbus_Set4x_Float(start, inum, pdata)
```

说明：

- `start`：起始寄存器地址
- `inum`：写入数量
- `pdata`：浮点数组

### 7.2 当前程序中的默认值

当前默认：

- `start_register = 0`
- `values` 长度 = `8`

也就是默认按下面的方式写：

```text
从起始地址 0 开始，连续写 8 个值
```

如果下位机需要其他起始地址，后续只要调整配置即可。

### 7.3 发送代码位置

发送逻辑在：

- [zmotion_client.py](c:/Users/a/Desktop/ai_pipeline_prototype/新方案/robot_modbus_lite/zmotion_client.py)

核心调用：

```python
ret = self._device.ZAux_Modbus_Set4x_Float(
    request.start_register,
    len(request.values),
    list(request.values),
)
```

1. 选择流程名称
