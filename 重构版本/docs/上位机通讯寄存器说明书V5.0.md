# 正运动机械手控制器 — 上位机通讯寄存器说明书

> 版本：V2.1  
> 更新日期：2026-05-16  
> 控制器型号：VPLC516E  
> 通讯协议：Modbus TCP/RTU  
> 字节序：大端模式（Big-Endian）

---

## 一、通讯概述

上位机通过Modbus协议与控制器通讯，采用IEEE浮点寄存器传递参数，LONG寄存器传递状态。

### 地址分区规则

| 区域 | 地址范围 | 读/写 | 说明 |
|------|----------|-------|------|
| IEEE(0~32) | 上位机专用区 | 上位机写，控制器只读 | 功能号、运动参数、执行触发 |
| IEEE(280~332) | 指令回显区 | 控制器写，上位机只读 | 上位机写入参数的回显，用于比对确认 |
| IEEE(34+) | 控制器写入区 | 控制器写，上位机只读 | 状态反馈、位置反馈、报警信息 |
| LONG(34/36/38/40/42/44/46) | 状态寄存器 | 控制器写，上位机只读 | 9个核心标志位 + 函数状态 + 报警 + IO |

**重要**：控制器ZBasic代码不能写入IEEE(0~32)区域。上位机每次只调用一个功能，不同函数可分时复用同一参数地址。

## 二、命令发送流程（三道门机制）

### 2.1 标准命令发送步骤

上位机每次发送指令都必须严格遵循"三道门"检查机制，确保指令在安全状态下发送、参数正确到达、系统状态未在发送过程中发生变化。**每一个函数的发送都独立走完整流程，上一个函数完成后才能发下一个。**

```
步骤1 - 第一道门（发指令前检查）：
  读取LONG(34)，检查4个条件：
  ① 报警=0?  ② 急停=0?  ③ 暂停=0?  ④ 同任务通道无执行中函数?
  任一不满足 → 提醒操作员，不发送指令

步骤2 - 写入参数：
  IEEE(0) = 函数号
  IEEE(2)~IEEE(30) = 参数

步骤3 - 第二道门（回显比对）：
  读取 IEEE(280)~IEEE(310)，与写入值逐一比对
  不一致 → 提醒"回显不一致"，重新写入

步骤4 - 第三道门（触发前二次检查）：
  再次读取LONG(34)，检查3个条件：
  ① 报警=0?  ② 急停=0?  ③ 暂停=0?
  任一不满足 → 提醒，不触发，回到步骤1

步骤5 - 触发执行：
  写入 IEEE(32) = 1

步骤6 - 等待完成：
  等待 IEEE(312) = 1（命令已被接受）
  等待 LONG(34) 中相应函数DONE
  确认无报警 → 回到步骤1，发送下一个命令
```

> 三道门的详细说明、判断方法和典型场景示例，请参见第八章"上位机发指令逻辑"。

### 2.2 回显区说明

上位机写入IEEE(0~32)后，控制器会将这些值复制到回显区IEEE(280~312)。上位机在触发执行前，应先读取回显区与写入值比对，确认参数已正确到达控制器。

| 写入地址 | 回显地址 | 说明 |
|----------|----------|------|
| IEEE(0) 函数号 | IEEE(280) | 回显当前函数号 |
| IEEE(2) 参数0 | IEEE(282) | 回显参数0 |
| IEEE(4) 参数1 | IEEE(284) | 回显参数1 |
| IEEE(6) 参数2 | IEEE(286) | 回显参数2 |
| ... | ... | 以此类推，步长=2 |
| IEEE(30) 参数14 | IEEE(310) | 回显参数14 |
| IEEE(32) 触发位 | IEEE(312) | 1=命令已被接受 |

**回显区行为**：
- 运动函数执行期间（cmd_busy=1）：回显区显示正在执行的函数号和参数
- 空闲期间：回显区实时跟随IEEE(0~32)的值
- IEEE(312)=1 表示命令已被控制器接受并开始处理

### 2.3 命令时序要求

- **第一道门**：写入参数前必须确认系统无报警、无急停、无暂停、同通道空闲
- **第二道门**：写入参数后必须读取回显区比对，确认参数正确到达控制器
- **第三道门**：触发前必须再次确认系统状态未发生变化
- 三道门全部通过后才能写入 IEEE(32) = 1 触发执行
- 控制器接受命令后自动清零 IEEE(32)
- 上位机检测到 IEEE(312)=1 后确认命令已被接受
- 同一通道（运动通道/程序通道）同一时刻只能执行一个函数

## 五、9个核心状态标志位（从LONG(34)读取）

上位机通过读取LONG(34)的特定位来判断9个核心状态。上位机不需要读取BIT地址，直接对LONG(34)做位与运算即可。

### 5.1 系统级标志（3个）

| 标志 | 寄存器.位 | 掩码(十六进制) | 判断方法 | 1=有效 | 0=无效 |
|------|----------|---------------|----------|--------|--------|
| 急停 | LONG(34).bit25 | $2000000 | (LONG(34) AND $2000000) ≠ 0 | 急停中 | 正常 |
| 暂停 | LONG(34).bit26 | $4000000 | (LONG(34) AND $4000000) ≠ 0 | 暂停中 | 正常 |
| 报警 | LONG(34).bit24 | $1000000 | (LONG(34) AND $1000000) ≠ 0 | 有报警 | 正常 |

### 5.2 运动任务T0状态（3个）— 函数号：106/107/108/109

| 标志 | 寄存器.位 | 掩码(十六进制) | 判断方法 | 1=有效 |
|------|----------|---------------|----------|--------|
| 运动就绪 | LONG(34).bit28 | $10000000 | (LONG(34) AND $10000000) ≠ 0 AND (LONG(34) AND $1000000) = 0 AND T0无执行中函数 | 就绪，可发命令 |
| 运动执行中 | LONG(34).bit2~9 | 见下方 | T0任一函数EXEC状态 | 执行中 |
| 运动完成 | LONG(34).bit2~9 | 见下方 | T0任一函数DONE状态 AND T0无执行中函数 | 完成 |

**运动执行中判断**：以下任一条件成立即为执行中
```
(LONG(34) AND $C) = $4         → LONG(34).bit2=1, bit3=0 → 106执行中
OR (LONG(34) AND $30) = $10    → LONG(34).bit4=1, bit5=0 → 107执行中
OR (LONG(34) AND $C0) = $40    → LONG(34).bit6=1, bit7=0 → 108执行中
OR (LONG(34) AND $300) = $100  → LONG(34).bit8=1, bit9=0 → 109执行中
以上任一成立 → T0通道忙，不能发T0函数
```

**运动完成判断**：以下任一条件成立且无执行中函数
```
(LONG(34) AND $C) = $8         → LONG(34).bit2=0, bit3=1 → 106完成
OR (LONG(34) AND $30) = $20    → LONG(34).bit4=0, bit5=1 → 107完成
OR (LONG(34) AND $C0) = $80    → LONG(34).bit6=0, bit7=1 → 108完成
OR (LONG(34) AND $300) = $200  → LONG(34).bit8=0, bit9=1 → 109完成
以上任一成立且无执行中 → T0通道完成
```

### 5.3 程序任务T1状态（3个）— 函数号：110/120

| 标志 | 寄存器.位 | 掩码(十六进制) | 判断方法 | 1=有效 |
|------|----------|---------------|----------|--------|
| 程序就绪 | LONG(34).bit28 | $10000000 | (LONG(34) AND $10000000) ≠ 0 AND (LONG(34) AND $1000000) = 0 AND T1无执行中函数 | 就绪，可发命令 |
| 程序执行中 | LONG(34).bit10~19 | 见下方 | T1任一函数EXEC状态 | 执行中 |
| 程序完成 | LONG(34).bit10~19 | 见下方 | T1任一函数DONE状态 AND T1无执行中函数 | 完成 |

**程序执行中判断**：以下任一条件成立即为执行中
```
(LONG(34) AND $C00) = $400      → LONG(34).bit10=1, bit11=0 → 110执行中
OR (LONG(34) AND $C0000) = $40000 → LONG(34).bit18=1, bit19=0 → 120执行中
以上任一成立 → T1通道忙，不能发T1函数
```

**程序完成判断**：以下任一条件成立且无执行中函数
```
(LONG(34) AND $C00) = $800      → LONG(34).bit10=0, bit11=1 → 110完成
OR (LONG(34) AND $C0000) = $80000 → LONG(34).bit18=0, bit19=1 → 120完成
以上任一成立且无执行中 → T1通道完成
```

### 5.4 三态逻辑说明

每组3个标志位遵循三态互斥逻辑：

| 状态 | 就绪 | 执行中 | 完成 | 说明 |
|------|------|--------|------|------|
| 就绪 | 1 | 0 | 0 | 无报警，无函数执行，可接受新命令 |
| 执行中 | 0 | 1 | 0 | 函数正在运行 |
| 完成 | 1 | 0 | 1 | 函数执行完毕，可接受新命令 |
| 异常 | 0 | 0 | 0 | 有急停/报警/暂停 |

**上位机推荐判断逻辑**：
- 发命令条件：就绪=1 或 完成=1
- 等待完成：执行中=1 → 等待 → 完成=1
- 异常检测：急停=1 或 报警=1

## 八、上位机发指令逻辑（核心流程）

上位机每次发送指令都必须严格遵循"三道门"检查机制，确保指令在安全状态下发送、参数正确到达、系统状态未在发送过程中发生变化。**每一个函数的发送都独立走完整流程，上一个函数完成后才能发下一个。**

### 8.1 第一道门：发指令前检查

**目的**：确认系统处于可接受新命令的状态。

发送任何指令前，必须先读取LONG(34)，检查以下4个条件。**任一条件不满足则不发送指令，并给出相应提醒**：

| 序号 | 检查项 | 寄存器.位 | 判断方法 | 不满足时的提醒 | 不满足时的处理 |
|------|--------|----------|----------|---------------|---------------|
| ① | 无报警 | LONG(34).bit24 | (LONG(34) AND $1000000) = 0 | "系统报警，请先复位" | 发送104函数报警复位 |
| ② | 无急停 | LONG(34).bit25 | (LONG(34) AND $2000000) = 0 | "急停状态，请先解除" | 等待硬件急停解除后发104复位 |
| ③ | 无暂停 | LONG(34).bit26 | (LONG(34) AND $4000000) = 0 | "系统暂停中" | 发送104函数恢复运动 |
| ④ | 同任务通道无执行中函数 | 见下方 | 见下方 | "函数执行中，请等待" | 等待当前函数完成 |

**第④项具体判断方法**：

发运动任务T0的函数（106/107/108/109）时，检查T0通道：
```
(LONG(34) AND $C) = $4         → LONG(34).bit2=1, bit3=0 → 106执行中
(LONG(34) AND $30) = $10       → LONG(34).bit4=1, bit5=0 → 107执行中
(LONG(34) AND $C0) = $40       → LONG(34).bit6=1, bit7=0 → 108执行中
(LONG(34) AND $300) = $100     → LONG(34).bit8=1, bit9=0 → 109执行中
以上任一成立 → T0通道忙，不能发T0函数
```

发程序任务T1的函数（110/120）时，检查T1通道：
```
(LONG(34) AND $C00) = $400       → LONG(34).bit10=1, bit11=0 → 110执行中
(LONG(34) AND $C0000) = $40000   → LONG(34).bit18=1, bit19=0 → 120执行中
以上任一成立 → T1通道忙，不能发T1函数
```

**注意**：T0和T1是独立通道，T0忙时不影响T1发指令，反之亦然。但急停/报警/暂停是系统级的，任一通道都不能发。

**4个条件全部满足 → 进入第二道门**

### 8.2 不能发送时的自动处理策略（重要！）

**核心原则**：上位机遇到不能发送的情况时，必须区分"可自动恢复"和"需人工处理"两种类型，采用不同策略，以保证整个流程能自动正常运行。

#### 8.2.1 两类阻塞状态

| 类型 | 触发条件 | 性质 | 处理策略 |
|------|----------|------|----------|
| **可自动恢复** | 函数执行中、暂停中 | 暂时性阻塞，系统会自动解除 | **自动等待，条件满足后立即执行，不需人工干预** |
| **需人工处理** | 急停、报警 | 安全性阻塞，必须人工确认后才能恢复 | **立即通知操作人员，等待人工处理** |

#### 8.2.2 可自动恢复 — 函数执行中

**场景**：上位机准备发下一个函数，但同任务通道的当前函数还在执行中。

**处理逻辑**：
```
1. 检测到同通道函数执行中 → 不发指令
2. 自动进入查询等待状态（轮询LONG(34)）
3. 检测到当前函数DONE → 立即继续三道门流程
4. 无需人工干预，流程自动继续
```

**关键**：上位机程序必须实现自动等待机制，而不是简单地报错后停止。等待期间应显示"等待前一个函数完成..."的状态提示，函数完成后立即自动执行下一个函数。

**示例**：
```
上位机流程：108直线插补 → 109延时 → 107虚拟点动

发送108 → 执行中 → 108完成
发送109 → 第一道门检查：T0通道空闲 ✓ → 写入 → 比对 → 触发 → 109执行中
准备发107 → 第一道门检查：T0通道忙(109执行中)
  → 自动进入查询等待
  → 轮询LONG(34)，检测(LONG(34) AND $300) = $200 → 109完成
  → 立即继续：写入107参数 → 比对 → 触发 → 107执行
  → 全程无需人工干预
```

#### 8.2.3 可自动恢复 — 暂停中

**场景**：上位机准备发函数，但系统处于暂停状态。

**处理逻辑**：
```
1. 检测到暂停 → 不发指令
2. 自动进入查询等待状态（轮询LONG(34)）
3. 检测到暂停解除（LONG(34).bit26=0）→ 立即继续三道门流程
4. 无需人工干预，流程自动继续
```

**说明**：暂停可能是操作员主动暂停（如HMI按暂停按钮），也可能是上位机自己发的暂停命令。无论哪种情况，暂停解除后上位机应自动继续执行，不需要重新发送指令。

**注意**：如果上位机希望主动恢复暂停，可以发送104函数恢复命令（IEEE(0)=104, IEEE(4)=2），然后继续流程。如果选择等待操作员在HMI上恢复，则自动查询等待即可。

#### 8.2.4 需人工处理 — 急停

**场景**：上位机准备发函数或二次检查时，检测到急停状态。

**处理逻辑**：
```
1. 检测到急停（LONG(34).bit25=1）→ 立即停止所有指令发送
2. 弹出醒目通知："⚠ 急停状态！请检查急停原因并解除"
3. 等待人工处理：
   a. 操作员解除硬件急停
   b. 操作员在上位机界面点击"报警复位"
   c. 上位机发送104函数报警复位
4. 等待 (LONG(34).bit25=0) AND (LONG(34).bit24=0) → 急停和报警都清除
5. 人工确认后，恢复自动流程
```

**关键**：急停是安全级事件，上位机**绝不能自动恢复**，必须等人工确认安全后才继续。

#### 8.2.5 需人工处理 — 报警

**场景**：上位机准备发函数或二次检查时，检测到报警状态。

**处理逻辑**：
```
1. 检测到报警（LONG(34).bit24=1）→ 立即停止所有指令发送
2. 读取LONG(38)确认报警类型，弹出醒目通知：
   - LONG(38).bit0=1 → "⚠ 半径超限报警"
   - LONG(38).bit3=1 → "⚠ 速度超限报警"
   - LONG(38).bit6=1 → "⚠ ECAT通讯报警"
   - LONG(38).bit7=1 → "⚠ 驱动报警"
   - 等等
3. 等待人工处理：
   a. 操作员确认报警原因
   b. 操作员在上位机界面点击"报警复位"
   c. 上位机发送104函数报警复位
4. 等待 (LONG(34).bit24=0) AND (LONG(38)=0) → 报警清除
5. 人工确认后，恢复自动流程
```

**关键**：报警是安全级事件，上位机**绝不能自动恢复**，必须等人工确认报警原因并处理后才继续。

#### 8.2.6 第三道门检测到异常的自动处理

第三道门（触发前二次检查）检测到异常时，处理策略与第一道门一致：

| 第三道门检测到 | 类型 | 处理 |
|---------------|------|------|
| 暂停（LONG(34).bit26=1） | 可自动恢复 | 自动查询等待暂停解除后，重新走三道门流程 |
| 急停（LONG(34).bit25=1） | 需人工处理 | 立即通知操作员，等待人工处理 |
| 报警（LONG(34).bit24=1） | 需人工处理 | 立即通知操作员，显示报警类型，等待人工处理 |

**注意**：第三道门检测到暂停时，参数已经写入控制器，暂停解除后不需要重新写入参数，直接回到第一道门重新检查即可（回显区仍保持之前写入的值）。

### 8.3 写入函数号和参数

第一道门通过后，将函数号和参数写入控制器：

```
写入 IEEE(0) = 函数号
写入 IEEE(2) = 参数0
写入 IEEE(4) = 参数1
...
写入 IEEE(30) = 参数14
```

**注意**：只写入当前函数需要的参数，不需要的参数可以不写。

### 8.4 第二道门：回显比对

**目的**：确认写入的函数号和参数已正确到达控制器，防止通讯干扰导致数据错误。

写入参数后，读取回显区IEEE(280)~IEEE(310)，与刚才写入的值逐一比对：

| 比对项 | 写入地址 | 回显地址 | 判断方法 | 不满足时处理 |
|--------|----------|----------|----------|-------------|
| 函数号 | IEEE(0) | IEEE(280) | IEEE(280) = 写入值 | 提示"函数号回显不一致"，重新写入 |
| 参数0 | IEEE(2) | IEEE(282) | IEEE(282) = 写入值 | 提示"参数0回显不一致"，重新写入 |
| 参数1 | IEEE(4) | IEEE(284) | IEEE(284) = 写入值 | 提示"参数1回显不一致"，重新写入 |
| ... | ... | ... | ... | ... |
| 参数14 | IEEE(30) | IEEE(310) | IEEE(310) = 写入值 | 提示"参数14回显不一致"，重新写入 |

**比对策略**：
- 只比对当前函数用到的参数，未使用的参数跳过
- 比对失败时，应重新写入全部参数后再次比对
- 连续比对失败3次，提示"通讯异常"，暂停发送

**比对全部通过 → 进入第三道门**

### 8.5 第三道门：触发前二次检查

**目的**：在写入参数到触发执行的时间窗口内，系统状态可能发生变化（如突然急停），必须再次确认。

回显比对通过后，**再次读取LONG(34)**，检查系统状态是否在比对期间发生了变化：

| 序号 | 检查项 | 寄存器.位 | 判断方法 | 不满足时的提醒 | 不满足时的处理 |
|------|--------|----------|----------|---------------|---------------|
| ① | 无报警 | LONG(34).bit24 | (LONG(34) AND $1000000) = 0 | "比对期间系统报警" | 不发送触发，回到第一道门 |
| ② | 无急停 | LONG(34).bit25 | (LONG(34) AND $2000000) = 0 | "比对期间急停" | 不发送触发，等待急停解除 |
| ③ | 无暂停 | LONG(34).bit26 | (LONG(34) AND $4000000) = 0 | "比对期间暂停" | 不发送触发，等待暂停解除 |

**注意**：第三道门不检查通道忙闲，因为参数已经写入，通道状态不会在比对期间突变（除非有其他主站同时发命令）。

**3个条件全部满足 → 发送 IEEE(32) = 1 触发执行**

### 8.6 等待执行完成

触发执行后，进入等待阶段：

```
1. 等待 IEEE(312) = 1              → 命令已被控制器接受
2. 等待 LONG(34) 中对应函数DONE    → 函数执行完成
3. 确认无报警: (LONG(34) AND $1000000) = 0
4. 回到8.1第一道门，发送下一个命令
```

**等待期间的异常处理**：
- 如果等待过程中检测到急停(LONG(34) bit25=1)：停止等待，进入急停处理流程
- 如果等待过程中检测到报警(LONG(34) bit24=1)：停止等待，读取LONG(38)确认报警类型
- 如果等待超时（如30秒未完成）：提示"执行超时"，可发104取消当前函数

### 8.8 典型场景示例

#### 场景1：单次运动命令（108直线插补）

```
步骤1 - 第一道门：读取LONG(34)
  - (LONG(34) AND $1000000) = 0   ✓ 无报警
  - (LONG(34) AND $2000000) = 0   ✓ 无急停
  - (LONG(34) AND $4000000) = 0   ✓ 无暂停
  - T0通道检查：
    (LONG(34) AND $C) ≠ $4        ✓ 106未执行中
    (LONG(34) AND $30) ≠ $10      ✓ 107未执行中
    (LONG(34) AND $C0) ≠ $40      ✓ 108未执行中
    (LONG(34) AND $300) ≠ $100    ✓ 109未执行中

步骤2 - 写入参数：
  IEEE(0) = 108
  IEEE(2) = 目标X, IEEE(4) = 目标Y, IEEE(6) = 目标Z
  IEEE(8) = 目标RX, IEEE(10) = 目标RY, IEEE(12) = 目标RZ
  IEEE(14) = 速度%, IEEE(16) = 加速度%, IEEE(18) = 减速度%

步骤3 - 第二道门：回显比对
  IEEE(280) = 108                 ✓ 函数号一致
```

## 九、注意事项

1. **IEEE(0~32)为上位机专用区**，控制器不会写入此区域，上位机可放心写入
2. **回显区必须比对通过后才触发IEEE(32)=1**，确保参数正确到达控制器
3. **同一通道同一时刻只能执行一个函数**，如果函数忙会返回LONG(38) bit2=1（自动清除）
4. **所有速度/加速度/减速度参数统一使用百分比（0~100%）**，控制器内部自动转换为实际值
5. **LONG(38)≠0时LONG(34)的bit24（报警）自动置1**，上位机应先检查LONG(38)的具体报警位
6. **报警复位(104函数)会清除所有报警标志**，并将各函数状态设为DONE
7. **120函数执行很快（约500ms）**，上位机可快速连续发送
8. **109延时完成标志需要上位机手动清除**：写入IEEE(8)=1可清除109的DONE状态
9. **暂停期间运动执行中状态仍为1**，这是正常行为，恢复后继续执行
10. **运动函数执行时会自动切换运动模式**（106→关节模式，107/108→笛卡尔模式），上位机无需手动切换
