# 机械手自然语言交互系统配置文件说明

本文说明 `data/` 目录下所有运行配置文件的用途、字段含义、修改方法和注意事项。

适用范围：Qt 工程师页面、用户页、自然语言解析、流程/位置管理、语音会话、TTS 播报、DeepSeek 问答、本地知识库和安全预检。

## 一、总览

| 文件 | 主要用途 | 是否建议现场修改 |
|---|---|---|
| `system_config.json` | 系统安全范围、超时、轮询、TTS、UI 缩放等全局参数 | 可以，但要谨慎 |
| `query_table.json` | 命令模板表，自然语言模板到 Func 参数的映射 | 可以，建议通过界面维护 |
| `position_registry.json` | 结构化位置库，如 `home`、休息位、位置A | 可以，建议通过界面维护 |
| `flow_registry.json` | 结构化流程库，含步骤、确认、状态、演练速度 | 可以，建议通过界面维护 |
| `flows.json` | 旧版/兼容流程库，流程名到模板步骤列表 | 可以，但优先使用 `flow_registry.json` |
| `nlp_standard_words.json` | 标准词、同音词、方言词、拼音归一化词表 | 可以，经常需要现场扩充 |
| `voice_wake_words.json` | 唤醒词和唤醒词别名，如“小正/小郑/小郭” | 可以 |
| `flow_phrase_aliases.json` | 复杂流程口语动作白名单，如“点头”展开为 Ry 正反转 | 可以，但必须谨慎 |
| `dashboard_query_aliases.json` | 看板/状态查询别名，如“下位机状态” | 可以 |
| `assistant_knowledge_base.json` | AI 助手本地知识库，用于闲聊、功能说明、安全边界问答 | 可以 |
| `atomic_state.json` | 原子自然语言记忆状态，如当前速度、步长、确认模式 | 可以但不建议手改 |
| `memory_params.json` | 跨会话速度偏好和统计信息 | 可以但不建议手改 |
| `avoidance_rules.json` | 避障/安全中间点规则 | 可以，但需要工程师确认 |

修改配置后，一般需要重启 GUI 才能完整生效。部分 NLP 词表和知识库在重新构建解析器时可生效，但现场操作建议统一重启。

## 二、`system_config.json`

### 作用

全局系统配置。包括：

- 软限位和安全边界
- 六轴通信/执行超时
- 回显比对参数
- 应急编码
- TTS 播报设置
- 用户页刷新周期
- L3 流程预检参数
- 关节软限位
- UI 缩放比例

主要加载代码：`robot_modbus_lite/system_config.py`

### 字段说明

| 字段 | 类型 | 含义 | 当前示例 |
|---|---|---|---|
| `x` | `[min,max]` | X 轴软限位，单位通常为 mm | `[-3000,3000]` |
| `y` | `[min,max]` | Y 轴软限位 | `[-3000,3000]` |
| `z` | `[min,max]` | Z 轴软限位 | `[0,3000]` |
| `safe_r_min` | number | 安全半径下限 | `200.0` |
| `safe_r_max` | number | 安全半径上限 | `1800.0` |
| `safe_z_min` | number | 安全高度下限 | `0.0` |
| `safe_z_max` | number | 安全高度上限 | `2500.0` |
| `safe_speed_max` | number | 速度百分比上限 | `150.0` |
| `safe_acc_max` | number | 加速度百分比上限 | `150.0` |
| `safe_dec_max` | number | 减速度百分比上限 | `150.0` |
| `motion_timeout_sec` | number | 等待动作完成的最大时间，单位秒 | `180.0` |
| `six_accept_timeout_sec` | number | 触发命令后等待 `IEEE(312)=1` 接受确认的最大时间 | `1.0` |
| `six_busy_timeout_sec` | number | 发送前等待目标通道空闲的最大时间 | `5.0` |
| `six_ready_recovery_timeout_sec` | number | 复位后等待系统重新就绪的最大时间 | `5.0` |
| `six_post_trigger_settle_sec` | number | 写 `IEEE(32)=1` 后稳定等待时间 | `0.08` |
| `six_status_poll_interval_sec` | number | 读取 `LONG(34/36/38)` 等状态的轮询间隔 | `0.05` |
| `six_accept_poll_interval_sec` | number | 读取 `IEEE(312)` 接受确认的轮询间隔 | `0.02` |
| `echo_retry_interval_sec` | number | 回显比对重试间隔 | `0.005` |
| `echo_retry_count` | integer | 回显比对最大重试次数 | `3` |
| `echo_write_rounds` | integer | 参数写入轮数 | `2` |
| `echo_compare_epsilon` | number | 浮点回显容差 | `0.001` |
| `emergency_codes` | list[str] | 三段式应急口令白名单，如“急停 A1B2 急停” | `["A1B2"]` |
| `operator_tts_enabled` | bool | 用户页是否默认启用 TTS 播报 | `true` |
| `broadcast_dedupe_window_sec` | number | 主动播报去重窗口，避免短时间重复播报 | `5.0` |
| `tts_retry_delay_sec` | number | TTS 失败后的重试延迟 | `5.0` |
| `tts_max_failures` | integer | TTS 连续失败阈值 | `3` |
| `operator_confirm_timeout_sec` | number | 用户页安全确认超时时间 | `60.0` |
| `operator_dashboard_refresh_ms` | integer | 用户页看板数据刷新间隔 | `50` |
| `operator_view_refresh_ms` | integer | 用户页界面显示刷新间隔 | `500` |
| `controller_realtime_poll_ms` | integer | 控制器实时反馈轮询间隔 | `500` |
| `dashboard_stale_after_ms` | integer | 看板数据超过多久视为过期 | `1000` |
| `l3_min_step_delay_ms` | integer | L3 流程预检最小步骤间隔 | `0` |
| `l3_cumulative_error_limit_mm` | number | L3 累计误差限制，0 表示不启用 | `0.0` |
| `l3_forbidden_boxes` | list[object] | L3 禁入包围盒列表 | `[]` |
| `joint_limits` | list | 关节软限位列表，通常 6 组 `[min,max]` | `[]` |
| `ui_scale` | `"auto"` 或 number | UI 缩放比例，支持自动或 `0.6~1.2` | `"auto"` |

### 修改建议

- 如果现场报 `六轴接受确认超时 IEEE(312)=0`，可先把 `six_accept_timeout_sec` 从 `1.0` 调到 `2.0` 或 `3.0`。
- 如果动作本身很长，把 `motion_timeout_sec` 调大。
- 如果 UI 在高 DPI 或超宽屏下显示不全，保持 `ui_scale="auto"`；需要强制缩放时可设为 `0.8`、`0.9` 等。
- 不建议随意增大 `safe_speed_max/safe_acc_max/safe_dec_max`，这会放宽安全预检。

## 三、`query_table.json`

### 作用

命令模板表。系统把用户说的模板名称或关键词映射为具体 Func 号和参数。

主要使用场景：

- 工程师页面模板管理
- 用户页“有哪些默认命令”
- 自然语言模板匹配
- 流程执行时按 `query_key` 查找具体动作

主要加载代码：`robot_modbus_lite/query_table.py`

### 顶层结构

```json
{
  "records": [
    {
      "query_key": "位置A",
      "func_num": 108,
      "keywords": "位置A A点",
      "description": "移动到位置A",
      "safety_level": 5,
      "params": {}
    }
  ]
}
```

### 字段说明

| 字段 | 含义 |
|---|---|
| `query_key` | 模板唯一名称。流程步骤、自然语言结果都会引用这个名称 |
| `func_num` | 下发功能号，如 104/106/107/108/109/110/120 |
| `keywords` | 关键词字符串，用于搜索和匹配 |
| `description` | 展示给用户或工程师看的说明 |
| `safety_level` | 安全等级，数字越大风险越高，通常流程确认会参考 |
| `params` | Func 参数字典 |

### 常用 Func 参数

#### Func106/107 关节或虚拟轴点动

| 参数 | 含义 |
|---|---|
| `axis_no` | 轴号。J1~J6 通常为 0~5，虚拟轴 X/Y/Z/RX/RY/RZ 通常为 6~11 |
| `pos_val` | 目标值或相对增量 |
| `spd_pct` | 速度百分比 |
| `acc_pct` | 加速度百分比 |
| `dec_pct` | 减速度百分比 |
| `fuzzy_pos` | 位置模糊标志，1 通常表示相对/模糊 |
| `fuzzy_spd` | 速度模糊标志 |
| `fuzzy_acc` | 加速度模糊标志 |
| `fuzzy_dec` | 减速度模糊标志 |
| `stop_cmd` | 停止标志 |

#### Func108 位姿移动

| 参数 | 含义 |
|---|---|
| `target_x/y/z` | 目标坐标 |
| `target_rx/ry/rz` | 目标姿态 |
| `spd_pct` | 速度百分比 |
| `acc_pct` | 加速度百分比 |
| `dec_pct` | 减速度百分比 |
| `move_type` | 运动类型，现场约定为 0/1 等 |
| `stop_cmd` | 停止标志 |
| `fuzzy_pos/spd/acc/dec` | 模糊参数标志 |

#### Func109/110 延时

| 参数 | 含义 |
|---|---|
| `delay_sec` | 延时时间，单位秒 |

#### Func120 IO

| 参数 | 含义 |
|---|---|
| `io_no` | IO 编号 |
| `io_action` | 动作，通常 0=关闭，1=打开 |

### 修改建议

- 模板名 `query_key` 不要重复。
- 流程中引用的模板不要随意删除，否则流程步骤会找不到动作。
- 新增危险动作时应设置较高 `safety_level`。
- 建议通过工程师页面新增、编辑、导入导出模板，减少 JSON 手写错误。

## 四、`position_registry.json`

### 作用

结构化位置库。用于保存 `home`、位置A、休息姿态、工装点位等坐标。

主要加载代码：`robot_modbus_lite/position_registry.py`

### 顶层结构

```json
{
  "version": "1.1",
  "updated_at": "2026-05-27T20:36:02.003917",
  "positions": []
}
```

### 位置字段

| 字段 | 含义 |
|---|---|
| `name` | 位置名称，例如 `home`、`休息姿态`、`位置A` |
| `pose` | 6 维位姿 `[x,y,z,rx,ry,rz]` |
| `spd` | 默认移动速度百分比 |
| `move_type` | 默认运动类型 |
| `locked` | 是否锁定。锁定后不能普通修改/删除 |
| `is_system` | 是否系统位置。系统位置通常更严格保护 |
| `created_by` | 创建者，如 `operator`、`engineer` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 示例

```json
{
  "name": "home",
  "pose": [1475.0, 0.0, 1545.0, 0.0, 0.0, 0.0],
  "spd": 50,
  "move_type": 0,
  "locked": false,
  "is_system": false
}
```

### 修改建议

- `pose` 必须是 6 个数字。
- `locked=true` 的位置现场不要直接改，除非明确知道影响。
- 用户说“移动到 home”或“休息了”这类指令可能会查这里的位置。
- 如果同名位置在 `query_table.json` 也存在，要确认两边含义一致，避免自然语言回答和执行动作不一致。

## 五、`flow_registry.json`

### 作用

结构化流程库。相比 `flows.json`，它保存更多信息：步骤结构、状态、是否确认、创建者、演练速度等。

主要加载代码：`robot_modbus_lite/flow_registry.py`

### 顶层结构

```json
{
  "version": "1.1",
  "updated_at": "...",
  "flows": []
}
```

### 流程字段

| 字段 | 含义 |
|---|---|
| `name` | 流程名称 |
| `description` | 流程说明 |
| `steps` | 步骤列表 |
| `step_delay_ms` | 步骤间默认延时 |
| `rehearsal_spd` | 演练速度 |
| `confirmed` | 是否已确认锁定 |
| `created_by` | 创建者 |
| `version` | 流程版本 |
| `state` | 流程状态，如 `idle`、`rehearsal`、`running` |
| `current_step` | 当前步骤索引 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 步骤字段

| 字段 | 含义 |
|---|---|
| `step_id` | 步骤编号 |
| `action` | 动作名称或内部动作标识 |
| `func_id` | Func 号。0 通常表示需要通过 `query_key` 或模板再次解析 |
| `params` | 步骤参数 |
| `position_name` | 关联位置名，可为空 |
| `spd_pct` | 该步骤速度 |
| `description` | 步骤说明 |

### 注意

如果步骤类似：

```json
"action": "flowdraft:xxx:01",
"func_id": 0,
"params": {"query_key": "flowdraft:xxx:01"}
```

说明这是流程草案保存后的内部模板引用。执行时必须能在模板表或服务中解析到该 `query_key`，否则会执行失败或只显示草案步骤。

## 六、`flows.json`

### 作用

旧版/兼容流程库。结构简单：流程名对应一串模板名。

主要加载代码：`robot_modbus_lite/flow_store.py`

### 字段说明

| 字段 | 含义 |
|---|---|
| `flows` | 流程列表 |
| `name` | 流程名 |
| `steps` | 步骤模板名列表，每个元素通常对应 `query_table.json` 的 `query_key` |
| `step_delay_ms` | 步骤间延时 |

### 示例

```json
{
  "name": "A到B",
  "steps": ["位置A", "位置B"],
  "step_delay_ms": 1000
}
```

### 修改建议

- 新系统优先用 `flow_registry.json`。
- 旧 Web/服务接口仍可能读取 `flows.json`。
- 不要让 `flows.json` 和 `flow_registry.json` 中同名流程内容长期不一致。

## 七、`nlp_standard_words.json`

### 作用

自然语言标准词表。用于：

- 同音字纠正
- ASR 误听纠正
- 四川话/口语变体归一化
- 拼音归一化
- 标准词分类

主要加载代码：`robot_modbus_lite/nlp_standard_words.py`、`robot_modbus_lite/nlp_normalization.py`

### 顶层字段

| 字段 | 含义 |
|---|---|
| `version` | 词表版本 |
| `description` | 词表说明 |
| `words` | 标准词列表 |

### 标准词字段

| 字段 | 含义 |
|---|---|
| `standard` | 标准词，例如“执行” |
| `pinyin` | 标准拼音，不带声调，例如 `zhixing` |
| `category` | 分类，如 `flow`、`position`、`motion`、`safety` |
| `homophones` | 同音/近音/误听词，如“直行”“运行吧” |
| `sichuan_variants` | 方言或现场口语，如“跑一哈” |
| `func_id` | 关联 Func 号，没有则为 `null` |

### 修改建议

- 现场 ASR 经常误识别的词，优先加到 `homophones`。
- 四川话、地方口语加到 `sichuan_variants`。
- `standard` 不要重复。
- `pinyin` 建议按普通话拼音填写，便于拼音归一化。
- 修改后建议用用户页文字输入或语音输入做回归测试，确认不会把闲聊误判成动作。

## 八、`voice_wake_words.json`

### 作用

配置唤醒词和唤醒词别名。系统只在句首识别这些词，用于进入生产控制/查询链路。

主要加载代码：`robot_modbus_lite/voice_wake_words.py`

### 字段说明

| 字段 | 含义 |
|---|---|
| `version` | 配置版本 |
| `description` | 说明 |
| `primary` | 主唤醒词，例如“小正” |
| `aliases` | 唤醒词别名，如“小郑”“校正”“小郭” |
| `session_grace_seconds` | 会话宽限时间。刚唤醒后一定时间内，后续话可不重复唤醒词 |

### 修改建议

- 如果现场经常把“小正”识别成“小镇”“小政”，加到 `aliases`。
- 不要加太普通的词，比如“你好”“系统”，否则容易误触发控制链路。
- `session_grace_seconds` 太长会增加误触发风险，太短会让用户每句都要叫唤醒词。

## 九、`flow_phrase_aliases.json`

### 作用

复杂流程口语动作白名单。DeepSeek 可以理解“点头”“小臂上下点头”这类口语，但真正展开为轴号和方向必须靠这里的白名单。

主要加载代码：`robot_modbus_lite/voice_nlp_adapter.py`

### 顶层字段

| 字段 | 含义 |
|---|---|
| `version` | 配置版本 |
| `description` | 说明 |
| `aliases` | 口语动作到实际动作序列的映射 |

### 动作字段

| 字段 | 含义 |
|---|---|
| `command` | 展示用命令名，如 `Ry正转` |
| `func_id` | 功能号，通常点动为 107 |
| `axis_no` | 轴号 |
| `direction` | 方向，`1` 正向，`-1` 反向 |

### 示例

```json
"点头": [
  {"command": "Ry正转", "func_id": 107, "axis_no": 10, "direction": 1},
  {"command": "Ry反转", "func_id": 107, "axis_no": 10, "direction": -1}
]
```

### 修改建议

- 这是安全敏感配置。不要把不确定的口语直接映射到真实动作。
- 新增口语动作后，必须用草案预览检查步骤是否符合预期。
- `axis_no` 和 `direction` 填错会导致机械手朝错误方向运动。

## 十、`dashboard_query_aliases.json`

### 作用

用户问状态、报警、通讯、安全范围、流程进度时，用这个配置把不同说法归类到七类看板。

主要加载代码：`robot_modbus_lite/dashboard_query_specs.py`

### 分类说明

| 分类 | 含义 | 示例问法 |
|---|---|---|
| `device_status` | 设备/下位机/报警状态 | “现在下位机状态是什么” |
| `action_feasibility` | 当前能否执行动作 | “现在能不能动” |
| `safety_boundary` | 安全边界、软限位、当前位置是否安全 | “当前位置安全吗” |
| `motion_limits` | 速度/加速度/减速度限制 | “速度有没有超限” |
| `process_preview` | 流程预演和流程进度 | “流程执行到哪了” |
| `process_adaptation` | 可达性、奇异、运动规划 | “这个位置能到吗” |
| `communication_faults` | 通讯/连接/EtherCAT 状态 | “通讯正常吗” |

### 修改建议

- 新增问法直接追加到对应数组。
- 不要把动作命令写到这里，例如“移动到位置A”不属于查询别名。
- 如果某个问法总是被 DeepSeek 闲聊接管，可以加到这里提高本地查询优先级。

## 十一、`assistant_knowledge_base.json`

### 作用

AI 助手本地知识库。用于回答：

- 你是谁
- 能做什么
- 怎么用
- 安全边界
- 模板/位置/流程/报警/TTS 说明

主要加载代码：`robot_modbus_lite/assistant_knowledge_base.py`

### 顶层字段

| 字段 | 含义 |
|---|---|
| `version` | 知识库版本 |
| `description` | 说明 |
| `entries` | 知识条目 |

### 条目字段

| 字段 | 含义 |
|---|---|
| `id` | 条目唯一 ID |
| `category` | 分类，如 `identity`、`usage`、`safety` |
| `keywords` | 命中关键词 |
| `content` | 回答依据文本 |
| `priority` | 优先级，通常 `high` 或 `normal` |
| `source` | 来源 |
| `answer_style` | 回答风格，如 `identity`、`usage`、`safety` |

### 修改建议

- 静态说明写这里，例如“系统支持哪些功能”。
- 不要把动态数据写死在这里，例如“当前有 22 个模板”，因为模板数量会变化。
- 安全边界类内容要明确：DeepSeek 不直接控制机械手，执行必须经过本地白名单、安全预检和人工确认。

## 十二、`atomic_state.json`

### 作用

原子自然语言记忆状态。用于保存用户页自然语言操作的当前速度、步长、确认模式等。

主要加载代码：`robot_modbus_lite/atomic_memory.py`

### 字段说明

| 字段 | 含义 |
|---|---|
| `current_speed` | 当前默认速度百分比 |
| `current_step_mm` | 当前默认直线步长，单位 mm |
| `current_step_deg` | 当前默认角度步长，单位度 |
| `current_acc` | 当前默认加速度百分比 |
| `current_dec` | 当前默认减速度百分比 |
| `confirm_mode` | 确认模式，如 `beginner` |
| `positions` | 旧式位置记忆，当前优先使用 `position_registry.json` |
| `position_stack` | 位置历史栈 |
| `last_direction` | 上一次方向 |
| `last_step` | 上一次步长 |

### 修改建议

- 一般不手动修改。
- 如果自然语言默认速度异常，可以检查 `current_speed/current_acc/current_dec`。
- `confirm_mode` 不建议随意设为专家模式，避免减少确认导致风险。

## 十三、`memory_params.json`

### 作用

跨会话记忆参数。比 `atomic_state.json` 更偏统计和偏好，例如不同动作类型的速度偏好。

主要加载代码：`robot_modbus_lite/memory_params.py`

### 字段说明

| 字段 | 含义 |
|---|---|
| `version` | 文件版本 |
| `updated_at` | 更新时间 |
| `memory` | 记忆参数主体 |
| `last_motion_speed_pct` | 最近运动速度偏好 |
| `last_jog_speed_pct` | 最近点动速度偏好 |
| `last_home_speed_pct` | 回零/回 home 速度偏好 |
| `last_calib_speed_pct` | 标定速度偏好 |
| `preferred_rehearsal_spd` | 流程演练速度偏好 |
| `total_commands` | 累计命令数 |
| `last_command_time` | 最近命令时间 |

### 修改建议

- 一般由系统自动更新。
- 如果速度偏好被错误学习，可以手动改回 50、30、20 等保守值。
- `total_commands` 只用于统计，不影响执行。

## 十四、`avoidance_rules.json`

### 作用

避障和安全中间点配置。用于在运动规划或建议中提供安全中间点。

主要加载代码：`robot_modbus_lite/avoidance_config.py`

### 字段说明

| 字段 | 含义 |
|---|---|
| `mode` | 避障模式，当前示例为 `off` |
| `rx_threshold` | RX 姿态变化阈值 |
| `ry_threshold` | RY 姿态变化阈值 |
| `rz_threshold` | RZ 姿态变化阈值 |
| `low_z_threshold` | 低 Z 高度阈值 |
| `xy_move_threshold` | XY 平面移动距离阈值 |
| `safe_points` | 安全中间点字典 |
| `rules` | 避障规则列表 |

### 安全点字段

| 字段 | 含义 |
|---|---|
| `name` | 安全点名称 |
| `x/y/z/rx/ry/rz` | 安全点位姿 |
| `speed_percent` | 经过安全点的速度 |
| `acc_percent` | 加速度 |
| `description` | 说明 |

### 修改建议

- `mode="off"` 表示不启用自动避障。
- 启用避障前必须由工程师验证安全点不会碰撞。
- 安全点速度建议保守设置，例如 20%。

## 十五、配置修改后的验证步骤

1. 修改前备份对应 JSON 文件。
2. 使用支持 UTF-8 的编辑器修改，保持合法 JSON 格式。
3. 重启 GUI。
4. 在工程师页或用户页查看是否加载成功。
5. 对配置影响的功能做小范围测试：
   - 改 `system_config.json`：测试连接、状态刷新、安全预检。
   - 改 `query_table.json`：测试模板是否可查询、可执行。
   - 改 `position_registry.json`：测试“查询位置”和“移动到位置”。
   - 改 `flow_registry.json/flows.json`：测试流程预览，不要直接上机执行。
   - 改 NLP/唤醒词配置：用文字输入先测试，再测试语音。
6. 现场真实机械手执行前，先确认急停、暂停、报警状态正常。

## 十六、常见问题

### 1. 修改配置后没有生效

优先重启 GUI。打包后的 EXE 会读取 `_internal/data` 或运行目录解析到的数据文件，确认改的是实际运行使用的那一份。

### 2. 报 `JSONDecodeError`

说明 JSON 格式错误。常见原因：

- 少逗号
- 多逗号
- 中文引号
- 注释写进 JSON
- 数组或对象括号没闭合

### 3. 语音总是识别不到唤醒词

检查 `voice_wake_words.json` 的 `aliases`，把 ASR 日志里实际识别出来的词加入别名。

### 4. DeepSeek 回答不知道现场功能

把静态说明加入 `assistant_knowledge_base.json`，把动态模板和位置则维护在 `query_table.json`、`position_registry.json`。

### 5. 复杂口语流程只生成草案、不执行

这是正常安全策略。复杂流程要先生成草案，用户查看步骤后说“确认保存”或“保存并执行”。

### 6. “点头”“打招呼”没有按预期展开

检查 `flow_phrase_aliases.json` 是否配置了对应口语动作，以及轴号、方向、次数是否被流程草案正确解析。

### 7. 六轴接受确认超时

先检查 `system_config.json`：

```json
"six_accept_timeout_sec": 1.0
```

可临时调到 `2.0` 或 `3.0`。如果仍然报 `IEEE(312)=0`，说明下位机可能没有按当前 V5.0 协议写接受确认寄存器。
