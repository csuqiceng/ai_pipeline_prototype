# 第一版实施冻结稿 V1

## 1. 适用范围

本冻结稿仅用于当前 Qt 第一版实施，不等同于最终标准协议。

当前原则：

- 先复用已打通的通信链路
- 先完成第一版页面与模板管理
- 不在本阶段重构底层寄存器协议

---

## 2. 第一版功能范围

### 2.1 前台运行页

- 固定指令卡片
- 参数型指令执行
- 固定函数型指令执行
- 执行摘要
- 机械手状态
- 最近执行记录
- 系统操作按钮
- 连接检测与反馈读取

### 2.2 后台管理页

- 模板列表
- 模板选中回填
- 新增 / 保存 / 删除 / 另存为
- JSON 预览
- JSON 持久化

---

## 3. 第一版模板分类

当前仅支持两类模板：

### 3.1 参数型指令

示例：

- `位置A`
- `位置B`
- `归零`

特点：

- 需要一组 7 参数
- 执行后允许更新机械手位置显示

### 3.2 固定函数型无参数指令

示例：

- `机床1开门`
- `固定函数5001`

特点：

- 不依赖完整位置参数语义
- 前台和后台界面上按固定函数型处理
- 参数输入框在后台页禁用

---

## 4. 当前通信实现冻结

### 4.1 当前实现方式

当前并未切换到最终文档中的 `VR[0]~VR[25]` 固定字段协议。

当前实际实现冻结为：

- `trigger_vr = 500`
- `payload_start_vr = 501`
- `status_vr_start = 600`
- payload 为模板中的 `registers[7]`

执行顺序：

1. 先写 payload 区
2. 再写 trigger 区
3. 再读反馈区

### 4.2 当前反馈读取

当前默认读取：

- `start_vr = 600`
- `count = 5`

第一版界面中将其解释为：

- 第 1 项：`RESULT`
- 第 2 项：`STATUS`
- 第 3~5 项：`CUR_X / CUR_Y / CUR_Z`

说明：

- 这是第一版实现解释，不代表最终标准已经全部落地

## 6. 第一版后台模板字段冻结

当前后台页统一维护以下字段：

- `query_key`
- `function_id`
- `function_name`
- `template_type`
- `keywords`
- `description`
- `pos_id`
- `device_id`
- `io_grip`
- `io_door`
- `ext_p1`
- `ext_p2`
- `registers`
  - `x`
  - `y`
  - `z`
  - `rx`
  - `ry`
  - `rz`
  - `speed`
- `acc_percent`
- `safety_level`

说明：

- 当前后台页 JSON 预览已经按最终标准 JSON 结构生成
- 但实际发送链路仍默认走第一版简化协议
- Qt 运行页已提供：
  - `真实控制器`
  - `本地Mock控制器`
  两种控制器模式切换
- Qt 运行页已提供：
  - `当前简化协议`
  - `最终标准协议`
  两种发送协议切换

## 7. 第一版基础校验冻结

当前仅做基础前置校验：

- 指令码必须大于 0
- 安全等级必须在 1~5
- 参数型指令：
  - 速度百分比必须在 0~100
  - 加速度百分比必须在 0~100
- 最终标准协议模式下：
  - `MOVE_ABS` 会校验坐标范围
  - `X: -300~300`
  - `Y: -300~300`
  - `Z: 0~300`

当前不做：

- 双车床联锁
- 视觉安全联动

---

## 8. 与最终标准的关系

当前冻结稿与最终标准关系如下：

- 页面和数据组织按最终标准方向设计
- 底层通信仍沿用当前已打通的简化链路
- 待第一版页面收口后，再单独切换到最终标准寄存器协议

### 8.1 当前已补充的最终标准兼容层

为后续切换到最终标准协议，当前代码中已补充但尚未替换现有链路的能力：

- 可将模板转换为最终标准 JSON：
  - `MOVE_ABS`
  - `MOVE_REL`
  - `HOME`
  - `GRIP_SET`
  - `DOOR_CTRL`
  - `WAIT_MS`
  - `FIXED_FUNC`
- 可将模板转换为 `VR[0]~VR[15]` 的标准指令区值
- 可将 `VR[16]~VR[25]` 的 10 个反馈值解析为：
  - `RESULT`
  - `STATUS`
  - `CUR_X / CUR_Y / CUR_Z`
  - `CUR_RX / CUR_RY / CUR_RZ`
  - `ALM_CODE`
  - `IO_STAT`

说明：

- 当前这层兼容用于平滑过渡到最终标准协议
- 现有 Qt 页面默认发送链路仍是简化协议
- 真正切换以 `阶段7：最终标准协议适配` 为准

---

## 9. 结论

本冻结稿用于保证：

- 第一版 Qt 页面继续推进
- 不破坏现有通信基线
- 不在当前阶段混入最终协议重构

后续若进入“最终寄存器协议切换”，应新增单独阶段，不直接覆盖本冻结稿。
