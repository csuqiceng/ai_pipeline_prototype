六轴机械手 — 上位机函数状态标志位使用指南
版本: V1.0
日期: 2026-05-14
适用: 上位机程序开发

==========================================================
一、核心概念：函数状态标志位
==========================================================

控制器通过 LONG(34) 向上位机反馈每个函数的执行状态。
上位机必须根据这些标志位决定"何时可以发下一条指令"。

1.1 每个函数占2个bit，4种状态

  00 = 空闲(IDLE)    函数未执行，可以触发
  01 = 执行中(EXEC)  函数正在运行，不能重复触发
  10 = 完成(DONE)    函数执行成功，可以触发下一个函数
  11 = 错误(ERR)     函数执行出错，需查LONG(38)报警码并处理

1.2 函数状态位在LONG(34)中的位置

  函数      位号        MASK掩码    EXEC值    DONE值    ERR值
  ────────  ──────────  ──────────  ────────  ────────  ────────
  Func104   34.00,01    0x00000003  0x01      0x02      0x03
  Func106   34.02,03    0x0000000C  0x04      0x08      0x0C
  Func107   34.04,05    0x00000030  0x10      0x20      0x30
  Func108   34.06,07    0x000000C0  0x40      0x80      0xC0
  Func109   34.08,09    0x00000300  0x100     0x200     0x300
  Func110   34.10,11    0x00000C00  0x400     0x800     0xC00
  Func111   34.12,13    0x00003000  0x1000    0x2000    0x3000    预留（当前上位机不实现）
  Func11    34.14,15    0x0000C000  0x4000    0x8000    0xC000
  Func120   34.18,19    0x000C0000  0x40000   0x80000   0xC0000

  说明：Func111 为协议预留状态位，当前 Qt 上位机不提供命令构建、发送和 mock 执行逻辑。

1.3 全局状态位（同样在LONG(34)中）

  位号    名称       掩码         含义
  ──────  ────────   ──────────   ──────────────────────
  34.24   M_ALARM    0x01000000   报警标志（有报警未处理）
  34.25   M_ESTOP    0x02000000   急停标志（急停激活中）
  34.26   M_PAUSE    0x04000000   暂停标志（暂停中）
  34.27   M_CANCEL   0x08000000   取消标志（已取消）
  34.28   M_READY    0x10000000   系统就绪（可以执行指令）

1.4 报警码 LONG(38)

  位号    掩码    含义
  ──────  ──────  ──────────────
  38.00   0x01    半径超限
  38.01   0x02    高度超限
  38.02   0x04    指令忙（运动函数执行中重复触发）
  38.03   0x08    速度超限
  38.04   0x10    加速度超限
  38.05   0x20    减速度超限
  38.06   0x40    EtherCAT通讯故障
  38.07   0x80    驱动器报警
  38.08   0x100   函数号非法
  38.09   0x200   参数非法

==========================================================
二、上位机如何读取函数状态
==========================================================

2.1 读取方法

  上位机读取 LONG(34) 的完整值（32位整数），然后用掩码提取对应函数的状态。

  C语言示例（使用ZMotion PC函数库）：
    int32_t status34;
    ZAux_Modbus_Get4x_Long(handle, 34, 1, &status34);

  Python示例（使用pymodbus）：
    result = client.read_holding_registers(34, 2, slave=1)
    status34 = struct.unpack('>i', struct.pack('>HH', result.registers[0], result.registers[1]))[0]

2.2 提取指定函数的状态

  步骤：
  (1) 用MASK掩码与LONG(34)做AND运算，提取对应2位
  (2) 判断结果：0=空闲，EXEC=执行中，DONE=完成，ERR=错误

  示例：判断Func108的状态
    func_state = status34 & 0xC0    // 0xC0是Func108的MASK

    if func_state == 0x00:          // 空闲
        可以触发Func108
    elif func_state == 0x40:        // 执行中(EXEC)
        Func108正在运行，等待
    elif func_state == 0x80:        // 完成(DONE)
        Func108执行成功
    elif func_state == 0xC0:        // 错误(ERR)
        Func108执行出错

2.3 检查全局状态

  示例：检查是否可以发运动指令
    has_alarm = (status34 & 0x01000000) != 0   // 34.24 M_ALARM
    is_estop  = (status34 & 0x02000000) != 0   // 34.25 M_ESTOP
    is_ready  = (status34 & 0x10000000) != 0   // 34.28 M_READY

    if has_alarm or is_estop or not is_ready:
        不能发运动指令，需先处理异常

三、上位机发送指令的完整流程（重点！）
==========================================================

3.1 运动函数（106/107/108/109/11）发送流程

  ┌─────────────────────────────────────────────────────────┐
  │  步骤1：检查前置条件                                      │
  │    读LONG(34)                                            │
  │    ① 对应函数位 = 00(空闲) 或 10(完成)                    │
  │    ② 34.24 = 0（无报警）                                  │
  │    ③ 34.25 = 0（未急停）                                  │
  │    ④ 34.28 = 1（系统就绪）                                │
  │    全部满足 → 继续；任一不满足 → 等待或处理异常              │
  ├─────────────────────────────────────────────────────────┤
  │  步骤2：写入函数号和参数                                    │
  │    写 IEEE(0) = 函数号                                    │
  │    写 IEEE(2)~IEEE(30) = 参数                             │
  ├─────────────────────────────────────────────────────────┤
  │  步骤3：读回显校验                                         │
  │    读 IEEE(280~312)                                       │
  │    确认写入值与回显值一致                                   │
  │    不一致 → 重试步骤2                                      │
  ├─────────────────────────────────────────────────────────┤
  │  步骤4：触发执行                                          │
  │    写 IEEE(32) = 1                                       │
  ├─────────────────────────────────────────────────────────┤
  │  步骤5：等待完成                                          │
  │    循环读LONG(34)，间隔50ms                                │
  │    函数位 = 01(EXEC) → 继续等待                            │
  │    函数位 = 10(DONE)  → 执行成功，可发下一条                 │
  │    函数位 = 11(ERR)   → 读LONG(38)查报警码，处理后重试       │
  └─────────────────────────────────────────────────────────┘

3.2 急停函数（104）发送流程

  ┌─────────────────────────────────────────────────────────┐
  │  步骤1：写入函数号和参数                                    │
  │    写 IEEE(0) = 104                                      │
  │    写 IEEE(2) = 急停控制值                                │
  │    写 IEEE(4) = 暂停控制值                                │
  │    写 IEEE(6) = 结束控制值                                │
  │    写 IEEE(8) = 报警复位值                                │
  ├─────────────────────────────────────────────────────────┤
  │  步骤2：读回显校验                                         │
  │    读 IEEE(280~288)，确认参数正确写入                       │
  ├─────────────────────────────────────────────────────────┤
  │  步骤3：触发执行                                          │
  │    写 IEEE(32) = 1                                       │
  ├─────────────────────────────────────────────────────────┤
  │  步骤4：确认结果                                          │
  │    急停：读34.25=1确认                                     │
  │    复位：读34.28=1, 34.24=0确认                            │
  └─────────────────────────────────────────────────────────┘

  ⚠️ 注意：Func104不检查状态标志位，任何情况下都可以触发！
  急停本身就是用来解决异常的，不可能等状态正常再急停。

3.3 并行函数（110/120）发送流程

  与运动函数流程相同，但注意：
  - Func110(T1延时)和Func120(IO)可以与运动函数同时执行
  - Func110和Func120之间是串行的，不能同时运行
  - 发送前同样要检查对应函数位是否空闲

==========================================================
四、连续流程编程规范（重点！）
==========================================================

4.1 核心原则：等完成再发下一条

  上位机连续流程工作时，必须遵循：
  发指令 → 等DONE → 发下一条指令

  绝对不能：发指令 → 不等完成 → 立即发下一条

  原因：
  - 控制器同一时刻只能执行一个运动函数
  - 运动函数执行期间，IEEE(0-32)被占用
  - 不等完成就发新指令，新指令可能丢失或覆盖旧参数

4.2 标准连续流程示例

  场景：运动到A点 → 延时0.5秒 → 闭合夹爪 → 运动到B点

  伪代码：
    // 第1步：运动到A点
    sendFunc108(target_A)           // 发送Func108
    waitFuncDone(0xC0)             // 等待Func108完成（MASK=0xC0）

    // 第2步：T1延时0.5秒（与运动函数独立，但上一步已完成所以串行）
    sendFunc110(0.5)               // 发送Func110
    waitFuncDone(0xC00)            // 等待Func110完成（MASK=0xC00）

    // 第3步：闭合夹爪
    sendFunc120(io_no=0, action=1) // 发送Func120
    waitFuncDone(0xC0000)          // 等待Func120完成（MASK=0xC0000）

    // 第4步：运动到B点
    sendFunc108(target_B)           // 发送Func108
    waitFuncDone(0xC0)             // 等待Func108完成

4.3 并行流程示例

  场景：运动到A点的同时开始T1延时

  伪代码：
    // 同时发送运动和延时
    sendFunc108(target_A)           // 发送Func108
    sendFunc110(0.5)               // 发送Func110（并行）

    // 分别等待完成
    waitFuncDone(0xC0)             // 等待Func108完成
    waitFuncDone(0xC00)            // 等待Func110完成

4.4 waitFuncDone 通用等待函数

  伪代码：
    def waitFuncDone(mask, timeout_ms=30000):
        start = current_time()
        while (current_time() - start) < timeout_ms:
            status34 = read_LONG(34)
            func_bits = status34 & mask

            if func_bits == DONE值:
                return SUCCESS
            elif func_bits == ERR值:
                alarm = read_LONG(38)
                return ERROR(alarm)
            // EXEC或IDLE，继续等待

        return TIMEOUT

  各函数的DONE值和ERR值参见1.2节表格。

==========================================================
五、异常处理流程
==========================================================

5.1 函数执行出错（函数位=11 ERR）

  处理步骤：
  (1) 读LONG(38)，确定报警码
  (2) 根据报警码处理：
      - 速度超限(38.03) → 降低速度百分比重试
      - 空间超限(38.00/01) → 修改目标位置重试
      - 驱动器报警(38.07) → 需人工检查硬件
      - 指令忙(38.02) → 等待当前函数完成再重试
  (3) 发送Func104报警复位：IEEE(0)=104, IEEE(8)=1, IEEE(32)=1
  (4) 等待34.28=1(就绪), 34.24=0(无报警)
  (5) 重新发送出错的函数

5.2 急停处理

  处理步骤：
  (1) 发送Func104急停：IEEE(0)=104, IEEE(2)=1, IEEE(32)=1
  (2) 等待34.25=1(急停确认)
  (3) 确认安全后，发送Func104解除急停：IEEE(0)=104, IEEE(2)=2, IEEE(32)=1
  (4) 发送Func104报警复位：IEEE(0)=104, IEEE(8)=1, IEEE(32)=1
  (5) 等待34.28=1(就绪), 34.24=0(无报警)
  (6) 重新发送被中断的运动指令

5.3 通讯超时

  触发后等待EXEC状态超时（建议500ms）：
  → 检查MODBUS连接
  → 重新发送指令

  等待DONE状态超时（建议30秒）：
  → 可能运动卡住，发Func104急停
  → 检查LONG(38)报警码

==========================================================
六、常见错误与注意事项
==========================================================

6.1 不要在EXEC状态时发运动指令

  错误：Func108执行中，又发Func108或Func106
  后果：新指令可能丢失，或参数被覆盖

  正确：等Func108完成(DONE)后再发下一条

6.2 Func104必须验证回显后再触发

  急停很重要，但正因为重要，更要确保参数正确写入。
  如果回显不匹配就触发，可能导致：
  - 本来要复位，结果触发了急停
  - 本来要急停，参数写错了没生效

6.3 完成标志不会自动清除

  函数执行完成后，函数位=10(DONE)会一直保持。
  下次触发同一函数时，控制器会自动覆盖为EXEC。
  但上位机在检查"是否可以触发"时，DONE等同于空闲。

6.4 LONG(34)的读取频率

  建议50ms读取一次，与控制器扫描周期匹配。
  太快(<10ms)：浪费通讯带宽
  太慢(>200ms)：响应迟钝

6.5 MODBUS_IEEE地址对齐

  MODBUS_IEEE是32位浮点数，每个占2个REG地址。
  只能使用偶数编号：IEEE(0), IEEE(2), IEEE(4)...
  奇数编号会被相邻偶数覆盖！
  上位机写REG时注意：IEEE(N)对应REG[N*2]和REG[N*2+1]
