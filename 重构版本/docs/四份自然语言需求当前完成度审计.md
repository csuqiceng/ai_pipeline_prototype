## 6. LangChain / LangGraph 当前结论

结论：**本项目不需要把完整 LangChain Agent 体系作为最终目标。**

当前正确终点是：

```text
LangGraph 状态机
+ DeepSeekToolDecider 窄 JSON 工具决策
+ Pydantic tool schema
+ LocalToolRegistry / ToolResult
+ SessionState
+ ExecutionGate / Qt 执行层
```

已落地证据：

- `robot_modbus_lite/agent_runtime/langchain_runner.py` 中有 `LangChainToolRunner` 和 `build_default_langgraph_app()`。
- `robot_modbus_lite/agent_runtime/runtime_factory.py` 会在 LangGraph 可用时创建 `LangChainToolRunner`，不可用时降级到 `LocalToolCallingRunner`。
- `robot_modbus_lite/agent_runtime/deepseek_tool_decider.py` 保留窄 JSON tool decision。
- `robot_modbus_lite/agent_runtime/tool_schemas.py` 用 Pydantic 校验工具输入/输出。
- `robot_modbus_lite/agent_runtime/local_tool_registry.py` 是事实执行边界。

不作为目标的内容：

- `AgentExecutor`
- ReAct
- 自由规划式 LangChain Agent
- LangChain memory 主控
- 让 LLM 直接决定执行事实或安全事实

当前状态不是“没接 LangChain”，而是只采用了适合工业控制的 LangGraph 协议层和状态机能力。后续应该继续做深 LangGraph 的多轮循环和 Pydantic schema，而不是迁移到 AgentExecutor。
