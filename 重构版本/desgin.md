# 机械手控制系统页面重设计总方案

版本：V1.0  
日期：2026-05-17  
范围：现有 PySide6 桌面软件页面重设计，新增面向操作者的“使用页面”，保留并整理现有“工程师页面”。  
依据：

- `robot_modbus_lite/qt_gui.py`
- `robot_modbus_lite/gui_ui_mixin.py`
- `robot_modbus_lite/voice_nlp_adapter.py`
- `docs/机械手自然语言交互系统_项目需求与技术路线建议书_V2.1.md`
- `web/agent_chat_demo/`

## 1. 总体定位

当前软件已经具备控制器连接、固定指令、流程执行、自然语言解析、语音识别、模板维护、系统参数、安全中间点、日志等能力，但现有页面是典型“工程师工作台”：控件密度高、参数暴露多、执行逻辑偏调试和维护。

后续需要增加的不是简单的“语音按钮”或“聊天框”，而是一套独立的“操作者使用页面”。它的目标是让产线操作者用自然语言完成查询、预检、确认、执行和报警处理，同时保留必要的常驻状态显示，避免语言交互天然存在的“说了才有、不说没有”的信息缺口。

新的产品结构采用双页面体系：

| 页面 | 面向角色 | 核心目标 | 操作方式 | 信息密度 |
| --- | --- | --- | --- | --- |
| 使用页面 | 产线操作者 | 语言交互、状态确认、安全执行、报警处理 | 语音/文本为主，按钮为辅 | 低到中，只显示当前任务需要的信息 |
| 工程师页面 | 调试、集成、维护人员 | 连接调试、模板维护、参数配置、流程维护、日志排障 | 鼠标键盘为主，语音为辅 | 高，允许完整参数和表格 |

设计原则：

1. 使用页面是默认生产入口，工程师页面是维护入口。
2. 所有安全关键状态必须常驻显示，不依赖操作者主动询问。
3. 每一次自然语言输入都要快速给出回执，不允许界面沉默。
4. 所有执行动作必须经过状态读取、预检、确认、执行反馈四步。
5. 工程师页面不删除现有能力，但要重新归类、降低混乱感。
6. 用户页面和工程师页面共用同一套状态、日志、指令、流程和安全数据。

## 2. 应用级信息架构

建议保留一个主程序，内部按角色切换页面，而不是拆成两个软件。

```text
应用启动
  |
  +-- 使用页面：操作者日常入口
  |     |
  |     +-- 智能对话
  |     +-- 安全预检
  |     +-- 执行监控
  |     +-- 报警处理
  |     +-- 完整状态
  |
  +-- 工程师页面：维护调试入口
        |
        +-- 运行调试
        +-- 指令模板
        +-- 流程管理
        +-- 安全参数
        +-- 日志诊断
        +-- 授权与系统
```

入口建议：

- 首次启动显示角色选择：`进入使用页面`、`进入工程师页面`。
- 可在设置中选择默认入口，生产环境默认进入使用页面。
- 工程师页面入口需要权限控制，至少要二次确认，后续可接授权系统。
- 页面切换保留在顶部菜单或右上角，不放在操作者主操作区，避免误触。

## 3. 现有工程师页面梳理

现有主窗口结构来自 `GuiUiMixin._build_ui()`：

- 左侧导航：`运行`、`后台`、`日志`
- 中间内容：`QStackedWidget`
- 右侧系统面板：`报警复位`、`暂停`、`继续`、`急停`、系统状态灯
- 底部状态栏：系统就绪、数据源、授权状态

### 3.1 运行页现状

运行页包括：

| 区域 | 当前功能 | 设计评价 |
| --- | --- | --- |
| 连接与反馈 | 控制器地址、真实/模拟控制器、协议、连接检测、反馈读取 | 工程师需要，操作者不应频繁看到 |
| 单次执行 | 固定指令卡片、筛选、函数类型过滤 | 工程师调试需要，生产中应被计划卡/快捷命令替代 |
| 流程执行 | 流程选择、步骤树、开始、单步、停止、重置 | 工程师和操作者都需要，但展示方式不同 |
| 自然语言执行 | 文本输入、在线 AI 解析、麦克风、解析结果、执行 | 是未来使用页核心，但现状偏调试 |
| 机械手状态 | X/Y/Z/RX/RY/RZ、速度、夹爪、伺服、实时状态、回显 | 应抽象为常驻状态栏和完整状态面板 |
| 执行摘要 | 模式、忙闲、结果、报警、IO、任务 ID | 应进入使用页右侧状态/日志区域 |
| 最近执行记录 | 任务、指令码、名称、类型、结果 | 使用页保留简化时间线，工程师页保留完整表格 |

### 3.2 后台页现状

后台页包括：

| 区域 | 当前功能 | 设计评价 |
| --- | --- | --- |
| 功能说明 | Func104/106/107/108 等说明 | 可以保留为工程师帮助区 |
| 当前选中模板 | 模板名称、指令码、指令类型、参数说明 | 保留 |
| 后台操作 | 新增、保存、另存为、删除、导入、导出 | 保留，但需要危险操作确认 |
| 指令模板列表 | 显示名称、函数号 | 保留，增加搜索和分类 |
| 模板编辑 | query_key、func_id、关键词、安全等级、坐标、速度、插补点等 | 保留，建议按函数类型分组 |
| JSON 预览 | 当前模板结构化 JSON | 保留 |
| 系统参数 | 运动范围、安全半径、高度、速度、加速度、超时 | 保留，加入修改影响提示 |
| 安全中间点 | 规避模式、阈值、中间点坐标 | 保留 |
| 流程管理 | 已有流程、流程步骤、可选模板 | 保留，可独立成一级页 |

### 3.3 日志页现状

日志页包括日志说明、日志摘要、刷新、导出、清空和操作日志表格。

重设计后：

- 使用页面只展示最近关键事件，例如“收到指令、预检通过、等待确认、执行完成、报警”。
- 工程师页面保留完整日志表格、导出、过滤、按 session 查看。
- 清空日志必须放到工程师页并加确认。

## 4. 新增使用页面总览

使用页面是生产主入口，核心不是“控制面板”，而是“语言交互的脸”。页面应让操作者一直知道三件事：

1. 设备现在是否安全。
2. 系统听到了什么、理解成什么。
3. 下一步是等待、确认、执行、完成，还是报警处理。

推荐桌面布局：

```text
+--------------------------------------------------------------------------------+
| 常驻状态栏：设备状态 | 急停 | 暂停 | 报警 | 通讯 | 当前执行 | J1-J6 | R/Z       |
+--------------+------------------------------------------------+----------------+
| 场景导航      | 主场景区域                                      | 状态/计划侧栏   |
|              |                                                |                |
| 智能对话      | 对话消息                                        | 待确认计划       |
| 安全预检      | 当前任务卡                                      | 七类看板摘要     |
| 执行监控      | 预检/执行进度                                  | 风险/报警详情    |
| 报警处理      | 安全确认按钮                                    | 最近事件         |
| 完整状态      |                                                |                |
+--------------+------------------------------------------------+----------------+
| 语音/文本输入区：麦克风 | 输入框 | 发送 | 急停 | 暂停 | 继续 | 取消            |
+--------------------------------------------------------------------------------+
```

响应式策略：

- 1380x860 及以上：三列布局，左导航、中对话、右状态。
- 1024 到 1379：隐藏左导航为顶部标签，保留右侧状态栏。
- 小窗口模式：只显示常驻状态栏、当前对话、紧急按钮，完整看板折叠。

## 5. 使用页面模块设计

### 5.1 常驻状态栏

常驻状态栏必须永远可见，任何场景都不能遮挡。它替代传统 HMI 中“看一眼”的状态感知。

显示字段：

| 字段 | 内容 | 状态颜色 | 数据来源 |
| --- | --- | --- | --- |
| 总体状态 | 就绪、运行、预检、等待确认、暂停、报警、离线 | 绿、蓝、黄、红、灰 | 综合状态 |
| 急停 | 开/关 | 关为绿，开为红 | `LONG(34)` bit |
| 暂停 | 开/关 | 关为绿，开为黄 | `LONG(34)` bit |
| 报警 | 无/有+报警码 | 无为绿，有为红 | `LONG(38)` |
| 通讯 | 正常/异常 | 绿/红 | 控制器连接、EtherCAT |
| 当前执行 | 空闲/Func号/流程步骤 | 蓝/灰 | 回显、执行状态 |
| 轴位 | J1 到 J6 当前值 | 默认文本，超限红 | DPOS/MPOS |
| 空间位置 | R、Z | 默认文本，越界红 | 安全看板 |

刷新规则：

- 核心状态 50ms 轮询。
- 非核心诊断 100ms 到 500ms。
- 状态栏显示使用节流刷新，避免 UI 抖动，建议 100ms 更新一次。
- 关键状态变化必须进入主动播报队列。

### 5.2 智能对话区

对话区是使用页面主区域，不显示工程师式 JSON。它展示语音识别文本、系统回执、预检结论、确认请求和执行结果。

消息类型：

| 类型 | 显示内容 | 示例 |
| --- | --- | --- |
| 用户输入 | 语音识别或文本输入内容 | “把机械手移动到位置D，速度慢一点” |
| 回执消息 | 系统已收到，正在处理 | “收到，正在读取当前状态” |
| 状态快照 | 当前安全状态摘要 | “设备空闲，无报警，通讯正常” |
| 计划消息 | 系统理解后的动作计划 | “计划执行：移动到位置D，速度40%” |
| 预检消息 | 检查项、通过/风险、建议 | “限位通过，速度通过，空间范围通过” |
| 确认消息 | 需要操作者确认的按钮 | “确认执行 / 取消 / 解释风险” |
| 执行消息 | 执行中、完成、失败 | “已下发，等待控制器响应” |
| 报警消息 | 报警码、原因、处置按钮 | “J2速度超限，已暂停执行” |

硬性规则：

- 用户输入后立即追加“收到/正在处理”的回执。
- 复杂预检期间必须显示进度，不允许只显示转圈。
- 所有系统回答必须包含当前已知设备状态，特别是执行前和报警后。
- 自然语言解析失败时，不显示技术报错，改为“未匹配到可执行动作”，并提供可选建议。

### 5.3 任务计划卡

当系统从自然语言中解析出可执行动作后，不应直接执行，而是生成任务计划卡。

计划卡字段：

| 字段 | 说明 |
| --- | --- |
| 动作标题 | 例如“移动到位置D” |
| 动作类型 | 模板、流程、系统动作、查询 |
| 来源 | 规则解析、DeepSeek解析、快捷按钮 |
| 参数摘要 | 目标位置、速度、加速度、点位、IO 等 |
| 安全等级 | 普通、需确认、禁止执行 |
| 预检状态 | 未开始、进行中、通过、有风险、失败 |
| 执行动作 | 确认执行、取消、解释风险、采纳建议 |

交互规则：

- 普通查询不生成确认卡，直接回答。
- 运动和流程动作必须先生成计划卡。
- 系统动作中 `暂停`、`继续`、`报警复位`可以快速确认。
- `急停`必须走独立应急通道，不等待大模型语义解析。

### 5.4 安全预检场景

预检场景展示系统从“理解动作”到“允许执行”的过程。

预检步骤：

1. 状态检查：无急停、无报警、未暂停、控制器在线。
2. 通道检查：目标通道空闲，可接受新指令。
3. 参数检查：速度、加速度、减速度、坐标格式合法。
4. 安全边界：R、Z、关节软限位。
5. 运动规划：是否需要中间点、是否有奇异点风险。
6. 回显准备：准备走 V5.0 三道门发送流程。

视觉表达：

- 通过：绿色文字和“通过”标签。
- 进行中：蓝色进度条和当前步骤。
- 有风险：黄色，必须给出风险原因和建议。
- 禁止：红色，按钮只保留“取消”和“查看原因”。

### 5.5 执行监控场景

执行中页面重点不是参数编辑，而是“现在执行到哪了”。

显示内容：

- 当前动作或流程步骤。
- 当前值、目标值、剩余量。
- 执行进度，若为估算必须标注“估算”。
- 控制器回显、接受确认、当前函数号。
- 暂停、取消、急停按钮。
- 操作者追问时直接回答当前进度。

完成后：

- 显示最终位置。
- 显示执行耗时。
- 显示结果：完成、取消、失败、报警中断。
- 自动写入最近事件和完整日志。

### 5.6 报警处理场景

报警优先级最高。任意页面发生报警，都切换或覆盖到报警场景。

报警页必须显示：

- 报警级别。
- 报警码和人类可读说明。
- 发生时间。
- 当前设备状态。
- 系统已采取的动作，例如暂停、钳位、停止发送。
- 可操作按钮：确认报警、报警复位、完整状态、导出日志。

报警页禁止：

- 继续显示普通执行确认按钮。
- 让操作者在未确认报警原因时继续执行新动作。
- 只显示“异常”而不说明具体原因。

### 5.7 七类看板

七类看板是使用页面的“虚拟屏幕”，既服务对话回答，也服务右侧状态摘要。

| 看板 | 使用页呈现方式 | 典型问题 |
| --- | --- | --- |
| 设备基础状态 | 常驻状态栏 + 完整状态页 | “设备现在什么状态？” |
| 动作执行可行性 | 计划卡/预检结果 | “现在能不能执行？” |
| 全域安全边界 | 风险面板 | “当前位置安全吗？” |
| 运动极限参数 | 参数摘要/风险提示 | “速度有没有超限？” |
| 工艺流程预演进度 | 执行/预检进度 | “流程预演到哪了？” |
| 工艺适配评估 | 计划解释/建议 | “这个位置能不能到？” |
| 通讯与故障诊断 | 报警页/状态栏 | “通讯正常吗？” |

完整状态页不是工程师参数页。它只展示操作者需要理解的状态，参数修改仍放在工程师页面。

## 6. 工程师页面重设计

现有工程师页面可以继续用 PySide6/QSS 实现，但建议从“运行/后台/日志”三页扩展为更清楚的维护导航：

| 新导航 | 包含功能 | 来自当前页面 |
| --- | --- | --- |
| 运行调试 | 控制器连接、模拟/真实切换、固定指令执行、实时反馈 | 运行页 |
| 自然语言调试 | 文本/语音输入、规则/DeepSeek解析、解析 JSON、白名单校验 | 运行页自然语言区 |
| 指令模板 | 模板列表、模板编辑、导入、导出、JSON预览 | 后台页 |
| 流程管理 | 流程列表、步骤编排、单步测试 | 后台页 |
| 安全参数 | 运动范围、安全半径、高度、速度、加速度、控制器限位读取 | 后台页 |
| 安全中间点 | 规避规则、中间点管理 | 后台页 |
| 日志诊断 | session 日志、操作日志、语音耗时、导出、过滤 | 日志页 |
| 授权系统 | 授权状态、订阅能力、本地 key 状态 | 现有授权入口 |

工程师页视觉调整：

- 弱化当前高饱和青色背景，改为浅灰工作台背景。
- 左侧导航宽度可增至 128px，使用文字+状态，不只大按钮。
- 右侧系统操作面板保留，但急停按钮视觉权重最高。
- 表单按函数类型分组，减少所有字段一次性铺开的压力。
- 对危险写入操作加确认，例如保存安全参数、删除模板、清空日志。

两套页面不应各自维护一套状态，应共享同一层运行数据。

## 8. 关键交互流程

### 8.1 查询流程

```text
操作者问状态
  -> 立即回执：收到，正在同步状态
  -> 读取看板缓存
  -> 对话区回答
  -> 需要时展开完整状态
```

查询不需要确认，不下发控制器动作。

### 8.2 普通动作流程

```text
操作者发出动作
  -> 立即回执
  -> 自然语言解析
  -> 生成计划卡
  -> 安全预检
  -> 预检通过
  -> 等待人工确认
  -> V5.0 三道门发送
  -> 执行监控
  -> 完成/失败/报警反馈
```

### 8.3 有风险动作流程

```text
操作者发出动作
  -> 立即回执
  -> 生成计划卡
  -> 安全预检发现风险
  -> 进入安全确认场景
  -> 给出风险原因和建议
  -> 操作者取消/采纳建议/授权确认
```

高风险动作默认不允许直接确认执行，必须按安全等级配置。

### 8.4 应急流程

```text
识别到授权应急编码
  -> 不等待大模型
  -> 走独立 Func104 通道
  -> 立即反馈
  -> 切换报警/安全状态场景
```

单独提到“急停”等词，不应直接触发动作。界面要明确显示“未识别有效授权指令，不执行动作”。

## 9. 页面状态机

使用页面建议使用 `QStackedWidget` 管理场景状态：

```text
待机
  -> 查询回答
  -> 安全预检
安全预检
  -> 等待确认
  -> 待机
  -> 报警
等待确认
  -> 执行中
  -> 待机
执行中
  -> 完成反馈
  -> 暂停中
  -> 报警
暂停中
  -> 执行中
  -> 待机
报警
  -> 报警确认
  -> 待机
完整状态
  -> 返回上一场景
```

状态切换时，对话区必须同步追加系统消息，不能只改变画面。

## 10. 视觉设计规范

整体风格：工业软件、清晰、克制、可长时间盯屏。

色彩：

| 用途 | 建议色 | 说明 |
| --- | --- | --- |
| 页面背景 | `#EAF1F5` 或 `#F2F5F7` | 降低疲劳 |
| 卡片背景 | `#FFFFFF` | 明确层级 |
| 分割线 | `#C7D3DC` | 保持结构 |
| 主操作 | `#1D7F5F` | 确认、发送 |
| 运行中 | `#28607D` | 执行、通讯 |
| 成功 | `#137A3D` | 正常、通过 |
| 警告 | `#A96800` | 风险、等待 |
| 危险 | `#B42318` | 急停、报警 |
| 禁用 | `#8A98A4` | 离线、不可操作 |

字体：

- 中文优先：`Microsoft YaHei`。
- 常规正文：13 到 15px。
- 状态栏数字：14 到 16px，必要时等宽。
- 主场景标题：18 到 22px。
- 按钮文字：14 到 16px。

控件：

- 卡片圆角不超过 8px。
- 安全按钮固定位置，不能随场景消失。
- 急停按钮使用红色实心，面积大于普通按钮。
- 按钮文字必须短，动作明确，例如“确认执行”“取消”“解释风险”。
- 不使用装饰性背景图和渐变球，避免干扰状态识别。

## 12. 分阶段实施路线

### 第一期：页面分层和使用页骨架

目标：不改底层执行链路，先把页面结构立起来。

交付：

- 新增“使用页面/工程师页面”切换。
- 使用页常驻状态栏。
- 使用页对话区、输入区、右侧计划/看板侧栏。
- 自然语言输入后生成可读计划卡。
- 工程师页保留现有功能。

验收：

- 能从使用页输入文本并看到回执。
- 能显示当前连接、报警、忙闲、轴位摘要。
- 能切换回工程师页执行现有调试功能。

### 第二期：预检和确认闭环

目标：使用页支持从语言到计划、预检、确认的完整闭环。

交付：

- 动作计划卡。
- 预检场景。
- 预检通过/风险/禁止三类状态。
- 确认执行、取消、解释风险。
- 最近事件时间线。

验收：

- 普通动作不会绕过确认直接执行。
- 风险动作能展示具体原因。
- 查询类问题不进入执行确认。

### 第三期：执行监控和报警场景

目标：操作者可以不用工程师页完成一次生产动作。

交付：

- 执行监控场景。
- 执行进度、当前位置、目标值、完成反馈。
- 报警强制覆盖场景。
- 暂停、继续、取消、报警复位的使用页交互。

验收：

- 执行中追问状态能立即回答。
- 报警后普通执行按钮不可用。
- 所有关键事件写入日志。

### 第四期：工程师页整理

目标：把现有工程师页从“三页堆叠”整理为维护模块。

交付：

- 运行调试、自然语言调试、指令模板、流程管理、安全参数、安全中间点、日志诊断导航。
- 后台表单按函数类型分组。
- 日志过滤和 session 查看。
- 危险操作确认。

验收：

- 现有模板、流程、参数功能不丢失。
- 工程师页能更快定位模板、流程、日志和安全参数。

## 13. 设计验收清单

使用页面验收：

- 输入后 200ms 内有可见回执。
- 急停、暂停、报警、通讯状态始终可见。
- 运动和流程动作必须显示计划卡并等待确认。
- 风险原因必须具体到参数、位置或报警码。
- 执行过程中能看到当前值、目标值和状态。
- 报警发生时能主动切换到报警处理。
- 每个按钮都有语音等价指令。
- 小窗口模式仍保留关键状态和急停按钮。

工程师页面验收：

- 现有连接、固定指令、流程执行、自然语言解析不丢失。
- 指令模板可新增、保存、另存、删除、导入、导出。
- 系统参数和安全中间点可维护。
- 流程可编排和单步调试。
- 日志可查看、过滤、导出。
- 危险操作有确认。

数据一致性验收：

- 使用页和工程师页显示的设备状态来自同一份快照。
- 使用页计划卡与工程师页解析结果可追溯到同一 plan/session。
- 执行结果同时进入使用页时间线和工程师日志。
- 报警状态在两个页面一致。

## 14. 最终页面关系

最终软件不再是单一工程师调试工具，而是一个双层产品：

- 使用页面负责生产操作，把自然语言、安全确认、状态反馈做成主体验。
- 工程师页面负责维护调试，把模板、流程、参数、日志做成后台能力。
- 两者共享底层控制器、看板、日志、预检、执行链路。

这个结构能保留当前工程能力，同时给后续自然语言交互系统留出清晰的用户入口。
