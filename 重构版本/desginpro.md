## 一、总体定位与核心目标

### 1.1 产品定义

当前软件 v4.x 已具备控制器连接、固定指令、流程执行、自然语言解析、语音识别、模板维护、系统参数、安全中间点、日志等能力，但现有页面是典型的"工程师工作台"：控件密度高、参数暴露多、执行逻辑偏调试。

后续产品需要从"工程师调试工具"升级为"双层产品"：

| 页面 | 面向角色 | 核心目标 | 操作方式 | 信息密度 |
|------|---------|---------|---------|---------|
| **使用页面** | 产线操作者 | 自然语言交互、状态确认、安全执行、报警处理 | 语音/文本为主，按钮为辅 | 低到中，只显示当前任务需要的信息 |
| **工程师页面** | 调试、集成、维护人员 | 连接调试、模板维护、参数配置、流程维护、日志排障 | 鼠标键盘为主，语音为辅 | 高，允许完整参数和表格 |

### 1.2 核心命题

用自然语言交互**完整替代 HMI 触摸屏的信息传递功能**。屏幕上的信息是"一直在那里的"，而语言信息是"说了才有、不说就没有的"。设计必须解决这个根本矛盾。

**底线标准**：自然语言交互系统在信息传递的及时性、完整性、准确性上，不得低于 HMI 触摸屏。

### 1.3 设计原则

1. **使用页面是默认生产入口**，工程师页面是维护入口。
2. **所有安全关键状态必须常驻显示**，不依赖操作者主动询问。
3. **每一次输入都要快速给出回执**，不允许界面沉默——这是安全底线。
4. **所有执行动作必须经过**：状态读取 → 预检 → 确认 → 执行反馈 四步。
5. **工程师页面不删除现有能力**，但要重新归类、降低混乱感。
6. **双页面共用同一套状态、日志、指令、流程和安全数据**。
7. **所有回答必须精确、量化、无模糊表述**。

### 1.4 即时回应：系统的生命线

"即时回应"不是要求所有问题都在 50ms 内给出最终答案，而是要求**系统在任何情况下都不沉默**。分为三个层次：

| 层次 | 时间要求 | 内容 | 作用 |
|------|---------|------|------|
| 回执应答 | 文字≤50ms，语音≤200ms | "收到，正在处理" | 消除"它听到没有"的疑虑 |
| 安抚性回应 | 后台运算期间持续播报 | 同步已知设备状态 + 处理进度 | 防止信息真空导致焦虑 |
| 结果应答 | 查询≤200ms，预检≤2s，预演≤5s | 完整、精确的答案 | 最终信息交付 |

**核心逻辑**：先确认收到 → 同步已知状态 → 告知正在处理 → 给出最终结果。缺少任何一步，操作者就会进入"信息真空"，可能引发误操作。

## 二、应用级信息架构

### 2.1 页面路由

```text
应用启动
  │
  ├── 角色选择（首次）/ 默认入口（配置）
  │
  ├── 使用页面：操作者日常入口
  │     │
  │     ├── 智能对话
  │     ├── 安全预检
  │     ├── 执行监控
  │     ├── 报警处理
  │     └── 完整状态
  │
  └── 工程师页面：维护调试入口
        │
        ├── 运行调试
        ├── 自然语言调试
        ├── 指令模板
        ├── 流程管理
        ├── 安全参数
        ├── 安全中间点
        ├── 日志诊断
        └── 授权与系统
```

### 2.2 入口策略

- 首次启动显示角色选择：`进入使用页面`、`进入工程师页面`。
- 可在设置中配置默认入口，生产环境默认进入使用页面。
- 工程师页面入口需要权限控制（二次确认，后续可接授权系统）。
- 页面切换放在顶部菜单或右上角，不放操作者主操作区，避免误触。

### 2.3 使用页面内部场景状态机

使用页面内部使用 `QStackedWidget` 管理场景：

```text
待机
  ├── 查询回答（回到待机）
  ├── 安全预检
安全预检
  ├── 等待确认
  ├── 待机（取消）
  └── 报警（预检失败/风险）
等待确认
  ├── 执行中
  └── 待机（取消）
执行中
  ├── 完成反馈（回到待机）
  ├── 暂停中
  └── 报警
暂停中
  ├── 执行中（继续）
  └── 待机（取消）
报警
  ├── 报警确认（回到待机）
  └── 待机
完整状态
  └── 返回上一场景
```

状态切换时，对话区必须同步追加系统消息，不能只改变画面。

## 三、使用页面设计

使用页面是生产主入口，核心不是"控制面板"，而是"语言交互的脸"。操作者应一直知道三件事：

1. 设备现在是否安全。
2. 系统听到了什么、理解成什么。
3. 下一步是等待、确认、执行、完成，还是报警处理。

### 3.1 推荐桌面布局

```text
+--------------------------------------------------------------------------------+
| 常驻状态栏：总体状态 | 急停 | 暂停 | 报警 | 通讯 | 当前执行 | J1-J6 | R/Z       |
+--------------+------------------------------------------------+----------------+
| 场景导航      | 主场景区域                                      | 状态/计划侧栏   |
|              |                                                |                |
| 智能对话      | 对话消息区域                                    | 待确认计划      |
| 安全预检      | + 当前任务卡                                    | 七类看板摘要    |
| 执行监控      | + 预检/执行进度                                 | 风险/报警详情   |
| 报警处理      | + 安全确认按钮                                  | 最近事件        |
| 完整状态      |                                                |                |
+--------------+------------------------------------------------+----------------+
| 语音/文本输入区：麦克风 | 输入框 | 发送 | 急停 | 暂停 | 继续 | 取消            |
+--------------------------------------------------------------------------------+
```

### 3.2 响应式策略

| 分辨率 | 布局 |
|--------|------|
| 1380×860 及以上 | 三列：左导航 + 中对话 + 右状态 |
| 1024–1379 | 两列：隐藏左导航为顶部标签，保留右侧状态栏 |
| 小窗口模式 | 单列：只显示常驻状态栏、当前对话、紧急按钮，完整看板折叠 |

### 3.3 常驻状态栏

常驻状态栏**必须永远可见**，任何场景都不能遮挡。替代传统 HMI 中"看一眼"的状态感知。

| 字段 | 内容 | 状态颜色 | 数据来源 |
|------|------|---------|---------|
| 总体状态 | 就绪/运行/预检/等待确认/暂停/报警/离线 | 绿/蓝/黄/红/灰 | 综合状态 |
| 急停 | 开/关 | 关为绿，开为红 | `LONG(34)` bit25 |
| 暂停 | 开/关 | 关为绿，开为黄 | `LONG(34)` bit26 |
| 报警 | 无/有+报警码 | 无为绿，有为红 | `LONG(38)` |
| 通讯 | 正常/异常 | 绿/红 | 控制器连接 + EtherCAT |
| 当前执行 | 空闲/Func号/流程步骤 | 蓝/灰 | 回显、执行状态 |
| 轴位 | J1–J6 当前值 | 默认文本，超限红 | DPOS/MPOS |
| 空间位置 | R、Z 当前值 | 默认文本，越界红 | 安全看板 |

刷新规则：

- 核心状态 50ms 轮询。
- 状态栏 UI 节流刷新 100ms，避免抖动。
- 关键状态变化进入主动播报队列。

### 3.4 智能对话区

对话区是使用页面主区域，不显示工程师式 JSON。展示语音识别文本、系统回执、预检结论、确认请求和执行结果。

消息类型：

| 类型 | 显示内容 | 示例 |
|------|---------|------|
| 用户输入 | 语音识别或文本输入内容 | "把机械手移动到位置D，速度慢一点" |
| 回执消息 | 系统已收到，正在处理 | "收到，正在读取当前状态" |
| 安抚性回应 | 运算中同步当前状态 + 进度 | "当前设备空闲，无报警，通讯正常，数据读取中" |
| 状态快照 | 当前安全状态摘要 | "设备空闲，无报警，通讯正常" |
| 计划消息 | 系统理解后的动作计划 | "计划执行：移动到位置D，速度40%" |
| 预检消息 | 检查项、通过/风险、建议 | "限位通过，速度通过，空间范围通过" |
| 确认消息 | 需要操作者确认的按钮 | "确认执行 / 取消 / 解释风险" |
| 执行消息 | 执行中、完成、失败 | "已下发，等待控制器响应" |
| 报警消息 | 报警码、原因、处置按钮 | "J2速度超限，已暂停执行" |

硬性规则：

- 用户输入后立即追加"收到/正在处理"的回执。
- 复杂预检期间必须显示进度步骤，不允许只显示转圈。
- 所有系统回答必须包含当前已知设备状态，特别是执行前和报警后。
- 自然语言解析失败时，不显示技术报错，改为"未匹配到可执行动作"，提供可选建议。
- 回答必须精确量化，禁止模糊表述。例如："J2轴超出负限位，当前-175.3°，限位-170°"（禁止说"位置异常"）。

### 3.5 任务计划卡

当系统从自然语言中解析出可执行动作后，不直接执行，而是生成任务计划卡。

| 字段 | 说明 |
|------|------|
| 动作标题 | 例如"移动到位置D" |
| 动作类型 | 模板/流程/系统动作/查询 |
| 来源 | 规则解析/DeepSeek解析/快捷按钮 |
| 参数摘要 | 目标位置、速度、加速度、点位、IO 等 |
| 安全等级 | 普通/需确认/禁止执行 |
| 预检状态 | 未开始/进行中/通过/有风险/失败 |
| 操作按钮 | 确认执行/取消/解释风险/采纳建议 |

交互规则：

- 普通查询不生成确认卡，直接回答。
- 运动和流程动作必须先生成计划卡。
- `暂停`、`继续`、`报警复位`可快速确认。
- `急停`走独立应急通道，不等待大模型语义解析。

### 3.6 安全预检场景

展示系统从"理解动作"到"允许执行"的过程。

预检步骤：

1. **状态检查**：无急停、无报警、未暂停、控制器在线。
2. **通道检查**：目标通道空闲，可接受新指令。
3. **参数检查**：速度、加速度、减速度、坐标格式合法。
4. **安全边界**：R 球面半径、Z 高度、关节软限位（参见 3.10 安全边界看板）。
5. **运动规划**：是否需要中间点、是否有奇异点风险。
6. **回显准备**：准备走 V5.0 三道门发送流程。

视觉表达：

- 通过：绿色文字 + "通过"标签。
- 进行中：蓝色进度条 + 当前步骤描述。
- 有风险：黄色，给出风险原因和建议。
- 禁止：红色，只保留"取消"和"查看原因"按钮。

### 3.7 安全确认场景

当预检发现风险时进入此场景。

显示内容：

- 风险详情：具体参数、当前值、安全值、超限/偏差量。
- 风险原因和建议方案。
- 三个按钮：确认执行（高风险默认不允许）/ 采纳建议 / 取消。

示例：

> 目标位置 R=820mm，安全上限 R_max=800mm，半径超限 20mm。
> 建议：将目标 X 坐标从 350 调整为 330，R 降至 795mm。

### 3.8 执行监控场景

执行中页面重点不是参数编辑，而是"现在执行到哪了"。

显示内容：

- 当前动作或流程步骤。
- 当前值、目标值、剩余量。
- 执行进度百分比（若为估算必须标注"估算"）。
- 控制器回显、接受确认、当前函数号。
- 暂停、取消、急停按钮。
- 操作者追问时直接回答当前进度。

完成后：

- 显示最终位置和执行耗时。
- 显示结果：完成/取消/失败/报警中断。
- 自动写入最近事件和完整日志。

### 3.9 报警处理场景

报警优先级最高。任意页面发生报警，都切换或覆盖到报警场景。

报警页显示：

- 报警级别、报警码和人类可读说明。
- 发生时间、当前设备状态。
- 系统已采取的动作（如暂停、钳位、停止发送）。
- 操作按钮：确认报警、报警复位、完整状态、导出日志。

报警页禁止：

- 继续显示普通执行确认按钮。
- 让操作者在未确认报警原因时继续执行新动作。
- 只显示"异常"而不说明具体原因。

### 3.10 七类看板

### 3.11 主动播报

看板不仅是"被动回答"的数据源，还必须支持**主动播报**——关键状态变化时系统主动告知操作者。

| 触发条件 | 主动播报内容 | 优先级 |
|---------|------------|--------|
| 报警发生 | "注意：J2 轴速度超限报警" | 最高 |
| 急停状态变化 | "设备已进入急停状态" | 最高 |
| 运动完成 | "J2 运动完成，当前位置 45.02°" | 高 |
| 通讯异常 | "EtherCAT 通讯异常，请检查" | 高 |
| 预检不通过 | "目标位置超出安全范围，建议调整" | 中 |

### 3.12 智能对话的应答流程

#### 查询流程

```text
操作者问状态
  → 立即回执（≤50ms）："收到，正在同步状态"
  → 读取看板缓存
  → 对话区回答（精确量化）
  → 需要时展开完整状态
```

查询不需要确认，不下发控制器动作。

#### 普通动作流程

```text
操作者发出动作
  → 立即回执（≤50ms）
  → 自然语言解析
  → 生成计划卡
  → 安全预检（L1 即时安全检查）
  → 预检通过 → 等待人工确认
  → V5.0 三道门发送
  → 执行监控（进度播报）
  → 完成/失败/报警反馈
```

#### 有风险动作流程

```text
操作者发出动作
  → 立即回执
  → 生成计划卡
  → 安全预检发现风险
  → 进入安全确认场景
  → 给出风险原因和建议
  → 操作者取消 / 采纳建议 / 授权确认
```

高风险动作默认不允许直接确认执行。

#### 应急流程

```text
识别到授权应急编码（三段式："急停{数字}急停"）
  → 不等待大模型
  → 走独立 Func104 通道（≤30ms）
  → 立即反馈
  → 切换报警/安全状态场景
```

单独提到"急停"等词，不直接触发动作。界面明确显示"未识别有效授权应急指令，不执行动作"。

### 6.3 语义引擎：三层递进

```text
用户输入
  ↓
第1层：jieba 分词 + 关键词词典（<10ms，覆盖率 ~80%）
  ↓ 未命中
第2层：规则模板匹配（<5ms，覆盖率 ~15%）
  ↓ 未命中
第3层：DeepSeek API 兜底（500–2000ms，覆盖率 ~5%）
  ↓ 所有结果

  ↓
MODBUS TCP 下发 / 看板数据读取
  ↓
话术模板 + 数据组装应答（<5ms）
```

### 6.4 5 级语义分类

| 层级 | 名称 | 对应 Func | 识别方式 | 应答策略 |
|------|------|---------|---------|---------|
| L1 | 闲聊咨询 | 无 | DeepSeek 兜底 | 直接生成自然语言回复 |
| L2 | 工艺查询 | Func13/14+预演 | 关键词"能不能""安全吗""到不到" | 触发 L1/L2 预检，返回可行性评估 |
| L3 | 常规执行 | 106/107/108/109/11 | 关键词 + 参数提取 | 回执 → 安全预检 → 确认 → 执行 → 结果 |
| L4 | 系统管理 | 1/2/15/标定 | 关键词 + 参数提取 | 回执 → 参数校验 → 执行 → 结果 |
| L5 | 应急处置 | 104/16/17 | 三段式编码匹配 | 跳过 NLP，直发 MODBUS |

各级即时回应标准：

| 层级 | 回执应答 | 结果应答 | 进度同步 | 特殊要求 |
|------|---------|---------|---------|---------|
| L1 闲聊 | ≤50ms | ≤1s | — | 涉及设备关键词需主动提醒 |
| L2 查询 | ≤50ms | ≤200ms(简单)/≤5s(预检) | 每 2s 播报 | 预检不通过须明确风险点和建议 |
| L3 执行 | ≤50ms | 执行完成后≤200ms | 每 1s 更新 | 执行中追问状态必须即时回答 |
| L4 管理 | ≤50ms | ≤2s | — | 安全参数修改须二次确认 |
| L5 应急 | ≤30ms(编码命中)/≤200ms(无效) | ≤100ms | — | 单独提及关键词不触发动作 |

### 6.5 应急指令管控

**三段式格式**：`关键词 + 数字编码 + 重复关键词`

示例：`急停1234急停`

校验流程：

```text
输入文本
  ↓ 正则匹配："急停\s*(\d+)\s*急停"
  ├── 匹配成功 → 提取编码 → 白名单校验
  │   ├── 编码在白名单 → 立即执行 Func104（<30ms）
  │   └── 编码不在白名单 → 返回"未识别有效授权应急指令"
  └── 仅匹配"急停"无编码 → 返回"未识别有效授权应急指令，请使用标准格式"
```

应急手段优先级：

| 优先级 | 手段 | 响应速度 | 定位 |
|--------|------|---------|------|
| 1 | 物理急停按钮 | ≤1ms | 唯一主要手段 |
| 2 | HMI 触摸屏急停 | ≤50ms | 辅助手段 |
| 3 | 上位机软件急停按钮 | ≤100ms | 辅助手段 |
| 4 | 语音急停（授权编码） | 3–10s | 辅助手段，不能替代物理急停 |

### 6.6 双重安全机制

| 层级 | 执行方 | 检查内容 | 定位 |
|------|--------|---------|------|
| PC 侧预检 | 上位机 | L1 参数级安全预检（限位/速度/空间范围） | 快速预警，基于缓存数据 |
| 控制器精检 | Func13/14 | 实时数据精确检查 | 最终确认，基于实时数据 |

PC 侧预检用于"快速预警"（发指令前给风险提示），控制器侧 Func13/14 用于"最终确认"（执行前强制安全检查）。两层互不替代，互为补充。

### 6.7 MODBUS TCP 分组轮询策略

| 优先级 | 数据组 | 地址范围 | 轮询周期 | MODBUS 请求数 |
|--------|--------|---------|---------|-------------|
| 核心 | LONG(34/36/38/40/42/46) 状态字 | — | 50ms | 1 次 |
| 核心 | IEEE(1500–1522) DPOS 12 轴 | — | 50ms | 1 次 |
| 核心 | IEEE(1600–1622) MPOS 12 轴 | — | 50ms | 1 次 |
| 次要 | IEEE(1700–1730) 安全参数+速度 | — | 100ms | 1 次 |
| 次要 | IEEE(200–222) AXISSTATUS | — | 100ms | 1 次 |
| 次要 | IEEE(240–262) MTYPE | — | 100ms | 1 次 |
| 低频 | IEEE(50–126) 软限位 | — | 启动时 1 次 | 2 次 |
| 低频 | IEEE(340–560) 标定数据 | — | 500ms | 按需 |
| 低频 | IEEE(1000–1195) 障碍物 | — | 事件触发 | 按需 |

性能评估：核心数据 3 次请求 × 10ms ≈ 30ms，在 50ms 周期内完成。

## 七、L1/L2/L3 安全预检体系

### 7.1 L1 即时安全检查（单动作级）

纯 Python 实现，无需调用控制器 API：

| 检查项 | 实现方式 | 数据源 |
|--------|---------|--------|
| 球面半径 | `r_min < sqrt(x²+y²+z²) < r_max` | 看板 3 |
| Z 高度 | `z_min < z < z_max` | 看板 3 |
| 速度百分比 | `0 < spd_pct ≤ 150` | 看板 4 |
| 软限位 | `rs_limit[i] ≤ target[i] ≤ fs_limit[i]` | 看板 3 |
| 系统报警 | `alarm_code == 0 and not estop` | 看板 1 |

### 7.2 L2 运动规划预演

调用控制器 FRAME_TRANS2 API，Python 侧实现决策逻辑：

| 检查项 | Python 实现 | 控制器 API 调用 |
|--------|-----------|-------------|
| FSTATUS 遍历 | 8 次循环 + 评分 | `FRAME_TRANS2(dir=2, fstatus=i)` |
| 奇异点检测 | 插值 5 点 + 阈值判断 | `FRAME_TRANS2(dir=2)` |
| 中点规划 | RY 偏移 5° | `FRAME_TRANS2(dir=2)` |
| 运动规划决策 | MotionPlan 决策树 | 依赖上述 API 结果 |

### 7.3 L3 流程级预演

基于 L1+L2 组合：

| 检查项 | 实现方式 |
|--------|---------|
| 逐动作安全检查 | 对流程每个动作调用 L1 |
| 逐动作路径规划 | 对每个直线运动调用 L2 |
| 时序适配性 | 状态机模拟（急停后未复位 → 禁止运动） |
| 累积误差评估 | 误差传播计算（每步误差叠加） |
| 干涉检查 | 简化包围盒检查 |

### 7.4 风险类型识别

| 风险类型 | 检测方式 | 反馈模板 |
|---------|---------|---------|
| 半径超限 | L1 空间检查 | "半径超限：当前 R={r}mm，安全上限 R_max={r_max}mm" |
| 高度超限 | L1 空间检查 | "高度超限：当前 Z={z}mm，安全上限 Z_max={z_max}mm" |
| 速度超限 | L1 速度检查 | "速度超限：指令速度 {spd}%，安全上限 {max_spd}%" |
| 软限位 | L1 限位检查 | "J{axis} 超出限位：目标 {target}°，限位 {limit}°" |

## 十二、语言交互的防误操作设计

### 12.1 三不原则

| 原则 | 要求 | 反例（禁止） |
|------|------|------------|
| **不沉默** | 任何输入必须在最短时间内得到回应 | 后台计算时界面无任何反馈 |
| **不模糊** | 所有回答必须精确、具体、量化 | "位置异常"、"速度有问题"、"不太安全" |
| **不遗漏** | 操作者需要知道的信息必须完整提供 | 只说"不安全"不说原因和建议 |

### 12.2 精确表述对照

| 模糊表述（禁止） | 精确表述（要求） |
|----------------|----------------|
| "位置异常" | "J2 轴超出负限位，当前 -175.3°，限位 -170°" |
| "速度有问题" | "指令速度 80%，安全上限 75%，超限 5%" |
| "不太安全" | "目标位置 R=850mm，安全上限 R_max=800mm，半径超限 50mm" |
| "处理中" | "安全预检进度 60%，已完成限位检查和速度检查，正在进行空间范围核验" |

### 12.3 误操作预防对照表

| 误操作模式 | 触发原因 | 预防措施 |
|-----------|---------|---------|
| 重复发送指令 | 不确定指令是否被接收 | 回执应答 ≤50ms |
| 自行判断设备状态 | 系统未及时反馈状态 | 安抚性回应 + 已知状态同步 |
| 焦虑性急停 | 不确定设备是否安全 | 安全状态主动同步 |
| 放弃语言交互 | 系统响应太慢 | 所有交互 ≤200ms 内有回应 |
| 误发危险指令 | 系统未做安全预检 | 指令安全网关强制预检 |

## 十三、分阶段实施路线

### 第一期：页面分层 + 使用页骨架 + 文字交互

**目标**：不改底层执行链路，先把双页面结构和使用页骨架立起来。

**交付**：

- 新增"使用页面/工程师页面"角色选择和页面切换。
- 使用页常驻状态栏（绑定看板数据）。
- 使用页对话区、输入区、右侧计划/看板侧栏。
- 自然语言输入后生成可读计划卡。
- jieba + 关键词词典语义引擎 + 两阶段应答。
- 7 类看板缓存 + MODBUS 分组轮询。
- L1 即时安全预检模块。
- 应急编码校验 + 独立通道。
- 工程师页保留现有全部功能。

**验收**：

- 能从使用页输入文本并看到 ≤50ms 回执。
- 能显示当前连接、报警、忙闲、轴位摘要。
- 简单查询结果 ≤500ms。
- 能切换回工程师页执行现有调试功能。
- L1 安全预检覆盖率 100%。
- 应急编码有效识别率 100%、误触发率 0%。
- 7 类看板 50ms 刷新。

### 第二期：预检确认闭环 + 语音交互 + L2 预演

**目标**：使用页支持从语言到计划、预检、确认的完整闭环。

**交付**：

- 动作计划卡完整交互。
- 预检场景（通过/风险/禁止三类状态）。
- 安全确认场景（风险原因 + 建议）。
- 确认执行、取消、解释风险、采纳建议交互。
- 最近事件时间线。
- 语音识别集成（iFlytek + VAD 回执）。
- L2 运动规划预演（调用控制器 FRAME_TRANS2 API）。
- 动态进度播报。

**验收**：

- 普通动作不会绕过确认直接执行。
- 风险动作能展示具体原因（精确到参数/位置/报警码）。
- 查询类问题不进入执行确认。
- 语音 VAD 回执 ≤200ms。
- L2 运动规划预演结果与控制器一致。
- 复杂预演 ≤5s + 动态播报。

### 第三期：执行监控 + 报警场景 + 语音应急

**目标**：操作者可以不用工程师页完成一次完整生产动作。

**交付**：

- 执行监控场景（进度、当前值、目标值、完成反馈）。
- 报警强制覆盖场景。
- 暂停、继续、取消、报警复位的使用页交互。
- 语音应急指令（三段式 + 关键词唤醒）。
- 主动播报（报警、急停、运动完成、通讯异常）。
- 全语音控制（所有按钮有语音等价指令）。
- 全屏/小窗口切换。

**验收**：

- 执行中追问状态能立即回答。
- 报警后普通执行按钮不可用。
- 所有关键事件写入日志。
- 语音应急编码识别准确率 100%。

### 第四期：工程师页整理 + L3 流程预演 + AI 预留

**目标**：工程师页从"三页堆叠"整理为维护模块，完成 L3 预演和 AI 接口预留。

**交付**：

- 运行调试、自然语言调试、指令模板、流程管理、安全参数、安全中间点、日志诊断导航。
- 后台表单按函数类型分组。
- 日志过滤和 session 查看。
- 危险操作确认。
- L3 流程级预演（时序 + 累积误差 + 干涉）。
- 6 类 AI 迭代预留接口。
- 安全参数分层读写 + 热更新。
- 对话日志归档 + 数据集自动生成。
- 生产工艺优化数据通道。

**验收**：

- 现有模板、流程、参数功能不丢失。
- 工程师页能更快定位模板、流程、日志和安全参数。
- L3 流程预演完整覆盖所有风险类型。
- AI 接口可对接本地 7B 大模型。
- 安全参数热更新闭环验证通过。

## 十五、关键风险与缓解

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| MODBUS TCP 轮询延迟 | 核心数据可能偶尔超出 50ms | 分组轮询 + 状态字优先 + 位置数据可容忍偶尔延迟 |
| PC 与控制器状态不同步 | 50ms stale data 可能导致误判 | 安全关键操作强制调用 Func13/14 实时确认 |
| 语音识别环境噪音 | 工业现场 ASR 准确率下降 | 定向麦克风 + 降噪 + 文本/按钮为备份方式 |
| PC 程序崩溃 | 交互系统失效 | 守护进程 + 看门狗 + HMI 始终可用作备用 |
| FRAME_TRANS2 调用延迟 | L2 预演可能较慢 | 缓存逆解结果 + 异步预演 + 进度播报 |
| 未来大模型对接 | 接口不兼容 | JSON 格式统一 + 标准化接口定义 |

## 十七、最终产品形态

最终软件不再是单一工程师调试工具，而是一个**双层产品**：

- **使用页面**负责生产操作，把自然语言交互、安全确认、状态反馈做成主体验。操作者可以用语言完成查询、预检、确认、执行和报警处理的完整闭环。所有按钮有语音等价指令，鼠标键盘是可选的，不是必需的。
- **工程师页面**负责维护调试，把模板、流程、参数、日志做成后台能力模块。信息密度高，适合调试排障。
- **两者共享底层**：控制器连接、看板缓存、安全预检、指令执行链路、日志系统、数据归档。

这个结构既能保留当前全部工程能力，又为自然语言交互系统提供了清晰的生产入口，为后续 AI 大模型迭代预留了完整的数据通道。
