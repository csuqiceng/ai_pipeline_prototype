# V3.0 Modbus TCP 协议迁移 — 完整实施记录

## 一、需求背景

### 1.1 原始需求

下位机(ZMC406-V2控制器)已实现 V3.0 IEEE/Modbus TCP 协议接口（Func 101~106，IEEE(0~34)寄存器，BIT(243)报警）。上位机当前使用 VR 寄存器协议（`ZAux_Direct_SetVrf/GetVrf`），需要新增 V3.0 协议分支，同时保留原有 VR 协议可回退。

### 1.2 通信方式变更原因

焊缝检测设备使用 Modbus TCP 通讯，上位机需要统一采用 Modbus TCP 方式与下位机通信。

### 1.3 V3.0 协议核心流程（来自《上位机通信协议说明书》）

```
发指令前: 读 BIT(243)==0(无报警) AND 读 IEEE(34)==0或4(不在执行中)
发送:     写 IEEE(0)=函数号 → 写 IEEE(2~30)=参数 → 写 IEEE(32)=1触发
等待:     轮询 IEEE(34)==4(完成)
异常:     IEEE(34)==12/28/44/72 为报警组合码
实时:     读 IEEE(1512~1522)=X/Y/Z/Rx/Ry/Rz（持续更新）
```

### 1.4 V3.0 IEEE 地址映射

| 用途 | IEEE地址 | SDK调用 | 说明 |
|------|---------|---------|------|
| 函数号 | IEEE(0) | `Modbus_Set4x_Float(0, 1, [func])` | 不清零，改了才变 |
| 目标X | IEEE(2) | `Modbus_Set4x_Float(2, 1, [x])` | mm |
| 目标Y | IEEE(4) | `Modbus_Set4x_Float(4, 1, [y])` | mm |
| 目标Z | IEEE(6) | `Modbus_Set4x_Float(6, 1, [z])` | mm |
| 目标Rx | IEEE(8) | `Modbus_Set4x_Float(8, 1, [rx])` | 度 |
| 目标Ry | IEEE(10) | `Modbus_Set4x_Float(10, 1, [ry])` | 度 |
| 目标Rz | IEEE(12) | `Modbus_Set4x_Float(12, 1, [rz])` | 度 |
| 速度 | IEEE(14) | `Modbus_Set4x_Float(14, 1, [speed])` | mm/s |
| 加速度 | IEEE(16) | `Modbus_Set4x_Float(16, 1, [accel])` | mm/s² |
| 减速度 | IEEE(18) | `Modbus_Set4x_Float(18, 1, [decel])` | mm/s² |
| 模糊标志 | IEEE(20) | `Modbus_Set4x_Float(20, 1, [0或1])` | 0=精确 1=模糊 |
| 模糊步长 | IEEE(22) | `Modbus_Set4x_Float(22, 1, [step])` | mm |
| 执行触发 | IEEE(32) | `Modbus_Set4x_Float(32, 1, [1.0])` | 写1触发 |
| 函数状态 | IEEE(34) | `Modbus_Get4x_Float(34, 1)` | 0/1/2/4/12/28/44/72 |
| 总报警 | BIT(243) | `Modbus_Get0x(243, 1)` | 0=正常 1=报警 |
| 启动就绪 | BIT(253) | `Modbus_Get0x(253, 1)` | 1=就绪 |
| 急停触发 | BIT(150) | `Modbus_Set0x(150, 1, [1])` | 写1急停 |
| 实时坐标 | IEEE(1512~1522) | `Modbus_Get4x_Float(1512, 6)` | X/Y/Z/RX/RY/RZ |

**重要说明**: SDK `ZAux_Modbus_Set4x_Float(start, ...)` 中 `start` 是 **MODBUS_IEEE 编号**，不是 REG 地址。标准 Modbus TCP 视角中 MODBUS_IEEE(0) 对应 4x 寄存器地址 40~41（每个 IEEE 占 2 个 REG 地址），但 SDK 已封装此映射。

### 1.5 V3.0 函数号定义（来自协议说明书）

| 函数号 | 名称 | 参数 | 说明 |
|--------|------|------|------|
| 101 | 关节移动 | IEEE(2)=轴号, (4)=方向, (6)=速度, (8)=角度, (10)=模糊 | 上位机暂未使用 |
| 102 | 直线插补 | IEEE(2~18)=XYZ坐标+速度加速度, (20)=模糊, (22)=步长 | 主要运动函数 |
| 103 | 报警清除 | 无参数 | 清除所有报警 |
| 104 | 停止 | IEEE(2)=0急停/1慢停 | 也可直接写BIT(150)=1急停 |
| 105 | 状态查询 | 无输入参数，结果在IEEE(2~30) | 查询当前位置和报警 |
| 106 | 焊缝巡迹 | 预留 | 暂不使用 |

### 1.6 IEEE(34) 状态码

| 值 | 含义 | 上位机动作 |
|----|------|-----------|
| 0 | 空闲 | 可发指令 |
| 1 | 就绪 | 可发指令 |
| 2 | 执行中 | 等待 |
| 4 | 完成 | 可发新指令 |
| 12 (4+8) | 完成+报警 | 清除报警 |
| 28 (4+8+16) | 完成+半径超限 | 反向移动 |
| 44 (4+8+32) | 完成+高度超限 | 反向移动 |
| 72 (8+64) | 报警+指令非法 | 减小步长 |

### 1.7 与 VR 协议的关键区别

| | VR 协议 | V3.0 Modbus TCP |
|--|--------|----------------|
| 通信方式 | `write_vr` / `read_vr` (ZAux_Direct_SetVrf/GetVrf) | `write_modbus_float` / `read_modbus_float` (ZAux_Modbus_Set4x_Float/Get4x_Float) |
| 镜像确认 | 需要（VR[500~516]） | **不需要** |
| 前置检查 | 无 | **BIT(243)==0 且 IEEE(34)==0或4** |
| 触发寄存器 | VR[517] | IEEE(32) |
| 状态寄存器 | VR[16~25] 10个值 | IEEE(34) 单个状态码 |
| 命令码 | 1001~6002 | 101~106 |
| 完成判定 | `status != RUNNING` | IEEE(34) bit2=1 |
| 速度单位 | 百分比(0~100) | mm/s |
| 夹爪控制 | VR命令码1004 | BIT(20000+) 写OUT口 |
| 延时等待 | VR命令码1006 | 上位机本地sleep |

### 3.4 `robot_modbus_lite/service.py` — 新增约80行

**修改位置**: 文件末尾，新增 V3.0 方法区

**新增内容**:

1. **命令码映射表** `VR_TO_V30_MAP`:
   ```python
   1001: 102,   # MOVE_ABS → 直线插补
   1002: 102,   # MOVE_REL → 直线插补
   1003: 102,   # HOME → 直线插补到原点
   1004: -1,    # GRIP_SET → 上位机写BIT口
   1005: -3,    # DOOR_CTRL → 上位机写BIT口
   1006: -2,    # WAIT_MS → 上位机本地延时
   1007: -4,    # CHECK_IN → 上位机本地无操作
   1008: 103,   # EMG_RESET → 报警清除
   4001: 103,   # SYS_RESET → 报警清除
   4002: 104,   # SYS_ESTOP → 停止(急停)
   4003: 104,   # SYS_PAUSE → 停止(慢停)
   4004: -5,    # SYS_RESUME → 上位机本地状态切换
   5001: -6,    # FIXED_FUNC → 上位机本地无操作
   6001: -5,    # AUTO_START → 上位机本地状态切换
   6002: -5,    # AUTO_STOP → 上位机本地状态切换
   ```
   
   **负数函数号含义**：V3.0 协议没有对应的下位机函数，由上位机本地处理：
   - `-1` GRIP_SET：写 BIT(20000) 控制夹爪
   - `-2` WAIT_MS：上位机本地 `time.sleep()`
   - `-3` DOOR_CTRL：写 BIT(20001) 控制门
   - `-4` CHECK_IN：本地空操作
   - `-5` RESUME/START/STOP：本地状态切换
   - `-6` FIXED_FUNC：本地空操作

2. **`build_v30_command_from_record(record, base_speed_mm=3000.0)`**
   - 将 QueryRecord 转换为 V30Command
   - Func 102: 速度从百分比换算为 mm/s（`speed = base_speed_mm * pct / 100`）
   - Func -1(GRIP): 提取 io_grip 参数
   - Func -2(WAIT): 提取延时参数
   - Func -3(DOOR): 提取 io_door 参数
   - Func < 0 其他: 本地操作标记
   - Func 103/104: 系统命令，含 stop_mode 区分急停/慢停

3. **`build_v30_system_command(code)`** — 构建系统命令
4. **`build_v30_precheck_reads()`** — 返回前置检查请求
5. **`build_v30_status_read()`** — 读 IEEE(34)
6. **`parse_v30_status(values)`** — 解析状态
7. **`build_v30_realtime_read()`** — 读 IEEE(1512~1522)
8. **`parse_v30_realtime(values)`** — 解析实时坐标

## 四、评审中发现的问题及修正

### 问题1（已修正）：`to_func_writes()` 跳过值为0的参数

- **文件**: `models.py` 第299行
- **问题**: `if val != 0.0` 导致坐标为0的轴不写入。例如移动到 (100, 0, 50)，Y=0 不会被写入，下位机可能读到旧值
- **修正**: 去掉 `if val != 0.0` 判断，始终写入所有参数
- **修正后代码**:
  ```python
  for addr, val in sorted(param_map.items()):
      writes.append(VrWriteRequest(start_vr=addr, values=(val,)))
  ```

### 问题2（已修正）：Func 104 停止命令缺少 stop_mode 参数

- **文件**: `service.py`
- **问题**: 急停(4002)和暂停(4003)都映射到 Func 104，但没有区分 stop_mode。按协议说明书 IEEE(2) 需写入 0=急停 或 1=慢停
- **修正**: 在 `build_v30_command_from_record` 和 `build_v30_system_command` 中增加 stop_mode 处理
  ```python
  if func_num == 104:
      stop_mode = 0 if code == 4002 else 1  # 4002=急停 4003=慢停
      return V30Command(func_num=104, desc="STOP", x=float(stop_mode))
  ```

### 问题3（已修正）：`_evaluate_feedback_result` 把实时坐标当 IEEE(34) 状态码解析

- **文件**: `qt_gui.py`
- **问题**: `_execute_send_v30` 返回的是实时坐标 `[X, Y, Z, RX, RY, RZ]`，但 `_evaluate_feedback_result` 用 `parse_v30_status(feedback)` 解析——把 X 坐标当成了 IEEE(34) 状态码。执行成功却被误判为报警，导致流程中断
- **修正**: V3.0 分支直接返回 `(True, "")`，因为执行成功已在 `_execute_send_v30` 内部的轮询中确认

### 问题4（已修正）：GRIP_SET 和 WAIT_MS 无 V3.0 映射

- **文件**: `service.py`, `qt_gui.py`, `models.py`
- **问题**: 查询表中 function_id=9,10(夹爪) 和 11(延时) 映射到 VR 命令码 1004/1006，但 V3.0 协议没有对应函数。用户点击夹爪或流程中包含夹爪/延时会抛 ValueError 崩溃
- **修正**:
  - `VR_TO_V30_MAP` 新增 `1004: -1` (GRIP_SET → 上位机写BIT口) 和 `1006: -2` (WAIT_MS → 上位机本地延时)
  - `V30Command` 新增 `io_grip` 和 `ext_p1` 字段
  - `_execute_send_v30` 中增加特殊处理：GRIP 写 BIT(20000)，WAIT 本地 sleep

### 问题5（已修正）：Mock controller BIT 数组太小

- **文件**: `mock_controller/controller.py`
- **问题**: `_modbus_bit` 只有 8000 个元素，BIT(20000) 越界。模拟器下 GRIP 命令测试失败
- **修正**: 扩大到 24000

### 问题6（已修正）：`can_send` 不包含 IEEE(34)=1 (就绪) 状态

- **文件**: `models.py` `V30Status.can_send`
- **问题**: `can_send` 判断 `raw in (0, 4)`，缺少状态值 1 (就绪)。按协议说明书 "就绪→可发指令"，但代码拒绝在就绪状态下发送
- **修正**: 改为 `raw in (0, 1, 4)`

### 问题7（已修正）：系统按钮 SYS_RESUME/AUTO_START/AUTO_STOP 无 V3.0 映射

- **文件**: `service.py`, `qt_gui.py`
- **问题**: VR 命令码 4004(恢复)、6001(自动启动)、6002(自动停止) 以及 1005(门控)、1007(签到) 无 V3.0 映射。用户在 V3.0 模式下点击这些按钮或流程中包含这些命令会抛 ValueError 崩溃
- **修正**: `VR_TO_V30_MAP` 补全所有缺失映射为负数函数号（上位机本地处理），`_execute_send_v30` 和 `_handle_system_action_v30` 对 func_num<0 的命令跳过下位机通信

### 问题8（已修正）：Mock controller 执行完后清零 IEEE(0) 函数号

- **文件**: `mock_controller/controller.py` `_execute_v30_command`
- **问题**: `finally` 块中 `self._modbus_ieee[MODBUS_FUNC_ADDR] = 0.0` 清零了函数号，违反协议规则 "IEEE(0)不清零 — 函数号保持，改了才变"
- **修正**: 删除该清零语句

### 问题9（已修正）：完成+报警(IEEE(34)=12)被当作执行成功

- **文件**: `qt_gui.py` `_execute_send_v30`
- **问题**: 轮询 IEEE(34) 时，`is_complete` 检查 `(raw & 4) != 0`，对 raw=12(完成+报警) 也返回 True，导致报警状态被误判为成功
- **修正**: 在 `is_complete` break 前增加 `has_alarm` 检查，有报警则 raise RuntimeError

### 问题10（已修正）：V3.0 轮询检测到报警时未设置 alarm_code

- **文件**: `qt_gui.py` `_poll_feedback_silent`
- **问题**: V3.0 轮询分支在检测到报警时只设置了 `alarm_text`，没有设置 `alarm_code`，GUI 显示不完整
- **修正**: 补设 `alarm_code = f"ERR_V30_{raw}"`

### 问题11（已修正）：VR 和 V3.0 共用 `_exec_thread` 存在线程竞态

- **文件**: `mock_controller/controller.py`
- **问题**: VR 协议的 `_dispatch_command` 和 V3.0 的 `_dispatch_v30_command` 都读写同一个 `self._exec_thread` 字段，且 join+赋值操作未持锁，并发时可能丢失线程引用或导致两个命令同时执行
- **修正**: V3.0 使用独立字段 `_exec_thread_v30`

## 七、使用方式

1. 启动 GUI：`python gui_main.py`
2. 在顶部连接栏选择协议下拉框 → **V3.0 Modbus TCP**
3. 选择控制器类型（模拟控制器或真实控制器）
4. 连接后即可正常使用：发送指令、流程执行、实时监控

可随时切回 "最终标准协议" 回退到 VR 协议。
