# 方案说明

## 1. 目标

本方案用于真机早期联调，优先解决“上位机到控制器”的稳定数据传输问题。

第一阶段目标：

1. 上位机连接控制器 `192.168.1.11`
2. 通过 `Modbus TCP` 写入一组执行参数
3. 控制器收到后按函数序号执行
4. 先支持 `移动 / 抓取 / 放下`

## 2. 核心架构

上位机负责：

- 接收文本或语音指令
- 规则解析
- 查询有效数据表
- 组装发送值
- 通过 `ZMOTION SDK` 与控制器通讯

控制器负责：

- 接收 8 个值
- 读取函数序号
- 调用对应 `ZBasic` 函数
- 执行动作

## 3. 通讯定义

- 控制器 IP：`192.168.1.11`
- 协议：`Modbus TCP`
- SDK 角色：只负责连接和数据传输

第一阶段发送结构：

```text
[func_id, reg1, reg2, reg3, reg4, reg5, reg6, reg7]
```

含义：

- `func_id`：函数序号
- `reg1~reg6`：位置或动作参数
- `reg7`：速度或附加参数

## 4. 当前推荐的数据源

第一阶段不再把“功能表”和“位置表”作为主执行数据源，而是优先使用“有效数据查询表”。

也就是：

- 用户输入固定查询键
- 上位机直接查到一整组可发送数据
- 直接发给控制器

例如：

```text
位置A -> [3, 1400, -1, 1380, 1, 80, 1, 10]
抓取  -> [9, 1, 0, 0, 0, 0, 0, 0]
放下  -> [10, 0, 0, 0, 0, 0, 0, 0]
```

## 5. 第一阶段功能范围

- 移动
- 抓取
- 放下

推荐首批查询键：

- 归零
- home
- 位置A
- 位置B
- 位置C
- 位置D
- 位置E
- 位置X
- 抓取
- 放下
- 延时

## 6. 评审重点

开始编码前，需要先确认：

1. 函数序号的语义
2. Modbus 起始寄存器地址
3. 数据是否统一按浮点写入
4. 速度值是否统一去掉 `%`
5. 是否需要最小状态回读位
