# 语音与 DeepSeek 接入方案 - Qt版

## 目标

在不破坏当前 Qt 主链路的前提下，把旧项目中的：

- 讯飞 IAT 语音识别
- DeepSeek 自然语言解析

接入到新 Qt 方案中。

接入后的解析结果只允许落到三类稳定动作：

1. 执行单个模板
2. 执行单个流程
3. 执行系统动作

不直接生成任意寄存器写入，不新增旁路执行链。

---

## 接入原则

### 1. 不改现有发送主链路

所有自然语言解析结果最终仍然走已有入口：

- 模板执行：`_execute_query_key(...)`
- 流程执行：`_start_flow()`
- 系统动作：`_handle_system_action(...)`

### 2. 先做最小可用版

第一阶段先接：

- 文本输入
- 规则解析
- DeepSeek 可选解析

暂不把麦克风和音频文件识别直接做进 GUI 主界面。

### 3. 失败必须回退

DeepSeek 调用失败时：

- 自动回退到本地规则解析
- 不允许因为外部接口失败而影响本地执行能力

---

## 总体结构

```text
手工输入文本
    │
    ▼
voice_nlp_adapter.py
    │
    ├─ 规则解析
    └─ DeepSeek 解析（可选）
    │
    ▼
统一动作结果
    │
    ├─ 模板执行
    ├─ 流程执行
    └─ 系统动作
```

---

## 模块设计

### 1. 新增适配层

新增：

- `robot_modbus_lite/voice_nlp_adapter.py`

职责：

- 接收自然语言文本
- 调用本地规则解析
- 可选调用 DeepSeek
- 返回统一结构化动作结果

输出类型限定为：

- `template`
- `flow`
- `system`
- `unknown`

### 2. GUI 接入点

在运行页新增：

- `语音/自然语言执行`

组件建议：

- 文本输入框
- `使用DeepSeek` 复选
- `解析文本`
- `执行解析`
- `清空`
- 解析结果预览

### 3. 旧项目复用范围

复用：

- `ai_pipeline_prototype.deepseek_client.DeepSeekClient`

暂不直接复用旧 Tk GUI 和旧 JSON 指令执行器。

---

## 解析规则

### 本地规则优先支持

1. 系统动作
   - 上电 / 启动 / 停机 / 暂停 / 继续 / 急停

2. 流程动作
   - `执行流程xxx`
   - `开始流程xxx`
   - `运行流程xxx`
   - 直接命中流程名

3. 模板动作
   - 复用当前模板别名解析
   - 例如：
     - `回零`
     - `位置A`
     - `抓取`
     - `放下`

### DeepSeek 解析目标

DeepSeek 只负责把自然语言分类成：

- 模板
- 流程
- 系统动作

并返回明确 target。

DeepSeek 不直接输出寄存器、VR 地址或底层协议细节。

---

## GUI 行为

### 解析文本

- 只做解析
- 不执行
- 把结果显示到预览框

### 执行解析

- 先解析
- 再按动作类型进入现有执行主链路

### 日志要求

至少记录：

- `自然语言解析`
- `DeepSeek解析`
- `解析回退`
- `自然语言执行`

---

## 风险边界

### 当前不做

- 多轮对话上下文
- 任意参数自由生成
- 自然语言直接生成新模板
- GUI 内直接接麦克风实时录音

### 必须保证

- 文本解析失败不影响现有运行页
- DeepSeek 不可用时可继续使用本地规则
- 模板/流程/系统按钮主链路不被破坏

## 第一阶段实施范围

本轮实现范围限定为：

1. 文本输入
2. 本地规则解析
3. DeepSeek 可选解析
4. 结果映射到：
   - 模板执行
   - 流程执行
   - 系统动作

这版不直接把语音采集做进 GUI 主流程。
