# V4.3 真实控制器联调执行清单

## 1. 目标

本清单面向现场联调人员，默认只使用 EXE 软件进行检查。

本清单只覆盖以下两类现场验证:

```text
1. 单功能是否能正常执行
2. 并行/互斥行为是否符合当前实现
```

不覆盖:

```text
1. 固件升级
2. 机械限位、治具和工艺参数标定
3. 脚本开发或 SDK 级调试
```

## 2. 现场前置条件

执行前确认:

```text
1. 真实控制器已上电，IP 可达
2. 机械臂周边无碰撞风险，现场具备急停手段
3. PC 可正常运行当前 EXE 软件
4. EXE 连接的目标 IP 与现场控制器一致
5. 当前 EXE 版本已包含最新模板和协议对齐修改
```

建议记录:

```text
控制器型号:
固件版本:
SDK 版本:
控制器 IP:
执行人:
执行日期:
```

## 3. 执行顺序

```text
1. 先确认基础连接和状态显示正常
2. 再逐条测试单功能
3. 然后测试 Func104 系统控制
4. 最后测试并行/互斥与扩展反馈
```

## 3A. 真机功能测试清单

现场真正要测的不是“地址名”，而是“功能是否成立、软件显示是否正确”。

### 3A.1 功能 1: 基础连接与状态读取

测试内容:

```text
1. 打开 EXE，连接真实控制器
2. 观察页面是否能稳定显示系统状态、报警信息、当前位置
3. 不执行动作时，确认页面数据不乱跳、不报连接错误
```

需要看到的返回:

```text
1. 软件显示“连接成功”或进入正常监控状态
2. 页面上的当前位置与机械臂现场位置基本一致
3. 无报警时，报警信息显示正常
4. 当前任务/当前函数/忙闲状态显示合理
```

### 3A.2 功能 2: 单条标准函数可正常执行

建议测试函数:

```text
1. Func106: 关节点动
2. Func108: 直线/定位
3. Func109: 定时检测
4. Func110: 延时
5. Func120: IO 控制
6. Func11: 多点插补
```

每条功能需要看到的返回:

```text
1. 点击执行后，软件没有立即报错
2. 日志或状态区能看到“已发送 / 执行中 / 执行完成”类似提示
3. 机械臂或 IO 动作与所选模板一致
4. 执行完成后，页面状态回到正常空闲
5. 如果失败，软件能明确显示错误，而不是无响应
```

什么结果算对:

```text
1. 动作执行结果与模板含义一致
2. 软件状态变化和现场动作一致
3. 成功时能完成并回到空闲
4. 失败时能看到明确报警或错误提示
```

### 3A.3 功能 3: Func104 系统控制有效

建议测试动作:

```text
1. 急停按下
2. 急停松开
3. 暂停按下
4. 暂停松开/继续
5. 结束按下
6. 结束松开
7. 报警复位
```

需要看到的返回:

```text
1. 急停后，软件状态立即变成急停/停止
2. 暂停后，运动停止；继续后能恢复
3. 结束后，当前动作停止
4. 报警复位后，报警状态恢复正常
5. 不残留假忙、假报警、假急停
```

### 3A.4 功能 4: 并行与互斥规则正确

建议场景:

```text
1. Func108 + Func110
2. Func110 + Func120
3. Func108 + Func106
4. Func108 + Func109
5. 运动执行中插入 Func104
6. IEEE(32) 连续快速触发
```

需要看到的返回:

```text
1. Func108 + Func110: 两者都能开始执行
2. Func110 + Func120: 第二条被拒绝、报忙，或明显不启动
3. Func108 + Func106: 第二条被拒绝、报忙，或明显不启动
4. Func108 + Func109: 第二条被拒绝、报忙，或明显不启动
5. Func104: 执行中也能立即生效
6. 连续触发: 不丢动作、不串动作、不状态错乱
```

### 3A.5 功能 5: 反馈值是否正确

建议顺带观察:

```text
1. Func109:
   IEEE(326)=剩余时间
   IEEE(330)=总延时

2. Func110:
   IEEE(328)=剩余时间
   IEEE(332)=总延时
   LONG(40)=剩余毫秒

3. Func120:
   LONG(44)=Y输出状态
   LONG(46)=X输入状态

4. Func11:
   IEEE(640)=当前点序号
   IEEE(642)=总点数
```

需要看到的返回:

```text
1. 日志里有对应反馈值
2. 反馈值和功能语义一致
3. 执行过程中会变化，结束后稳定
```

### 3A.6 功能 6: 扩展反馈是否有效

这项不阻塞主链，只顺带看:

```text
1. IEEE(52) 当前速度
2. IEEE(54) 剩余距离
3. IEEE(70) ECAT 状态
4. IEEE(72) FRAME 坐标系
```

需要看到的返回:

```text
1. 是否有值
2. 是否随动作变化
3. 是否值得长期保留在 GUI 日志中
```

## 4. M0.5 地址映射验证

### 4.1 页面层面重点确认

如果现场只使用 EXE，不做脚本验证，则至少确认以下页面现象:

```text
1. 页面能稳定显示当前位置
2. 执行动作时，状态会从空闲变为执行中，再变回完成/空闲
3. 出错时，页面能显示报警码或错误提示
4. 当前函数、忙闲状态、报警状态变化基本符合现场动作
```

## 5. M9 并行时序验证

### 5.1 目标

确认真实硬件符合当前实现假设:

```text
1. motion slot 内互斥
2. program slot 内互斥
3. motion 与 program 可并行
4. Func104 不受 slot 限制
```

### 5.2 推荐验证场景

按顺序执行以下场景:

```text
场景 A: Func108 + Func110
场景 B: Func110 + Func120
场景 C: Func108 + Func106
场景 D: Func108 + Func109
场景 E: 运动执行中触发 Func104 pause / resume / reset
场景 F: 连续两次快速触发 IEEE(32)
```

### 5.3 每个场景的预期

```text
场景 A:
  预期 Func108 与 Func110 可同时运行
  重点看 LONG(34) 是否能反映并行中的状态变化

场景 B:
  预期 Func120 因 program slot 忙而被拒绝或返回忙

场景 C:
  预期 Func106 因 motion slot 忙而被拒绝或返回忙

场景 D:
  预期 Func109 因 motion slot 忙而被拒绝或返回忙

场景 E:
  预期 Func104 可立即生效
  pause 后可 resume
  reset 不应留下假忙状态

场景 F:
  预期下位机能稳定锁存，不出现丢触发、串写或状态错乱
```

### 5.4 现场执行方式

推荐两种方式任选其一:

```text
1. 直接用 GUI 模板页/流程页执行
2. 结合控制器监控界面观察 LONG(34)/LONG(36)/LONG(38)/IEEE(322)
```

建议现场固定使用以下模板:

```text
位置A
位置B
T1延时1秒
T0延时1秒
急停
暂停
继续
报警复位
```

## 6. IEEE(52/54/70/72) 扩展反馈确认

在 M0.5 和 M9 完成后，补做一次观察:

```text
1. IEEE(52) 当前速度
2. IEEE(54) 剩余距离
3. IEEE(70) ECAT 状态
4. IEEE(72) FRAME 坐标系
```

记录内容:

```text
1. 是否有值
2. 值是否随动作变化
3. 刷新是否稳定
4. 是否保留到 GUI 日志
```

## 7. 联调完成定义

本轮真实控制器联调可判定为完成，当且仅当:

```text
1. M0.5 地址映射脚本有现场结果文件或文字记录
2. M9 六个场景均有执行记录
3. 已明确 IEEE(32) 连续触发行为是否稳定
4. 已明确 IEEE(52/54/70/72) 是否保留
5. 如发现异常，已记录为“代码问题 / 固件问题 / 待复测”三类之一
```
