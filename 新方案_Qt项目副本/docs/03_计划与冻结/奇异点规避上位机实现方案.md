# 奇异点规避上位机实现方案

## 1. 背景

当前下位机调试中发现一个明确风险：

- `RX / RY / RZ` 在某些姿态组合下会出现奇异点或接近奇异区
- 导致运动函数无解
- 或在姿态切换时发生突然爆转
- 甚至可能引发机械干涉

因此，需要上位机在发送运动位置前，先结合：

- 当前实时位置
- 当前实时姿态
- 目标位置
- 目标姿态

做一层运动预处理。

目标不是让上位机替代控制器运动学，而是：

**提前识别高风险路径，并自动插入可规避奇异点的中间位置，分两步执行。**

---

## 2. 目标

在不破坏现有主流程的前提下，为上位机增加以下能力：

1. 对运动目标做奇异风险预判
2. 命中风险规则时，自动插入规避中间点
3. 将一次运动拆分为两步：
   - 当前位姿 -> 中间点
   - 中间点 -> 目标点
4. 日志记录整个预处理过程
5. 保证该能力可以逐步启用，不影响现有稳定链路

---

## 3. 推荐方案

推荐采用：

**规则法 + 中间点模板法**

而不是直接做完整运动学路径求解。

原因：

- 当前项目已经有模板、工位点、标准协议、日志、实时状态
- 规则法更容易和现有系统结合
- 更适合先快速落地
- 风险可控
- 便于后续逐步积累工艺经验

---

## 4. 方案核心思路

### 4.1 基本逻辑

当上位机准备发送一条运动指令时：

1. 读取当前实时位姿
2. 获取目标点位姿
3. 根据规则判断：
   - 这条路径是否存在奇异点风险
   - 是否需要经过安全过渡点
4. 如果不需要规避：
   - 按原逻辑直接发送
5. 如果需要规避：
   - 自动生成中间点
   - 分两步发送

---

### 4.2 分两步执行方式

例如：

```text
原始目标：
当前位姿 -> TARGET

规避后：
当前位姿 -> SAFE_POINT -> TARGET
```

或者：

```text
当前位姿 -> SAFE_ROTATION_POINT -> TARGET
```

这两步都仍然走当前已经跑通的主链路：

- 写命令区
- 镜像确认
- 执行触发
- 结果回读
- 实时监控

---

## 5. 推荐实施方式

## 5.1 第一阶段：固定安全中间点

先定义一组固定安全中间点，例如：

- `SAFE_POINT`
- `SAFE_ROTATION_POINT`
- `APPROACH_HIGH_POINT`

这些点用于：

- 先抬高 Z
- 先过渡姿态
- 先远离机床内部危险区域

优点：

- 最简单
- 最稳
- 与当前模板系统最容易融合

---

## 5.2 第二阶段：按规则命中插入中间点

为上位机增加规则判断：

- 某些姿态变化过大时
- 某些 `RX / RY / RZ` 组合出现风险时
- 某些工位之间切换时
- 某些区域进入机床内部时

则自动插入：

- `SAFE_POINT`
- 或对应的过渡点

例如：

- 目标点属于机床内部点位，必须先到 `SAFE_POINT`
- `RZ` 翻转角度过大，必须先到 `SAFE_ROTATION_POINT`

---

## 5.3 第三阶段：支持多类规避规则

后续可以逐步扩展规则种类，例如：

1. 姿态角变化阈值规则
2. 高风险工位切换规则
3. 区域规则
4. 强制抬高规则
5. 工艺路径模板规则

这样以后不会只剩一个固定安全点，而是形成一套工艺规则库。

---

## 6. 系统中的落点

## 6.1 数据层

建议新增一份规避配置文件，例如：

- `data/avoidance_rules.json`

内容可包括：

- 安全中间点定义
- 风险工位组合
- 姿态阈值
- 是否启用自动规避

示例结构：

```json
{
  "enabled": true,
  "safe_points": {
    "SAFE_POINT": {
      "x": 0.0,
      "y": 0.0,
      "z": 200.0,
      "rx": 0.0,
      "ry": 0.0,
      "rz": 0.0
    }
  },
  "rules": [
    {
      "name": "machine_inner_requires_safe_point",
      "targetPosIds": [2, 3],
      "via": "SAFE_POINT"
    }
  ]
}
```

---

## 6.2 服务层

建议把运动预处理放在服务层，而不是直接写进界面。

适合新增：

- 运动预处理器
- 路径拆分器

职责：

1. 接收当前位姿和目标模板
2. 判断是否命中规避规则
3. 输出：
   - 单步运动
   - 或两步运动序列

这样界面层只负责：

- 发第一步
- 等完成
- 再发第二步

---

## 6.3 界面层

Qt 页面可以新增这些显示：

- 当前是否启用奇异规避
- 本次是否触发规避
- 使用了哪个中间点
- 当前是第几步

日志里建议记录：

- 命中规避规则
- 自动插入中间点
- 第一步发送
- 第一步完成
- 第二步发送
- 第二步完成

---

## 7. 与当前主流程的关系

这个功能必须建立在现有稳定主流程之上：

- 不能重写寄存器主链路
- 不能破坏镜像确认流程
- 不能绕过执行触发位
- 不能破坏结果区回读

正确做法是：

**只在上位机发送前增加“路径预处理”，真正的每一步发送仍然走当前已跑通的主链路。**

---

## 8. 风险和边界

## 8.1 上位机不能替代控制器最终保护

上位机规避只是前置优化，不能替代下位机最终安全保护。

下位机仍然必须保留：

- 无解判断
- 奇异保护
- 爆转保护
- 干涉保护
- 急停保护

---

## 8.2 不建议第一阶段就做完整运动学求解

完整运动学求解需要：

- 精确机械臂模型
- 关节限位
- 奇异性判定
- 干涉模型
- 路径搜索

这会显著抬高项目复杂度。

当前阶段不建议直接上这条路线。

---

## 9. 推荐实施顺序

### 阶段 1

- 先定义固定安全中间点
- 先支持少量高风险工位自动插入中间点

### 阶段 2

- 增加姿态变化阈值规则
- 支持更多工艺路径模板

### 阶段 3

- 再评估是否需要更复杂的运动学规避

---

## 10. 结论

这个需求可以实现，而且当前最适合的路线不是“通用运动学求解”，而是：

**上位机基于规则自动插入安全中间点，将高风险运动拆成两步执行。**

这条路线的优点是：

- 与现有系统兼容
- 风险低
- 容易逐步上线
- 不破坏已经跑通的寄存器主流程

后续开发建议：

**先做规则法和中间点模板，再视效果决定是否继续升级。**
