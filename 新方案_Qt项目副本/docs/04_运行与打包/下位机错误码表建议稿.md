# 下位机错误码表建议稿

## 1. 目标

这份文档用于统一下位机失败返回方式，解决当前这类问题：

- `RESULT = -1`
- `ALM_CODE = 0`

这类返回只能说明“失败了”，但不能说明“为什么失败”。  
为了让上位机能够准确判断失败原因，下位机应统一定义一套错误码表，并且所有失败分支都必须同时写：

- `RESULT`
- `ALM_CODE`
- `STATUS`

---

## 2. 状态寄存器建议

建议固定使用以下状态寄存器：

- `VR[16]`：`RESULT`
- `VR[17]`：`STATUS`
- `VR[24]`：`ALM_CODE`

建议语义：

### `RESULT`

- `0`：成功
- `-1`：失败

### `STATUS`

- `0`：空闲 / 完成
- `1`：运行中
- `2`：暂停
- `3`：故障

### `ALM_CODE`

- `0`：无报警
- 非 `0`：具体失败原因

---

## 3. 基本原则

### 成功时

必须写：

```text
RESULT = 0
ALM_CODE = 0
STATUS = 0
```

### 失败时

不要只写：

```text
RESULT = -1
```

必须同时写：

```text
RESULT = -1
ALM_CODE = 具体错误码
STATUS = 3
```

一句话原则：

> 每一个失败分支都必须同步写 `RESULT=-1` 和一个明确的 `ALM_CODE`，不要只写失败不写原因。

---

## 4. 推荐错误码分段

建议按类型分段，便于后续维护和扩展。

### 100 段：运动参数 / 范围类

- `101`：目标参数非法
- `102`：坐标越界
- `103`：姿态越界
- `104`：速度参数非法
- `105`：加速度参数非法

### 200 段：运动学 / 轨迹类

- `201`：逆解失败
- `202`：奇异点风险
- `203`：路径规划失败
- `204`：中间点不可达
- `205`：目标点不可达

### 300 段：状态机 / 执行条件类

- `301`：控制器忙
- `302`：未回零
- `303`：伺服未使能
- `304`：刹车未释放
- `305`：当前模式不允许执行
- `306`：联锁条件不满足

### 400 段：IO / 工艺动作类

- `401`：夹爪动作失败
- `402`：门控动作失败
- `403`：到位检测失败
- `404`：超时未完成

### 900 段：系统类

- `901`：未知内部错误
- `902`：子程序异常退出
- `903`：通讯数据非法
- `904`：命令码不支持

---

### 5.1 坐标越界

```text
RESULT = -1
ALM_CODE = 102
STATUS = 3
```

### 5.2 逆解失败

```text
RESULT = -1
ALM_CODE = 201
STATUS = 3
```

### 5.3 伺服未使能

```text
RESULT = -1
ALM_CODE = 303
STATUS = 3
```

### 5.4 忙状态拒绝执行

```text
RESULT = -1
ALM_CODE = 301
STATUS = 3
```

---

## 6. 下位机程序建议写法

最好的方式不是在每个失败分支里到处手写，而是统一封装成功出口和失败出口。

### 失败出口

```basic
SUB SetFail(errCode)
    VR(16) = -1      ' RESULT
    VR(24) = errCode ' ALM_CODE
    VR(17) = 3       ' STATUS = FAULT
END SUB
```

### 成功出口

```basic
SUB SetSuccess()
    VR(16) = 0
    VR(24) = 0
    VR(17) = 0
END SUB
```

### 失败分支示例

```basic
IF X > X_MAX THEN
    CALL SetFail(102)
    RETURN
END IF

IF InverseSolveFail = 1 THEN
    CALL SetFail(201)
    RETURN
END IF

IF ServoEnable = 0 THEN
    CALL SetFail(303)
    RETURN
END IF
```

这样做的好处是：

- 错误码写法统一
- 上位机能稳定解析
- 现场排查时可以直接定位失败原因

---

## 7. 上位机对应判断建议

为了和下位机统一，建议上位机按以下规则判断执行结果：

### 成功

- `STATUS = 0`
- `RESULT = 0`
- `ALM_CODE = 0`

### 失败

满足任意一条即视为失败：

- `RESULT != 0`
- `ALM_CODE != 0`
- `STATUS = 3`

### 特别说明

如果未来仍出现：

- `RESULT = -1`
- `ALM_CODE = 0`

则应视为：

- 下位机失败分支未按规范写错误码

不应把它当成“正常无报警失败”长期保留。

---

## 8. 推荐落地顺序

建议按下面顺序实施：

1. 先固定 `VR[16] / VR[17] / VR[24]` 的语义
2. 先实现统一 `SetFail(errCode)` 和 `SetSuccess()`
3. 先把最常见失败原因补齐：
   - `102`
   - `201`
   - `301`
   - `303`
   - `306`
4. 再逐步扩展完整错误码表

---

## 9. 最终结论

这份建议稿的核心不是“错误码写多少”，而是先把规则定死：

> 下位机每一个失败分支都必须同步写 `RESULT=-1`、明确的 `ALM_CODE` 和故障状态 `STATUS=3`。

只有这样，上位机才能稳定判断失败原因，而不会再出现“失败了但不知道为什么失败”的情况。
