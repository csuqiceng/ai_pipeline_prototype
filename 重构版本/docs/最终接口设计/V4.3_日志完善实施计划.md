# V4.3 日志完善实施计划

## 1. 目标

本次日志改造只解决联调和排障可追溯性问题，不修改协议执行行为。

核心目标:

```text
1. UI 仍只显示最近 200 条日志
2. 全量日志自动持久化到磁盘
3. 时间戳提升到毫秒级
4. 同一次发送链路可通过统一关联键串起来
5. 失败日志保留异常类型和 traceback
6. 导出日志时导出整场会话，而不是仅导出内存 200 条
```

## 2. 范围

本次只改:

```text
robot_modbus_lite/qt_gui.py
```

不改:

```text
1. robot_modbus_lite/service.py
2. robot_modbus_lite/models.py
3. 执行协议地址和时序
4. mock_controller 行为
```

## 3. 实施项

### 3.1 结构化日志基础字段

为每条日志补充:

```text
time            UI 显示时间，精确到毫秒
ts              ISO 时间戳
session_id      本次 GUI 会话 ID
seq             会话内递增序号
monotonic_ms    相对会话启动的毫秒数
host            当前控制器地址
controller_mode mock / real
thread          产生该日志的线程名
```

### 3.2 发送链路关联字段

为一次发送或系统命令生成:

```text
dispatch_id
task_id
query_key
func_num
root_query_key
plan_step_index
plan_step_total
```

说明:

```text
dispatch_id 是一次发送链路的唯一主键
task_id 继续保留，但不单独承担唯一关联职责
```

### 3.3 失败日志增强

失败日志补充:

```text
error_type
error_message
traceback
```

优先覆盖:

```text
连接检测
发送执行
系统命令
反馈读取
后台线程 work_fn 异常
```

### 3.4 JSONL 自动持久化

每次 `_append_log()` 时自动追加到:

```text
runtime_root/data/exported_logs/session_<session_id>.jsonl
```

约束:

```text
1. 持久化失败不能影响主流程
2. UI 内存日志仍只保留最近 200 条
3. 手动“导出日志”导出整场会话
```

### 3.5 清空日志保护

调整为:

```text
1. 清空前自动导出当前会话快照
2. 清空只影响 UI 内存列表
3. 持久化会话文件继续保留
```

## 4. 实施顺序

```text
1. 增加 session_id / dispatch_id / 结构化字段
2. 增加 JSONL 持久化
3. 改造后台线程异常包装，保留 traceback
4. 给关键发送链路补上下文
5. 改造导出和清空日志
6. compileall 和离屏行为验证
```

## 5. 验收标准

满足以下条件视为完成:

```text
1. UI 日志时间显示到毫秒
2. 发送一次模板后，会话 JSONL 中能看到统一 dispatch_id 的完整链路
3. 后台线程异常日志包含 error_type 和 traceback
4. 导出日志文件包含完整会话日志，而非仅最近 200 条
5. 清空日志前会自动生成一份快照文件
6. python -m compileall robot_modbus_lite 通过
```
