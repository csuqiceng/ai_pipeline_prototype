# V4.3 完整协议对齐实施方案

## 1. 目标

本方案的目标不是补单点缺口，而是让当前代码实现完整对齐以下文档:

```text
docs/最终接口设计/上位机通讯协议说明书V4.3.txt
```

覆盖范围:

```text
1. 后台模板编辑字段与协议函数参数一一对应
2. 命令构造与 IEEE 地址映射一一对应
3. 执行前检查、触发、等待完成、回显校验符合协议时序
4. Func104 特殊时序与控制字语义完整对齐
5. 并行规则、状态判断和告警处理符合协议说明
6. GUI / 默认模板 / 脚本 / 日志 / 打包产物保持一致
```

不在本次范围:

```text
1. 固件实现修改
2. 非 V4.3 文档定义的旧兼容路径保留策略之外的历史重构
3. 机械工艺参数与现场标定
```

## 2. 当前主要差距

基于现有代码与 V4.3 协议正文比对，当前至少存在以下差距。

### 2.1 后台模板编辑与协议字段不完全一致

```text
1. Func104 当前是“语义动作版”编辑，不是完整控制字版
2. Func104 未直接暴露 estop=2 / cancel=2 等协议状态
3. Func106/107/108 的 stop_cmd 文案仍沿用旧语义，不是协议原文:
   0=正常,1=急停,2=快停,3=慢停,4=暂停,5=恢复
4. Func109 的 check_value 文案更接近“校验值”，当前叫“检测值”
5. Func104 在函数号下拉框中仍显示“急停/慢停”，与四控制字模型不一致
6. _collect_record() 对未知函数号仍用 Func108 参数静默兜底，缺少显式报错
7. stop_mode 旧两态模型仍在 GUI 内部残留，应明确为兼容层或继续清理
```

### 2.2 标准函数执行时序已实现，待复核确认

协议 1.1 要求:

```text
步骤1 写函数号
步骤2 写参数
步骤3 读回显校验
步骤4 检查 LONG(34) 状态位 / 34.24 / 34.25 / 34.28
步骤5 写 IEEE(32)=1
步骤6 循环等待 DONE / ERR
步骤7 完成标志清理
```

当前实现已具备核心链路，但本方案仍需做一致性复核确认:

```text
1. 标准函数前置检查已覆盖 34.24 / 34.25 / 34.28，需复核与协议解释一致
2. 回显校验已实现，需复核是否完全按协议描述的 IEEE(280~312) 进行
3. 完成态 =10 / 错误态 =11 时的当前清理策略已实现，需复核是否与协议一致
```

### 2.3 Func104 特殊时序仍需按协议重审

协议 1.2 明确:

```text
1. Func104 不检查状态位，不等待空闲
2. 只校验参数写入正确
3. 写 IEEE(32)=1 后 1ms 内响应
4. 通过 LONG(34) 或 LONG(36) 确认急停/暂停/复位结果
5. 完整流程包含: 急停按下 → 解除急停 → 报警复位 → 确认就绪
```

当前实现虽已把 Func104 从标准前置检查中排除，但仍需补足:

```text
1. 后台模板页支持完整 Func104 控制字组合
2. Func104 完成后显式记录 34.25 / 34.26 / 34.27 / 34.28
3. Func104 联调与日志确认同时覆盖 LONG(36) 相关状态位，至少包含 36.00 / 36.01 / 36.02 / 36.03 / 36.04 / 36.05
4. “继续/恢复”“结束松开”“急停松开” 与协议值 2 的关系清晰化
```

### 2.4 并行规则需要严格按协议和文档统一

协议 1.3 写的是:

```text
110(T1延时) 和 120(IO输出) 可与运动函数(106/107/108)同时执行
110 和 120 之间串行执行
```

当前实现已扩展为:

```text
motion slot: 106/107/108/109/11
program slot: 110/120
system slot: 104
```

这属于本项目的实现约定，后续要明确区分:

```text
1. 协议正文的最小要求
2. 当前实现对 Func109 / Func11 的扩展纳管
3. GUI / mock / 真实硬件脚本 / 文档 三处保持同一套规则
```

### 2.5 反馈、状态与文档命名仍需统一

需要统一核对:

```text
1. LONG(34) 函数位与全局位解释
2. LONG(36) 系统状态
3. LONG(38) 报警码
4. IEEE(322) 当前函数号仅作辅助显示，不作并行判断
5. IEEE(52/54/70/72) 继续作为可选反馈，明确标注“非协议主链”
```

## 4. 分阶段实施

### 4.1 P0 后台模板编辑完整对齐

目标:

```text
让后台模板编辑页中的字段、枚举值、文案、默认值与协议函数参数完全对应
```

实施项:

```text
1. Func104 改为完整控制字编辑模型
   - estop_ctrl: 0/1/2
   - pause_ctrl: 0/1/2
   - cancel_ctrl: 0/1/2
   - reset_ctrl: 0/1
   - 可保留“快捷动作”层，但底层必须能完整表达协议值

2. 修正 Func106/107/108 stop_cmd 文案为协议语义

3. 修正 FUNC_OPTIONS / FUNC_LABELS 中 Func104 的显示名称，去掉“急停/慢停”旧命名

4. Func109 字段文案从“检测值”调整为“校验值”或“非零校验值”

5. _collect_record() 对未知函数号改为显式报错，不再静默按 Func108 收集参数

6. 明确 stop_mode 在 GUI 内部是兼容字段还是继续移除，避免用户可见层与内部模型混用

7. 检查 _sync_func_form_mode / _load_record_into_form / _collect_record / _validate_record 四处一致性

8. query_table 默认模板字段和 GUI 可编辑字段保持一致
```

验收:

```text
每个函数号在后台切换时，显示字段与协议表逐项一致
```

### 4.2 P1 命令构造与地址映射全面复核确认

目标:

```text
保证 SixAxisCommand.to_func_writes() 与协议第五章交叉对照表完全一致
```

实施项:

```text
1. 核对 Func104 / 106 / 107 / 108 / 109 / 110 / 120 / 11 的 IEEE 地址
2. 核对 Func11 点位区 IEEE(400+i*12) 地址
3. 核对 expected_echo_points() 与回显区 IEEE(280~312) 的对应关系
4. 核对 query_table / service / models 三处参数名映射一致
5. 单独确认协议例外项:
   - Func109 delay_time=IEEE(4)
   - Func110 delay_time=IEEE(6)
   - Func120 不走 snap_para, 直接读 IEEE(2)/IEEE(4)
   - Func11 点位区直接读 IEEE(400+)
```

验收:

```text
逐函数输出“参数名 -> 地址 -> 类型 -> GUI字段 -> service映射”对照表
```

### 4.3 P2 标准函数执行时序复核确认

目标:

```text
对已实现的标准函数执行链做协议 1.1 一致性复核，并收敛剩余差距
```

实施项:

```text
1. 前置检查已实现:
   - 对应函数位是否空闲
   - 34.24 是否报警
   - 34.25 是否急停
   - 34.28 是否就绪

2. 写参数后的回显校验已实现

3. 触发后等待 DONE / ERR 的主链已实现，剩余差距聚焦为:
   - ERR 时显式读取 LONG(38) 并纳入错误路径日志

4. 完成位清理策略已实现，但协议正文存在两种表述，需固定项目口径:
   - 步骤4 写法: DONE/ERR 触发前先经 Func104 复位
   - 步骤7 写法: 可通过下次触发自动覆盖
   - 本项目需明确当前采用哪一种解释，并同步到文档/日志/联调脚本
```

验收:

```text
标准函数执行日志能完整反映“写入 -> 回显 -> 前置检查 -> 触发 -> 完成/错误”
```

### 4.4 P3 Func104 特殊时序完整对齐

本阶段承接 §4.1 的 Func104 编辑模型改造，重点不是重复修改编辑字段，而是让编辑页、执行时序、反馈记录三处语义完全一致。

目标:

```text
Func104 的行为与协议 1.2 完整一致
```

实施项:

```text
1. 不走标准前置检查
2. 仅校验参数回显
3. 执行后显式确认 34.25 / 34.26 / 34.27 / 34.28 结果
4. 执行后同时记录 LONG(36) 相关状态:
   - 36.00 急停按钮状态
   - 36.01 暂停按钮状态
   - 36.02 结束按钮状态
   - 36.03 急停标志
   - 36.04 暂停标志
   - 36.05 结束标志
5. 支持并验证:
   - 急停按下
   - 急停松开
   - 暂停按下
   - 暂停松开
   - 结束按下
   - 结束松开
   - 报警复位
```

验收:

```text
后台模板、系统按钮、日志记录三处对 Func104 语义一致
```

## 7. 风险与注意事项

```text
1. Func104 从“语义动作版”改成“完整控制字版”后，现有模板和按钮映射需要一起迁移
2. stop_cmd 文案修正后，用户理解会变化，但底层值域不应变化
3. _collect_record() 改为显式报错后，新增函数号如果未同步更新会更早暴露问题，这是预期行为
4. stop_mode 如果继续保留为兼容字段，需要避免再次回流到用户可见文案
5. 完成位清理策略若调整，可能影响 mock 和真实控制器联调脚本
6. 文档术语要统一使用“协议原义”与“项目实现约定”两层描述，避免再次混用
```
