## 第一章：设计原则与要求

### 1.1 本文档的目的

本文档定义自然语言交互系统与底层控制器Func之间的二次封装层。上位机开发人员通过本文档可以：

1. 明确知道自然语言指令如何解析为底层Func参数
2. 明确每条指令的执行逻辑、安全校验、确认机制
3. 明确流程管理的执行策略
4. 获得可直接编码的逻辑伪代码

本封装层是自然语言→JSON→MODBUS整条链路的核心桥梁，为JSON指令意图结构提供标准化的解析规则，同时保障及时回应（≤50ms回执）和工业安全底线。

### 1.2 七条设计原则

**原则一：正确区分闲聊与指令**

所有生产指令必须以唤醒词"小正"开头。无"小正"前缀的语音一律视为闲聊或工艺讨论，不触发任何设备动作。三段式应急编码"急停XXX急停"除外，因其自身具备强校验机制。

| 语音 | 判定 | 动作 |
|------|------|------|
| "小正，上升50" | 指令 | 解析执行 |
| "急停123急停" | 应急指令 | 三段式校验后执行 |
| "这个机械手能不能往上走" | 闲聊 | 不执行，自然语言回复 |
| "我们下一步应该往右移" | 工艺讨论 | 不执行，自然语言回复 |
| "急停"（无编码） | 闲聊提及 | 不执行，回复"如需急停请使用标准格式" |

**原则二：指令简洁且容错**

指令设计必须简洁，3~4字覆盖80%日常操作，不超过8字覆盖95%。同时禁止使用单字代表动作或位置，因为单字发音错误或识别差错无法通过上下文恢复。

| 规则 | 正确 | 错误 | 原因 |
|------|------|------|------|
| 禁止单字指令 | "小正，上升" | "小正，上" | "上"可能被识别为"下""上""尚"等 |
| 禁止单字位置 | "小正，J1正" | "小正，1正" | "1"可能被识别为"7""一"等 |
| 方向词必须完整 | "前进""后退""上升""下降" | "前""后""上""下" | 单字方向易混淆 |
| 轴号必须带J | "J1正""J3负" | "1正""3负" | J前缀明确标识关节轴 |

**原则三：早期全复述确认，流程执行时按流程管理**

单条指令执行时，解析结果必须复述给操作者确认，默认值（速度、步长等）必须明确展示在配套界面和语音中。操作者确认后才执行。流程执行时，流程本身已经过编排确认，每步仅做L1安全检查，通过即执行，不逐步复述确认。安全检查不通过时暂停流程并通知操作者。

| 执行模式 | 复述确认 | 安全检查 | 说明 |
|---------|---------|---------|------|
| 单条指令（新手模式） | 全部复述确认 | L1预检 | 上线初期 |
| 单条指令（熟练模式） | 中高风险复述 | L1预检 | 熟练后 |
| 单条指令（专家模式） | 仅高风险复述 | L1预检 | 非常熟练 |
| 流程执行 | 不逐步复述 | 每步L1检查 | 流程已预编排 |

**原则四：应急指令使用特殊密码格式**

急停等应急操作使用三段式编码格式"关键词+数字编码+重复关键词"，编码在白名单内才有效。此格式无需"小正"前缀，因为三段式本身就是强校验，不可能在闲聊中误触发。单独提及"急停"关键词不触发任何动作。

| 格式 | 示例 | 校验 |
|------|------|------|
| 三段式 | "急停123急停" | 关键词+编码+重复关键词，编码在白名单 |
| 前缀式 | "小正，急停" | 需"小正"前缀，走普通指令通道 |
| 单独提及 | "急停" | 不执行，提示使用标准格式 |

**原则五：指令词语清晰无歧义**

指令中的方向词、动作词、对象词必须设计为不易混淆的词语，避免同音词和近音词导致的识别错误。

| 方向词 | 含义 | 不使用 | 原因 |
|--------|------|--------|------|
| 前进 | X正方向 | 往前/向前 | "前"与"先"近音 |
| 后退 | X负方向 | 往后/向后 | 统一用"后退" |
| 左移 | Y负方向 | 往左 | 统一用"左移" |
| 右移 | Y正方向 | 往右 | 统一用"右移" |
| 上升 | Z正方向 | 往上/向上 | "上"与"尚"近音 |
| 下降 | Z负方向 | 往下/向下 | 统一用"下降" |
| 正转 | 关节正方向 | 正走/正向 | 统一用"正转" |
| 反转 | 关节负方向 | 反走/反向 | 统一用"反转" |

**原则六：识别全参数、半参数、模糊三类指令**

系统必须能够识别并正确处理三种粒度的指令：

| 指令类型 | 特征 | 示例 | 解析规则 |
|---------|------|------|---------|
| 全参数 | 所有要素都有确定数据 | "20%速度上升3毫米加速度50%减速度30%" | 全部使用用户指定值 |
| 半参数 | 部分要素有确定数据 | "上升3毫米" / "20%速度上升" | 有数据用数据，无数据用默认/上次值 |
| 模糊 | 无确定数据 | "上升" / "高一点" | 全部使用默认/上次值 |

**确定数据优先原则**：用户明确说的数据必须使用，不可被默认值覆盖。未指定的要素按优先级补全：上次使用值 > 系统默认值。

**原则七：让上位机开发人员清楚意图和执行逻辑**

本文档必须清楚表述：
1. 底层用的是哪些Func（104/106/107/108/109/110/120）
2. 二次封装对Func参数做了哪些定性和定量处理
3. 每条指令的完整执行链路（解析→补全→确认→安全检查→执行→反馈）
4. 流程管理的执行策略
5. 异常处理的逻辑

## 第三章：默认值与记忆参数体系

### 3.1 记忆参数

| 参数 | 初始默认值 | 修改方式 | 说明 |
|------|-----------|---------|------|
| current_speed | 50% | "速度XX%"/"加速"/"减速" | 当前记忆速度 |
| current_step_mm | 10mm | "步长XX毫米"/"步长大一点" | 平移轴步长 |
| current_step_deg | 5° | "步长XX度" | 关节轴步长 |
| current_acc | 100% | "加速度XX%" | 当前记忆加速度 |
| current_dec | 100% | "减速度XX%" | 当前记忆减速度 |
| confirm_mode | beginner | "切换新手/熟练/专家模式" | 确认模式 |

### 3.2 确定数据优先规则

```
参数值来源优先级：
  1. 用户本次指令明确指定的数据 → 必须使用
  2. 上次执行使用的值           → 用户没说时沿用
  3. 系统默认值                 → 没有历史时使用
```

| 要素 | 用户说了 | 用户没说 | 示例 |
|------|---------|---------|------|
| 位置/距离 | 用用户值 | 用默认步长 | "上升3毫米"→3mm；"上升"→10mm |
| 速度 | 用用户值 | 用current_speed | "20%速度上升"→20%；"上升"→50% |
| 加速度 | 用用户值 | 用current_acc | "加速度50%上升"→50% |
| 减速度 | 用用户值 | 用current_dec | "减速度30%上升"→30% |
| 姿态 | 用用户值 | 保持当前DPOS | "Rx30移动到350 200 450"→Rx=30 |
| 运动类型 | 用用户指定 | 线性插补(0) | "快速移动到"→PTP(1) |

### 3.3 安全必须确认，非安全用默认

| 要素 | 缺失时 | 规则 | 原因 |
|------|--------|------|------|
| 方向 | **必须确认** | 无方向不执行 | 方向错了可能撞东西 |
| 轴号 | **必须确认** | 无轴号不执行 | 动错轴很危险 |
| 速度 | 用默认值 | 有安全上限钳位 | 非安全关键 |
| 步长 | 用默认值 | 步长小，有安全预检 | 非安全关键 |
| 加减速 | 用默认值 | 有ClampSafetyPct钳位 | 非安全关键 |

```python
class MotionHistory:
    def __init__(self, max_depth=20):
        self.stack = []
        self.last_direction = None
        self.last_step = None
        self.last_command = None
    
    def push(self, position):
        self.stack.append(position.copy())
        if len(self.stack) > max_depth:
            self.stack.pop(0)
    
    def pop(self):
        if self.stack:
            return self.stack.pop()
        return None
    
    def record_direction(self, from_pos, to_pos):
        dx = to_pos[0] - from_pos[0]
        dy = to_pos[1] - from_pos[1]
        dz = to_pos[2] - from_pos[2]
        d = (dx**2 + dy**2 + dz**2) ** 0.5
        if d > 0.001:
            self.last_direction = (dx/d, dy/d, dz/d)
            self.last_step = d
```

## 第七章：流程管理

### 7.1 流程执行策略

**核心原则：流程执行时，每步执行前做L1安全检查，不做全流程预演。**

原因：
1. 全流程L1+L2预演耗时太长
2. 流程是操作者预先编排的，一般条件满足
3. 预演时设备状态和实际执行时可能已变化
4. 逐步检查更符合工业实际

### 7.2 流程执行时序

```
操作者："小正，执行取料放置流程"
  ↓
系统："取料放置流程，共8步，开始执行第1步"
  ↓
循环每步：
  ├── L1安全检查
  │   ├── 通过 → 执行 → "第N步完成" → 下一步
  │   └── 不通过 → 暂停流程 → 通知操作者 → 等待处理
  └── 操作者中途指令（暂停/取消/查询进度）
  ↓
全部完成 → "流程全部完成"
```

### 7.3 流程中的操作者指令

| 语音 | 动作 |
|------|------|
| "小正，暂停流程" | 当前步完成后暂停 |
| "小正，继续流程" | 从暂停处继续 |
| "小正，取消流程" | 当前步完成后终止 |
| "小正，跳过这一步" | 跳过当前步（需确认） |
| "小正，流程进度" | "第3步/共8步，正在下降到A点" |
| "小正，从第3步开始" | 从指定步开始执行 |

### 7.4 安全检查未通过的处理

```
第N步L1安全检查未通过
  ↓
系统暂停流程："第N步安全检查未通过：XXX。
  选项：1.调整参数后重试 2.跳过此步 3.取消流程"
  ↓
操作者选择：
  "小正，调整参数" → 修改 → 重新检查
  "小正，跳过" → 确认后跳到下一步
  "小正，取消流程" → 终止
```
