# 主流程稳定基线说明

## 1. 目的

当前项目已经跑通以下主流程：

1. 上位机选择模板或指令
2. 上位机按当前协议组包
3. 通过寄存器把命令下发给下位机
4. 下位机执行命令
5. 下位机把执行结果和状态回写到状态寄存器
6. 上位机读取回写状态
7. 页面显示执行结果、状态、坐标、报警
8. 日志记录整个过程

因此，从现在开始，这条链路应视为**稳定基线**。

后续所有开发都应遵循一个原则：

**先保证“能下发、能执行、能回写、能显示、能记录”不被破坏，再继续做功能增强。**

---

## 2. 当前已确认跑通的主链路

当前已经确认成立的能力包括：

- 上位机可以选择模板并发送指令
- 下位机可以执行收到的命令
- 下位机可以按协议回写执行结果和状态
- 上位机可以读取状态区并刷新页面
- 页面可以展示执行结果、状态、报警、当前位置
- 日志可以记录关键操作过程

可以概括为：

**“上位机下发 -> 下位机执行 -> 下位机回写 -> 上位机显示” 主链路成立。**

后续功能增强，优先在外围做，不要先动主链路。

### 4.1 可以继续增强的部分

- 页面布局
- 页面显示文案
- 后台表单体验
- 日志展示
- 系统参数配置

### 4.2 需要谨慎增强的部分

- 寄存器字段映射

## 5. 后续开发的修改原则

### 原则 1：先保主链路，再做新功能

任何新增功能，不能以破坏主流程为代价。

### 原则 2：优先改外围，不先动核心链路

优先修改：

- UI
- 文案
- 配置
- 日志

谨慎修改：

- 协议组包
- 寄存器写入
- 状态解析
- 下位机回写逻辑

### 原则 3：所有高风险改动都必须回归验证

只要改到下列任何内容，就必须做一轮回归验证：

- 寄存器映射
- 命令码
- 指令组包
- 回写解析
- 通信调用
- 协议切换

---

## 6. 每次修改后的最小回归检查项

每次改动后，至少确认以下几点：

1. 能发送指令
2. 下位机能执行
3. 下位机能回写状态
4. 上位机能读取状态
5. 页面能正常显示结果
6. 日志能记录关键动作

如果其中任意一项失败，就不能把当前版本视为稳定版本。

---

## 7. 建议的后续开发模式

后续开发可以分成两层：

### 7.1 稳定层

这层尽量少动：

- 寄存器协议
- 组包逻辑
- 回写逻辑
- 通信链路

### 7.2 增强层

这层可以持续迭代：

- 模板管理

- 日志系统
- 辅助校验
- 工程体验

从现在开始，后续开发应以这条主流程为稳定基线。

后续的所有工作，都应当理解为：

**在不破坏主流程的前提下，继续完善功能。**
