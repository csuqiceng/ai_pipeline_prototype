1.1  标准函数执行逻辑（时序步骤）

适用函数: 106/107/108/109/11

步骤1: 检查状态标志
  读 LONG(34), 确认以下条件全部满足:
  (a) 对应函数位 = 00(空闲) 或 10(完成)
      如果=11(错误), 需要先清除(通过Func104复位)
      完成(DONE)状态允许下次触发时自动覆盖为EXEC
  (b) 34.24 = 0, 无报警
  (c) 34.25 = 0, 未急停
  (d) 34.28 = 1, 系统就绪
  任一条件不满足, 不能触发, 需先处理异常

步骤2: 写入函数号
  写 IEEE(0) = 函数号（如106）

步骤3: 写入参数
  写 IEEE(2)~IEEE(30) 的运动参数
  注意: 参数必须在触发前写入, 触发后下位机会立即读取

步骤4: 读回显校验
  读 IEEE(280~312) 回显区, 确认数据正确写入
  IEEE(280)=函数号, IEEE(282+i*2)=参数i, IEEE(312)=触发位
  如果回显与写入不一致, 说明通讯异常, 不要触发

步骤5: 触发执行
  写 IEEE(32) = 1
  下位机检测到后自动清除IEEE(32)=0

步骤6: 等待完成
  循环读 LONG(34) 对应函数位:
  01(执行中) → 继续等待
  10(完成)   → 执行成功, 可发下一个函数
  11(错误)   → 读LONG(38)查报警码, 处理后重试

步骤7: 清除完成标志
  完成后函数位=10(完成), 下次触发前需清除
  清除方式: 通过Func104报警复位, 或下次触发时自动覆盖

1.2  急停函数执行逻辑（特殊时序步骤）

适用函数: 104

急停函数与标准函数的关键区别:
  - 不检查状态标志位(不管当前是空闲/执行/完成/错误/报警)
  - 不需要等待空闲状态
  - 任何情况下都可以立即执行
  - 原因: 急停本身就是用来解决异常状态的, 不可能等状态正常再急停

步骤1: 写入函数号和参数
  写 IEEE(0) = 104
  写 IEEE(2) = 急停控制值 (1=急停按下, 2=急停松开)
  写 IEEE(4) = 暂停控制值 (1=暂停按下, 2=暂停松开)
  写 IEEE(6) = 结束控制值 (1=结束按下, 2=结束松开)
  写 IEEE(8) = 报警复位值 (1=复位按下)

步骤2: 校验参数正确性（只校验参数，不看状态位）
  读回显 IEEE(280~288), 确认写入的参数值正确
  只需确认"我要发的急停/暂停/复位指令确实写进去了"

步骤3: 触发执行
  写 IEEE(32) = 1
  下位机1ms内响应

步骤4: 确认执行结果
  读 LONG(34) 或 LONG(36) 确认:
  急停: 34.25 = 1
  暂停: 34.26 = 1
  复位: 34.28 = 1, 34.24 = 0

急停操作完整流程示例:
  (1) 急停触发: IEEE(0)=104, IEEE(2)=1, IEEE(32)=1 → 机械手立即停止
  (2) 确认急停: 读34.25=1
  (3) 确认安全: 读36.00=0(物理急停按钮已松开)
  (4) 解除急停: IEEE(0)=104, IEEE(2)=2, IEEE(32)=1
  (5) 报警复位: IEEE(0)=104, IEEE(8)=1, IEEE(32)=1
  (6) 确认就绪: 读34.28=1, 34.24=0

1.3  并行函数执行逻辑

110(T1延时)和120(IO输出)可与运动函数(106/107/108)同时执行。
但110和120之间串行执行(同一任务), 不能同时运行。

典型并行场景: 运动到位后延时再闭合夹爪
  (1) 触发108运动到目标位置
  (2) 同时触发110延时0.5秒
  (3) 等110完成(DONE)
  (4) 触发120闭合夹爪
  (5) 等120完成(DONE)
  (6) 触发下一个运动指令

2.9  模糊函数参数说明

模糊函数出现在106/107/108中, 共4个参数: fuzzy_pos, fuzzy_spd, fuzzy_acc, fuzzy_dec。

2.9.1  模糊函数的含义

| 参数名     | 值 | 含义                                    |
|-----------|---|----------------------------------------|
| fuzzy_pos | 0 | 绝对定位: pos_val是目标位置,运动到该位置    |
| fuzzy_pos | 1 | 增量定位: pos_val是增量,从当前位置加上该值   |
| fuzzy_spd | 0 | 绝对速度: spd_pct直接作为速度百分比使用      |
| fuzzy_spd | 1 | 叠加速度: 在当前速度百分比基础上加上spd_pct  |
| fuzzy_acc | 0 | 绝对加速度: acc_pct直接使用                 |
| fuzzy_acc | 1 | 叠加加速度: 在当前加速度百分比基础上加上acc_pct|
| fuzzy_dec | 0 | 绝对减速度: dec_pct直接使用                 |
| fuzzy_dec | 1 | 叠加减速度: 在当前减速度百分比基础上加上dec_pct|

2.9.2  叠加运算规则（重要！）

叠加模式下的运算公式:
  实际百分比 = 当前轴的百分比 + 输入的百分比

关键规则:
(1) 叠加是绝对百分比值的加减, 不是相对比例
    例: 当前速度50%, fuzzy_spd=1, spd_pct=10 → 实际=50+10=60%
    不是: 50% * (1+10%) = 55%

(2) 输入的百分比可以是负值
    例: 当前速度50%, fuzzy_spd=1, spd_pct=-10 → 实际=50+(-10)=40%
    负值表示减少, 正值表示增加

(3) 最终结果限制在0~150范围
    如果叠加后<0, 则=0(停止)
    如果叠加后>150, 则=150(最大值)

(4) 当前百分比的计算方式
    当前速度百分比 = 当前SPEED * 150 / MAXSPD
    当前加速度百分比 = 当前ACCEL * 150 / SAFEACC

2.9.3  模糊函数使用示例

场景1: 在当前速度基础上增加20%
  fuzzy_spd=1, spd_pct=20

场景2: 在当前速度基础上减少10%
  fuzzy_spd=1, spd_pct=-10

场景3: 从当前位置增量移动30度
  fuzzy_pos=1, pos_val=30

场景4: 使用绝对速度50%运动到绝对位置90度
  fuzzy_pos=0, pos_val=90, fuzzy_spd=0, spd_pct=50

2.9.4  模糊函数参数值参考

当前模糊函数的具体数值范围尚未最终确定, 暂按三维机方案执行。
上位机开发者应注意:
- fuzzy参数为0时, 对应的速度/加速度/减速度/位置参数按绝对值使用
- fuzzy参数为1时, 对应的参数按叠加方式使用, 可正可负
- 建议调试时先用fuzzy=0(绝对模式), 确认基本功能正常后再使用fuzzy=1(叠加模式)

第四章  数据格式与运算标准
==========================================================

4.1  IEEE浮点数格式

- IEEE(0)~IEEE(750+) 均为32位IEEE754单精度浮点数
- 在Modbus中占2个保持寄存器(1个IEEE = 2个WORD)
- 写入整数时自动转为浮点(如写104, 读回104.0)
- 读取时必须按浮点数解析, 不能按整数解析
- 函数号虽然是整数, 但也以浮点格式存储, 读取后需INT()取整

4.2  LONG长整数格式

- LONG(34)/LONG(38)/LONG(44)/LONG(46) 为32位有符号整数
- 在Modbus中占2个保持寄存器
- 状态位使用十六进制掩码进行位操作
- 地址与IEEE不同: LONG(34)和IEEE(34)是不同的存储区

4.3  掩码运算示例

检查106是否完成:
  (LONG(34) AND $C) = $8

检查106是否空闲:
  (LONG(34) AND $C) = $0

检查是否有报警:
  (LONG(34) AND $1000000) <> 0
  即 34.24 <> 0

检查是否急停:
  (LONG(34) AND $2000000) <> 0
  即 34.25 <> 0

检查系统就绪:
  (LONG(34) AND $10000000) <> 0
  即 34.28 <> 0

清除106状态位:
  LONG(34) = LONG(34) AND NOT $C

设置106执行:
  LONG(34) = (LONG(34) AND NOT $C) OR $4

5.2  地址映射规则

IEEE地址与Modbus寄存器地址的映射:
  IEEE(n) 对应 Modbus保持寄存器 400001 + n*2 和 400001 + n*2 + 1
  即每个IEEE浮点数占2个连续的Modbus寄存器(32位)

LONG地址与Modbus寄存器地址的映射:
  LONG(n) 对应 Modbus保持寄存器 400001 + n 和 400001 + n + 1
  即每个LONG占2个连续的Modbus寄存器(32位)

重要: IEEE(n)和LONG(n)虽然n相同, 但是不同的存储区, 不能混用!
  IEEE(34) 是浮点数存储区地址34

  两者在Modbus中映射到不同的寄存器地址

第六章  ZBasic MODBUS通讯基础（官方说明）
==========================================================

本章内容来源于正运动RTBasic编程手册, 供上位机开发人员理解控制器MODBUS寄存器模型。

6.1  MODBUS寄存器类型总览

控制器MODBUS寄存器符合MODBUS标准通讯协议, 分为位寄存器和字寄存器两类:

| 寄存器类型     | 数据类型    | 占用REG数 | 触摸屏称呼  | 取值范围                        |
|---------------|-----------|----------|-----------|--------------------------------|
| MODBUS_BIT    | 布尔型     | 独立空间(0X) | MODBUS_0X | 0或1                          |
| MODBUS_REG    | 16位整型   | 1个       | MODBUS_4X | -32768到32767                  |
| MODBUS_LONG   | 32位整型   | 2个REG    | MODBUS_4X | -2147483648到2147483647        |
| MODBUS_IEEE   | 32位浮点型 | 2个REG    | MODBUS_4X | -3.4028235E+38到-1.401298E-45  |
| MODBUS_STRING | 1字节字符串 | 共用4X   | MODBUS_4X | 每个字符占8位                   |

6.2  字寄存器共用空间（核心！）

MODBUS_REG、MODBUS_LONG、MODBUS_IEEE 共用同一个4X物理存储空间!
一个LONG占用两个REG地址, 一个IEEE也占用两个REG地址。

  MODBUS_LONG(0)  占用 MODBUS_REG(0) 与 MODBUS_REG(1)
  MODBUS_LONG(1)  占用 MODBUS_REG(1) 与 MODBUS_REG(2)  ← 与LONG(0)重叠!
  MODBUS_IEEE(0)  占用 MODBUS_REG(0) 与 MODBUS_REG(1)
  MODBUS_IEEE(1)  占用 MODBUS_REG(1) 与 MODBUS_REG(2)  ← 与IEEE(0)重叠!

因此: REG、LONG、IEEE的地址编号绝对不能重叠, 否则数据互相覆盖!

计算方式(官方原文):
  MODBUS_REG(1)为高位, MODBUS_REG(0)为低位
  MODBUS_LONG(0) = MODBUS_REG(1) * 2^16 + MODBUS_REG(0)

官方例程:
  MODBUS_REG(0) = 0
  MODBUS_REG(1) = 0
  MODBUS_LONG(0) = 70000
  打印: REG(0)=4464, REG(1)=1
  验证: 1 * 65536 + 4464 = 70000 ✓

6.3  本项目的地址分区规划

由于LONG和IEEE共用空间, 本项目严格分区:

  IEEE(0~32)     → 上位机参数传入区  (占REG 0~65)
  LONG(34~46)    → 控制器状态反馈区  (占REG 68~93)
  IEEE(50~312)   → 回显与反馈区      (占REG 100~625)
  IEEE(400~)     → 插补点数据区
  IEEE(720~752)  → 触摸屏专用区
  IEEE(1500~)    → DPOS/MPOS/安全参数区

注意: IEEE(34)和LONG(34)虽然编号相同, 但在控制器内部是不同的存储区!
  - IEEE(34) 是浮点数存储区地址34
  - LONG(34) 是长整数存储区地址34
  - 两者在Modbus中映射到不同的寄存器地址

6.4  标志位的提取方法

上位机读取LONG(34)后, 需要用位操作提取各个标志位。

6.4.1  单个标志位提取

  提取34.25(急停标志):
    方法1: (LONG(34) AND $2000000) <> 0    → True表示急停
    方法2: (LONG(34) >> 25) AND 1 = 1      → 右移25位后取最低位

  提取34.24(报警标志):
    方法1: (LONG(34) AND $1000000) <> 0
    方法2: (LONG(34) >> 24) AND 1 = 1

6.4.2  双位状态提取(函数执行状态)

  每个函数占2位: 00=空闲, 01=执行中, 10=完成, 11=错误

  提取106状态(34.02, 34.03):
    步骤1: 取出2位 → val = (LONG(34) AND $C) >> 2
    步骤2: 判断:
      val = 0 ($0) → 空闲
      val = 1 ($1) → 执行中(EXEC)
      val = 2 ($2) → 完成(DONE)
      val = 3 ($3) → 错误(ERR)

  提取120状态(34.18, 34.19):
    步骤1: 取出2位 → val = (LONG(34) AND $C0000) >> 18
    步骤2: 判断同上

6.4.3  通用提取公式

  提取 X.NN 位:
    bit_value = (LONG(X) >> NN) AND 1

  提取 X.NN, X.N(N+1) 双位:
    val = (LONG(X) AND mask) >> NN
    其中 mask = 3 << NN (即 $3 左移NN位)

6.6  数据格式注意事项

(1) IEEE浮点数写入整数会自动转换
    写入 IEEE(0)=104, 读回为 104.0
    上位机读取后需 INT() 取整得到函数号

(2) LONG整数不支持小数
    浮点型向整型转换时会丢失小数部分
    例: VR(0)=10.314, MODBUS_LONG(0)=VR(0) → LONG(0)=10

(3) 日期等8位数据不要用IEEE存储
    单精度浮点数有效位只有6位, 8位数据会丢失精度
    建议使用LONG(32位整型)存储

(4) 控制器地址从0开始
    与威纶触摸屏通讯时地址一一对应(都从0开始)
    与昆仑通态触摸屏通讯时, 触摸屏地址需+1
