# V4.3 真实控制器联调执行清单

## 1. 目标

本清单只覆盖以下两类现场验证:

```text
1. M0.5 地址映射只读验证
2. M9 并行执行框架真实硬件时序验证
```

不覆盖:

```text
1. 写入型危险测试
2. 固件升级
3. 机械限位、治具和工艺参数标定
```

## 2. 现场前置条件

执行前确认:

```text
1. 真实控制器已上电，IP 可达
2. 机械臂周边无碰撞风险，现场具备急停手段
3. PC 已安装当前项目所依赖 Python 环境和 ZMotion SDK
4. 当前代码版本已包含:
   tools/verify_v43_mapping.py
   tools/verify_v43_mock_m9.py
   data/query_table.json 新模板
5. GUI 或脚本连接的目标 IP 与现场控制器一致
```

建议记录:

```text
控制器型号:
固件版本:
SDK 版本:
控制器 IP:
执行人:
执行日期:
```

## 3. 执行顺序

```text
1. 先做 M0.5 地址映射只读验证
2. M0.5 通过后，再做 GUI / M9 并行时序验证
3. 最后记录 IEEE(52/54/70/72) 是否有效
```

## 4. M0.5 地址映射验证

### 4.1 执行命令

推荐执行:

```bash
python tools/verify_v43_mapping.py --host <controller-ip> --json docs/最终接口设计/v43_mapping_result.json
```

示例:

```bash
python tools/verify_v43_mapping.py --host 192.168.1.11 --json docs/最终接口设计/v43_mapping_result.json
```

### 4.2 需要确认的结果

重点检查:

```text
1. LONG(34) 可读
2. LONG(36) 可读
3. LONG(38) 可读
4. LONG(34, count=3) 返回长度是否为 3
5. IEEE(320) 可读，且尽量与 LONG(36) 当前值一致
6. IEEE(322) 可读
7. IEEE(1600, count=6) 可读
8. IEEE(1612, count=6) 可读
```

### 4.3 判定标准

通过标准:

```text
1. connect controller = PASS
2. LONG(34/36/38) = PASS
3. LONG(34, count=3) = PASS
4. IEEE(320/322) = PASS 或 IEEE(320)=WARN 但有现场合理解释
5. MPOS joints / pose = PASS
6. 无 SDK 异常、无地址越界异常、无明显地址步进错误
```

失败处理:

```text
1. 任一关键地址 FAIL: 先停止 M9 联调，优先排查地址映射或 SDK 读取方式
2. LONG count 行为异常: 暂停批量读取设计，改回单点读取确认
3. IEEE(320) 与 LONG(36) 不一致: 结合刷新周期复测，再判断是否需要协议修正
```

## 5. M9 并行时序验证

### 5.1 目标

确认真实硬件符合当前实现假设:

```text
1. motion slot 内互斥
2. program slot 内互斥
3. motion 与 program 可并行
4. Func104 不受 slot 限制
```

### 5.2 推荐验证场景

按顺序执行以下场景:

```text
场景 A: Func108 + Func110
场景 B: Func110 + Func120
场景 C: Func108 + Func106
场景 D: Func108 + Func109
场景 E: 运动执行中触发 Func104 pause / resume / reset
场景 F: 连续两次快速触发 IEEE(32)
```

### 5.3 每个场景的预期

```text
场景 A:
  预期 Func108 与 Func110 可同时运行
  重点看 LONG(34) 是否能反映并行中的状态变化

场景 B:
  预期 Func120 因 program slot 忙而被拒绝或返回忙

场景 C:
  预期 Func106 因 motion slot 忙而被拒绝或返回忙

场景 D:
  预期 Func109 因 motion slot 忙而被拒绝或返回忙

场景 E:
  预期 Func104 可立即生效
  pause 后可 resume
  reset 不应留下假忙状态

场景 F:
  预期下位机能稳定锁存，不出现丢触发、串写或状态错乱
```

### 5.4 现场执行方式

推荐两种方式任选其一:

```text
1. 直接用 GUI 模板页/流程页执行
2. 结合控制器监控界面观察 LONG(34)/LONG(36)/LONG(38)/IEEE(322)
```

建议现场固定使用以下模板:

```text
位置A
位置B
T1延时1秒
T0延时1秒
急停
暂停
继续
报警复位
```

## 6. IEEE(52/54/70/72) 扩展反馈确认

在 M0.5 和 M9 完成后，补做一次观察:

```text
1. IEEE(52) 当前速度
2. IEEE(54) 剩余距离
3. IEEE(70) ECAT 状态
4. IEEE(72) FRAME 坐标系
```

记录内容:

```text
1. 是否有值
2. 值是否随动作变化
3. 刷新是否稳定
4. 是否保留到 GUI 日志
```

## 7. 联调完成定义

本轮真实控制器联调可判定为完成，当且仅当:

```text
1. M0.5 地址映射脚本有现场结果文件或文字记录
2. M9 六个场景均有执行记录
3. 已明确 IEEE(32) 连续触发行为是否稳定
4. 已明确 IEEE(52/54/70/72) 是否保留
5. 如发现异常，已记录为“代码问题 / 固件问题 / 待复测”三类之一
```

建议最终保存:

```text
1. docs/最终接口设计/v43_mapping_result.json
2. 一份现场联调结论记录
3. 如有异常，一份问题列表和复测建议
```
